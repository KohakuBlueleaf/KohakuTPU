# Frozen stack and binding witnesses

The witness JSON files are stored in the Hugging Face dataset
`KBlueLeaf/kohakutpu-golden`, not in git; `python software/rust/golden/fetch.py`
downloads them into this directory. A regeneration that changes a witness is
uploaded to that dataset in the same change.

The JSON files are fixed byte-layout and compiler-output witnesses. They are
not regenerated from a live Python compiler. Rust stage tests compare against
them; changes require review of the affected layout or ruling.

- `e2e/`: graph, L2, L1, packages, dispatch order and verifier results for whole kernels.
- Stage directories: ISA encodings, L0 packages, L1 images, L2 lowering and schedules.
- `kernels/` and `plan/`: generator inputs, graphs and planner decisions.
- `props/`: traced inputs for independently asserted Rust properties.
- `bindings/`: machine views, IMEM accounting, buffers, images, ISA configuration,
  package readers/builders and callback-interpreter logs.

Binding groups use `{group, cases: [...]}`. Each case names its input, output
and output SHA-256; bytes use hexadecimal strings. The Python binding tests
compare the native extension with these files, not a second compiler.

## Card-view normalization

`bindings/card.json` describes the runtime's schema-derived build facts.
Those facts are authoritative because they describe the card that runs the
packages. On v9t6, `vc.regs=128` and `vc.rf_copies=2`; trace defaults of
32 registers and four copies are not a hardware reference. Runtime-view cases
include node-count and enumeration overrides, stage capacity and addresses.

The machine digests omit provenance (`sources`) and measurement annotations.
Regenerating timing-source strings therefore does not change hardware digests.
Address-layout fixture JSON files are generated by `scripts/py/machine --set`
and held byte-equal by the machine-generator tests.

## Planner launches corrected from the Python trace

`cargo run -p ktpu-kernels --example plan_regold [--write]` lists (and with
`--write` rewrites) planner-golden launch graphs the current generators trace
differently, leaving RUL.060 and RUL.020 launches to their rulings. A launch
is rewritten only when the Python trace is shown wrong. Rewritten:

- `plan/synthetic.enumerated.json`, `rows_e66f2e5737` (4 launches): a
  one-hot over a per-row statistic and a broadcast column row. The Python
  tracer gave the ops the broadcast row's 4 rows instead of the statistic's
  16 (`Trace::math`); the training step's labels came out wrong on the card
  model (`rows_7b307e07d5`, CPU f32 relative error 2.31). Witness:
  `ktpu-kernels` `clauses::rows::api_row_math_takes_a_statistics_rows`.

## Machine digest regeneration

After regenerating machines with `python -m machine --all` from `scripts/py`,
run `cargo run -p ktpu-machine --example digests -j 16` from `software/rust`.
The example writes `machine/digests.json` using `Machine::digest` for every
named machine. Review changed facts before accepting the witnesses.
`digest_matches_frozen_machine_witnesses` checks the complete name/digest map;
`digest_ignores_sources_and_follows_facts` independently checks that provenance
is excluded and hardware facts affect the digest.

## L1 relocation-view regeneration

The L1 stage's golden harness supports reviewed relocation updates:

```text
KTPU_L1_REGOLD=audit cargo test -p ktpu-l1 --features mutants --test golden -- --nocapture
KTPU_L1_REGOLD=write KTPU_L1_CASES=case1,case2 KTPU_L1_REGOLD_BACKUP=<dir> cargo test -p ktpu-l1 --features mutants --test golden -- --nocapture
```

Audit prints differing bindings, parameter spans and relocation sites. Write
requires an explicit case allowlist and changes only `programs.<node>.relocated`
and `bindings`; other comparison differences refuse the update. Original changed
fixtures are saved under `KTPU_L1_REGOLD_BACKUP` (required in write mode).
Existing snapshots are not overwritten. Plain, resident and default engine-package views must still match,
and binding the relocation view at its source placement must reproduce the plain
bytes. Independent shifted-placement payload witnesses are in
`crates/ktpu-l1/tests/framework_reloc.rs`. Unset both variables for acceptance tests.

## L2 lowering regeneration

The L2 harness supports reviewed changes to its lowering-output comparison:

```sh
KTPU_L2_REGOLD=audit cargo test -p ktpu-l2 --test golden goldens -- --exact --nocapture
KTPU_L2_REGOLD=write KTPU_L2_CASES=case1,case2 KTPU_L2_REGOLD_BACKUP=<dir> cargo test -p ktpu-l2 --test golden goldens -- --exact --nocapture
```

Audit visits every non-skipped L2 fixture and prints every differing case and
its first differing line per compared field. A successful audit means the
changed lowerings pass the static verifier, not that the frozen text matches.
Pass text, refusal expectations and variant comparisons retain their ordinary
checks. `KTPU_GOLDEN` filtering is not used with regeneration.

Write requires a nonempty, comma-separated allowlist of exact fixture case
names; unknown names are rejected. It rewrites only `l1` in
`golden/l2/<case>.json`, and also `l1_scheduled` when
`KTPU_GOLDEN_SCHEDULED=1` enables that comparison. No field is added and no
pass, variant, refusal, L1-stage, scheduler-stage or end-to-end fixture is
regenerated by this path. Set `KTPU_GOLDEN_SCHEDULED=1` for the audit and write
when reviewing both lowering views.

A selected case must lower successfully, pass its other existing comparisons,
and build and pass the refusing static verifier after image scheduling with
the fixture's machine/node count and caller/scratch arena bindings. Refused
or skipped cases are not writable. Before replacement, the exact original JSON
is saved as `$KTPU_L2_REGOLD_BACKUP/<filename>` using exclusive creation, so a prior original is never overwritten. Review audit
output before invoking write; audit itself does not write fixtures or backups.
Writes are per-case: an unrelated fixture failure can make the command fail
after an approved case has been updated. There is no whole-suite rollback;
inspect the allowlisted files and backups even when the command exits nonzero.

## Scratch arena write-line witnesses

`arena/lines.json` freezes the arena sizes and member offsets of every
end-to-end fixture with L1 and L2 text. The audited regeneration path is:

```text
KTPU_LINE_REGOLD=audit cargo test -p ktpu --features mutants --test arena_goldens -- --nocapture
KTPU_LINE_REGOLD=write KTPU_LINE_REGOLD_OUT=<dir> cargo test -p ktpu --features mutants --test arena_goldens -- --nocapture
```

Before writing, the reader checks every member's name, space and node against
the word-aligned mutant, independently computes line-aligned starts and sizes
from buffer types, and requires nondecreasing sizes/offsets. It writes only
this arena fixture plus `arena-word.json` (the word layout) and
`arena-review.json` (each changed case's size and moved-offset count) under
`KTPU_LINE_REGOLD_OUT`.
The existing stage and package fixtures bind each parameter separately and
remain unchanged. Unset `KTPU_LINE_REGOLD` for acceptance tests.

## Indexed line-layout output overlay

`lines/kernels-lanes-TG.RUN.012.relayout.json` freezes the corrected compiler
output for the immutable graph in the original e2e fixture. The golden reader
checks that its old L2 triggers L1.VER.017, that the graph's caller ports stay
unchanged, and that the corrected graph is accepted and relocatable. It compares
the complete L2, L1, arena sizes and package output with this overlay; no old
verdict is rewritten into acceptance.

```text
KTPU_GOLDEN_SHARD=9/16 KTPU_LINE_OUTPUT_REGOLD=audit cargo test -p ktpu --features mutants --test golden -- --nocapture
KTPU_GOLDEN_SHARD=9/16 KTPU_LINE_OUTPUT_REGOLD=write cargo test -p ktpu --features mutants --test golden -- --nocapture
```

The overlay includes replicated full-line word slots, full-line gathers/scatters,
and one bounded output compaction. It is not an arena-offset-only update. The
independent address and mutation witnesses are `ktpu/tests/line_slots.rs`.
Unset `KTPU_LINE_OUTPUT_REGOLD` for acceptance tests.

## Mover packing machine selection

The four node-quant fixtures use the unaffected `multimesh_v9t5` machine.
It has the same compute, mover and address facts as v9t6, while allowing mover
QUANT. Current v9t6 checks their unproven finite-input contract on the card. The audited
machine-only migration preserves every input, expected value, compiler text,
package byte and verdict. Run from the repository root:

```text
python software/rust/golden/packing/regold.py
python software/rust/golden/packing/regold.py --write --backup <dir>
```

The auditor checks the machine-fact equivalence except board name and packing
policy, and executes checked-vector/mover acceptance on both machines before changing only
machine selection. Acceptance runs unset all regold controls and compare the
original byte outputs. Current-board vector byte and refusal witnesses live in
`application/tests/runtime/test_packing*.py` and `ktpu-l2/tests/packing.rs`.

## Software loop and relocated-literal encoding

`KTPU_LOOP_REGOLD=audit cargo test -p ktpu-l1 --features mutants --test golden -- --nocapture`
compares the six explicitly enumerated software-control cases. Write mode also
requires `KTPU_L1_CASES` with every changed case. It updates only package byte
views: inputs, image words, canonical text, schedules and bindings must still
compare unchanged. The ordinary-placement equality of bound relocation bytes
is checked before any update. Originals are saved under `KTPU_L1_REGOLD_BACKUP`.

The changes are relocated immediate LOAD literals before descriptor PATCHes,
unit-specific runtime-frontier waits instead of static counts after labels, and retaining uploads
on repeated control-flow paths. `ktpu-l0/tests/contract.rs` independently checks
shifted literal bindings and unchanged PATCH payload indices, with mutants;
the exhaustive finite packing model case crosses many node-loop iterations.

`cargo run -p ktpu-l1 --features mutants --example loop_regold [-- --write --backup DIR]`
audits the corresponding six named tier-0 spec inputs. It refuses changes to
DISPATCH words and preserves every input; the loop path uses a runtime-frontier
wait, witnessed by a static-loop-wait mutant. Write mode saves the original spec
inputs under `--backup DIR`.

`KTPU_L0_LOOP_REGOLD=audit|write cargo test -p ktpu-l0 --features mutants --test golden`
audits the two named L0 loop-program fixtures. It preserves their inputs, units,
bindings, existing data-plane payloads and DISPATCH/MOVER/FETCH commands, then
updates package views and checksums. Original L0 fixtures are saved under
`KTPU_L0_REGOLD_BACKUP` (required in write mode). Unset all regeneration
variables for acceptance gates.

## Running the comparisons

From `software/rust`, run each shard with bounded parallelism:

```text
KTPU_GOLDEN_SHARD=I/16 RAYON_NUM_THREADS=16 cargo test -p ktpu --test golden -j 16
```

Use `I=0..15`. The reader is `crates/ktpu/tests/golden.rs`; each stage crate
also owns clause, mutation and golden tests. `crates/ktpu-kernels/tests/`
checks generator and planner-call witnesses, and `crates/ktpu-plan/tests/`
checks planner decisions. `ruled.json` names explicit exceptions checked by
the golden reader; compact-statistic attention has no refusal exception.

`interp_env.py` supplies only callback inputs and logs for the retained package
interpreter. It computes no tensor values. Compiled tensor-value evidence comes
from card or Verilated-card runs.

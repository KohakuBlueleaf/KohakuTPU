# The simulated card

A Verilated multimesh card behind the driver's `Transport` seam: the same
driver, program images, doorbells and status polls as on silicon, with a
process in place of the board.

```
  driver (kohakuaccel, kohakutpu)          unchanged
        |  write64 / read64 / write_block / read_block
        v
  VerilatorTransport                       driver/kohakuaccel/transport/verilator.py
        |  line protocol on stdin/stdout
        v
  card_main.cpp                            sim/verilator/harness/
        |  host manager 0, every clock
        v
  card_v8t8_2n                             tests/system/, generated by gen_card.py
        station bus, nodes, Xache, interlink, DRAM (axi_ram)
```

## The flow

| step | tool | output |
|---|---|---|
| emit the card | `scripts/py/gen_card.py` | `tests/system/card_<ver>[_<n>n].v` |
| name its sources | `scripts/py/xsim.py` `BENCHES["card_v8t8_2n"]` | the build list |
| build the model | `scripts/py/vlt.py ... --cc card_main.cpp --vlt-config card.vlt` | `build/vlt_card_v8t8_2n/obj_dir/vsim` |
| drive it | `VerilatorTransport` | the driver's `Transport` |

```
python scripts/py/gen_card.py --ver v8t8 --sim-mesh ktpu_sim_1x1_1c1v_1m_nol2_pump \
    --compute 0,1 -o tests/system/card_v8t8_2n.v --module card_v8t8_2n
python scripts/py/vlt.py card_v8t8_2n --cc sim/verilator/harness/card_main.cpp \
    --keep --vlt-config sim/verilator/card.vlt
python scripts/py/card_run.py --load burn
```

## The generated card

`gen_card.py` reads every value from the image's own Tcl: `scripts/tcl/<ver>/00_config.tcl`
sourced through tkinter, its source list from `10_sources.tcl` with the Vivado
procs stubbed, and the station map from `v8/50_addr_lit.tcl`. Only
`PER_DIE_CLK 1` images are emitted.

| block-design part | stand-in |
|---|---|
| Clocking Wizard (DRP) | `src/kohakuaccel/verif/clk_wiz_model.v` |
| DDR4 register port | `axil_ram` |
| `axi_dwidth_converter` 32 → 64 | `axi_up32to64` |
| DDR4 controller + DRAM | `axi_ram`, one per channel, with a backdoor port |
| `proc_sys_reset` | `kh_rst_sync` |

- `--compute` dies carry a node; the other dies keep station, Xache home and
  DRAM channel, with RAMs behind both node windows and the Xache master idle.
- `--sim-mesh` replaces every die's mesh top with one module (a 1x1 mesh for the
  2-node card); every other parameter is the image's.
- Clocks are top-level ports at the image's domains.

**Resets** follow `scripts/tcl/v8t3/20_clocks.tcl` ([clocking.md](../../../docs/arch/physical/clocking.md)):

- `rstn` is the fixed control wizard's lock;
- every die's sysnode domain (node, Xache partition, interlink) is held by
  `lock_all`, the AND of `rstn` and every mesh wizard's lock;
- control, station bus, DDR and XDMA domains wait on `rstn` alone.

A LOAD through a mesh wizard's window (station port 3) drops that wizard's lock
for `LOCK_CYC` cycles and so resets every sysnode domain on the card, as on
silicon.

**`clk_wiz_model`** answers the PG065 register map. Duty registers read 0 and a
full-word zero written to one answers SLVERR: the IP faults that write, and
`driver/kohakutpu/clock/card.py` composes 64-bit words around it, so a driver
that read-merges a duty half fails here as it does on the card.

## The harness

`card_main.cpp` owns `main()`, every clock and host manager 0 (64-bit AXI4 on
`bus_clk[1]`, the JTAG-to-AXI port on the card).

**Clocks** advance by the earliest pending edge across all of them:

| clock | period |
|---|---|
| `clk_ctrl` | 10.000 ns |
| `clk_xdma` | 4.000 ns |
| `bus_clk[0..3]` | 5.000, 5.010, 4.990, 5.020 ns |
| `ddr_clk[0..3]` | 3.332, 3.336, 3.328, 3.340 ns |
| mesh wizard outputs | `10 ns * D * div / M`, from `wiz_divclk`, `wiz_mult`, `wiz_div` |

The bus and DDR periods differ per die so no two domains stay phase-locked.
A mesh-wizard output stops while its wizard is unlocked and restarts at the
applied rate, so a driver retune behaves as on the card.

**Start-up:** `rstn` low for 50 control cycles, then every clock runs until
`sys_rstn` is all ones, then `--settle` die-0 sysnode cycles, then `READY`.

**Protocol** (every number hex, one reply line, `E <text>` on error):

| command | reply | meaning |
|---|---|---|
| `R <addr>` / `W <addr> <data>` | `V <data>` / `OK` | one 64-bit access |
| `RB <addr> <n>` / `WB <addr> <hex>` | `V <hex>` / `OK` | bursts of up to 256 beats, never across 4 KB |
| `BR <ch> <word>` / `BW <ch> <word> <hex>` | `V <hex>` / `OK` | one 512-bit DRAM word, backdoor |
| `SC <substr>` | `V scope:var:n:bytes ...` | public arrays whose scope contains `substr` |
| `PE <scope> <var> <idx> <n>` | `V <hex>` | read `n` elements |
| `PK <scope> <var> <idx> <hex>` | `OK` | write whole elements from `idx` |
| `T <n>` | `OK` | advance `n` die-0 sysnode cycles |
| `S` | `V sys= ctrl= decerr= sys_rstn= locked= ps=` | counters and state |
| `Q` | | exit |

Replies go to the original stdout, taken private at start; fd 1 becomes stderr,
so a `$display` from the model is never read as a reply. `VerilatorTransport`
sends stderr to `<build>/model.log`.

**Public arrays** are declared in `sim/verilator/card.vlt`: each node's
`rv64_syscore.spad` and every `xpm_memory_sdpram.mem` (the RV64 imem, the
staging banks). An element sits at `datap + k * entSize`, little-endian.

**`--no-timing`.** `vlt.py --cc` builds without `--timing`: the harness owns
time, so RTL `#` delays are not scheduled. With `--timing`, a model whose RTL
carries `#` delays stops with "Missed a time slot?" under a harness that steps
time edge by edge.

## Loading a program

`rv64load.LoadWindow` takes either path:

- `load_elf` streams the image through the node's load window, as on the card;
- `burn_elf` writes the RV64 imem and scratchpad arrays with `PK`, which skips
  the AXI traffic and exists only on the model.

`LoadWindow.run` then starts the core and polls its console the same way after
either.

## The checks

| script | what it checks |
|---|---|
| `scripts/py/card_run.py` | A_CAPS on every node; a block written through one node's memory window reads back through every node and sits in DRAM (backdoor); a mover copy across all four channels; `hello_kohakuaccel` on every node's RV64; station DECERR zero |
| `scripts/py/card_staging_check.py` | a pattern through each node's staging aperture reads back through the window and sits in that node's staging banks (`PE`); DECERR zero |
| `scripts/py/card_elf_run.py` | one RV64 ELF on one node; exit status is the program's exit word |

Each takes `--build <dir>` for a model built under another `--build-root`.

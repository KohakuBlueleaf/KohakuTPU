# L2 program

L2 is batches of work on named units: every value has a hardware-sized shape
and a named space, every op is one hardware feature or a fixed instruction
pattern of known cost, and the compiler decides only addresses, registers,
issue order, sync and packaging. `pipeline.compile_l1` runs the L2 -> L2
passes, lowers the body to L1 text ([../l1/program.md](../l1/program.md)) and
runs the image scheduler. Clause format, ids and evidence tags:
[../README.md](../README.md).

**Path prefixes.** Rust crate paths are relative to `software/kohakutpu/compiler/crates/`. `L/` =
`software/kohakutpu/language/kohakutpu/language/`, `K/` =
`software/kohakutpu/application/kohakutpu/application/`, `E/` =
`software/kohakutpu/language/kohakutpu/language/examples/`. Doc pages: `l2p` =
`docs/spec/l2-program.md`, `ktpu` = `docs/projects/kohakutpu/ir/ktpu.md`.

**Evidence.** The 455 card kernels were compiled from L2 by the compiler of
2026-10-21; an L2 construct whose L1 lowering appears in them is `silicon`
(per the statement tally of those kernels). They predate the 16-a-word
statistic pack, `unpack lane=`, `xrot`, gather / scatter index views and the
lane relayout. A refusal or error path is never `silicon`. `RTL` names a run
on a Verilated card; offline checks leave hardware-value clauses `unproven`.

## 1. A body

- **L2.BODY.001** `silicon` `fn NAME.l2(PARAM: TYPE @SPACE(LAYOUT), ...)` holds, first, `NAME = buffer : TYPE @SPACE(LAYOUT)` scratch statements, then the body. (code: ktpu-l2/src/ir/read.rs:48-98; evidence: every silicon kernel's scratch `h1`, `h2`, ... parameters)
- **L2.BODY.010** `unproven` A `buffer` without a target or a type is refused "NAME = buffer : TYPE @SPACE(LAYOUT)". (code: ktpu-l2/src/ir/read.rs:78-87; evidence: implementation inspected; qualifying device witness not established)
- **L2.BODY.002** `silicon` Read-time expansion/arithmetic precede L2 parsing; ordinary for loops remain in the body tree, while explicit unroll requests expansion. (code: ktpu-l2/src/ir/read.rs:52-55, :170-195; ktpu-l1/src/text/meta.rs:154-157, :222-273; evidence: 455 kernels and 160/137 loops)
- **L2.BODY.018** `unproven` Nonconstant when and computed indices are retained for per-instance resolution. Constant when selects/discards its block; expand expands the macro at read time. (code: ktpu-l2/src/ir/read.rs:52-55, :481-484, :548-551; ktpu-l1/src/text/meta.rs:158-187, :275-314, :364-385; evidence: implementation inspection)
- **L2.BODY.003** `silicon` `par VAR in LO..HI on UNIT[EXPR]` makes instances that run concurrently, instance VAR on unit UNIT[EXPR]; UNIT is `mg` or `vc`. (code: ktpu-l2/src/ir/read.rs:197-231, :439-459; evidence: `par ... on vc[..]` / `mg[..]` in every compiled kernel)
- **L2.BODY.004** `silicon` `for VAR in LO..HI` runs its iterations in order on the enclosing instance. (code: ktpu-l2/src/ir/read.rs:318-327, :461-479, :553-558; evidence: 455 kernels (`loop` 160 / 137, the mm kernels' K loops))
- **L2.BODY.011** `unproven` UNIT may be `node`. (code: ktpu-l2/src/ir/read.rs:14-15, :197-231; evidence: implementation inspected; qualifying device witness not established)
- **L2.BODY.012** `unproven` A par unit names `node`, `mg` or `vc` with one index. `mg[any]`/`vc[any]` record no assigned index; `node[any]` is refused. Unsupported unit names or index counts are refused. (code: ktpu-l2/src/ir/read.rs:197-230; evidence: implementation inspection)
- **L2.BODY.013** `unproven` `for VAR in LO..HI pipe=K` takes K an integer >= 1. (code: ktpu-l2/src/ir/read.rs:179-185; evidence: implementation inspected; qualifying device witness not established)
- **L2.BODY.014** `unproven` for accepts pipe=K and the internal keyword named by passes::step::LIFTED. pipe must be an integer at least one; other keywords/extra positionals are refused. The internal keyword value is not validated here. (code: ktpu-l2/src/ir/read.rs:170-195; ktpu-l2/src/passes/step.rs:15-16; evidence: implementation inspection)
- **L2.BODY.005** `unproven` Untargeted par/for require a named in-span binding and nonempty body, with diagnostics naming the operation. Nonempty blocks are refused except on untargeted par/for/when/if handled by their branches. (code: ktpu-l2/src/ir/read.rs:120-234; evidence: implementation inspection)
- **L2.BODY.006** `unproven` if sticky is a runtime block in a vector stream loop; lowering synchronizes math, reads GETSTK and wraps the block in SKIPZ. (code: ktpu-l2/src/ir/read.rs:131-144, :486-491, :538-546; ktpu-l2/src/lower/vector/ctx/emit/typed/iteration.rs:264-305; evidence: implementation inspection)
- **L2.BODY.007** `unproven` A `par` over sysnodes may hold unit `par`s. (code: ktpu-l2/src/ir/read.rs:424-459; evidence: implementation inspected; qualifying device witness not established)
- **L2.BODY.008** `silicon` A value is `NAME = OP ARGS : TYPE`; an effect (a store, a drain, a send) is `OP ARGS`. A type is `DTYPE[constant dims] @SPACE[(MODE)]`. (code: ktpu-l2/src/ir/read.rs:236-296; evidence: 455 kernels)
- **L2.BODY.015** `unproven` Untargeted if requires one positional sticky and a nonempty block. Instance walking refuses it at sysnode scope or in non-vector instances; the vector branch retains it without checking loop membership here. (code: ktpu-l2/src/ir/read.rs:131-144, :486-491, :538-546; evidence: implementation inspection)
- **L2.BODY.016** `unproven` A `par` inside a unit's instance is refused "a par inside a unit's instance". (code: ktpu-l2/src/ir/read.rs:529-536; evidence: implementation inspected; qualifying device witness not established)

## 4. Order

- **L2.ORDER.001** `unproven` Stages order required conflicting accesses, not a completion barrier after every par. A later stage waits for overlapping earlier unfinished accesses when one writes, subject to streamed and own-memory exceptions. Eligible pipeline stages can be sent ahead. (code: ktpu-l2/src/lower/sync.rs:58-75, :153-166, :202-249; evidence: implementation inspection; no qualifying device witness established)
- **L2.ORDER.002** `unproven` IR creates unit-par and sysnode-operation stages. Ordinary mover operations group, while quant/copy vector fallbacks, transpose, tiled GEMM and status use specialized stages. Consecutive stream stages with equal groups and overlapping rings may merge. Access records drive conflict ordering. (code: ktpu-l2/src/ir/read.rs:439-459, :493; ktpu-l2/src/lower/mod.rs:118-285; ktpu-l2/src/lower/group.rs:14-48; ktpu-l2/src/lower/sync.rs:19-50, :202-214; evidence: implementation inspection)
- **L2.ORDER.003** `silicon` Two accesses conflict when they share a key, one writes and their ranges meet -- except that two streamed accesses never conflict, and a unit touching its own memory both times is ordered by its own run. (code: ktpu-l2/src/lower/sync.rs:53-75; evidence: 455 kernels)
- **L2.ORDER.004** `silicon` Later stages wait for conflicting earlier accesses through latest required emission positions, excluding fences/already-complete positions. Waits use marks or posted-move tokens; a mark prints only when named by a wait. (code: ktpu-l2/src/lower/sync.rs:169-175, :197-214, :252-315; evidence: mark/wait 7752/165)
- **L2.ORDER.005** `unproven` Ordinary mover operations join a preceding posted mover stage only when the prior IR stage is an operation with matching pipeline group. With node_loop or qualifying looped vector quant they instead block. A closing final stage needs no appended completion; otherwise scheduling waits the last outstanding post then adds barrier, excluding already completed posts. (code: ktpu-l2/src/lower/mod.rs:255-282; ktpu-l2/src/lower/sync.rs:179-193; evidence: implementation inspection)
- **L2.ORDER.006** `unproven` When a grouped stage needs a wait, later stages of the same loop with iteration index below current iteration plus K may be emitted ahead if they require no wait and pass no fence, shared unit, or overlapping same-key access where either access writes. (code: ktpu-l2/src/lower/sync.rs:159-164, :217-249; evidence: implementation inspection; no qualifying device witness established)
- **L2.ORDER.007** `unproven` An accumulator-add sender follows its add drain with a COUNTed token drain. Before releasing a subsequent add sender, lowering consumes the previous token with `fill A0 recv n=1` and waits; the receiver also consumes outstanding tokens before its tail. An intermediate consumes its remote incoming token before forwarding its accumulator. Remote token consumption rings completion to the source, which consumes that completion before its tail. (code: ktpu-l2/src/lower/adds.rs:111-197; evidence: compiler handshake inspected; general receiver hardware semantics not independently established)
- **L2.ORDER.008** `unproven` The shared-memory ordering pass inserts no cross-sysnode handshake between stages with equal phase. (code: ktpu-l2/src/lower/nodes.rs:154-165; evidence: implementation inspection; no qualifying device witness established)
- **L2.ORDER.009** `unproven` For a cross-sysnode conflict across phases, ordering inserts a fence carrying the accesses of every earlier stage through the latest conflicting one (the frontier the release advertises), skips already-covered releases, rings the later sysnode's leased event slot, and places a consuming wait before the later stage. The fence waits on every unit stream with unfinished work in that frontier, not on all units. (code: ktpu-l2/src/lower/nodes.rs:129-245; ktpu-l2/src/lower/events.rs:147-149, :158-215; ktpu-l2/src/lower/sync.rs:202-214, :252-303; evidence: implementation inspection; no qualifying device witness established)

### Symbolic events and leases

Order releases and accumulator-ready streams retain symbolic identities until
all sysnode stages of the invocation have been assembled. `lower_events` leases
slots jointly for both kinds, then emits ordinary numeric ring/consuming-wait
operations. Slot identity is scoped to the receiving sysnode, not global.
Native accumulator COUNT markers retain their unit-level receive semantics.
`release_union` supplies every access through the advertised producer frontier,
including reads needed for write-after-read ordering.

`BackendSyncFacts` describes the slot ABI independently of `il.slots`.
Firmware exposes its hardware slots; KohakuAccel OS reserves messages 0–3,
credits 4–7 and barrier 8 (`software/kohakuaccel/os/include/kos/abi.h`).
The default common artifact uses the intersection, 9–15 on a 16-slot machine.
`lower_with_sync` accepts an explicit backend description. The description's
revision and available/reserved sets are compile-visible artifact identity.

`EventSpec` names producers, consumers, regions, kind, count and a lifetime;
`SlotLease` associates an event and receiver with one slot for that lifetime.
`allocate_slots` colours overlapping lifetimes independently per receiver.
Lifetime endpoints denote proven happens-before epochs: the end includes the
last consume and sender quiescence, not merely an instruction position or a
host generation number. The lowering's existing ordered streams hold their
leases for the whole invocation and preserve FIFO token counting. Replay must
start in a quiescent epoch. Distinct streams cannot alias during an invocation;
no phased-join insertion is implemented. Exhaustion refuses with
`L2.ORDER.009` rather than taking a reserved slot.

Code: `software/kohakutpu/compiler/crates/ktpu-l2/src/lower/events.rs`
(`BackendSyncFacts`, `allocate_slots`, `release_union`, `lower_events`),
`software/kohakutpu/compiler/crates/ktpu-l2/src/lower/nodes.rs` (`order_nodes`),
and `software/kohakutpu/compiler/crates/ktpu-l2/src/lower/adds.rs` (`added`).
Evidence: stage witnesses for overlapping edges, exhausted leases and the
multi-sysnode `xsplitk` example; no device result is asserted.

### Relayout prologues

`relayout.emit_steps` embeds planned relayouts in a consumer kernel. Scratch
buffers retain the transform grain and line ownership of standalone relayouts;
index and mask tables are explicit input ports. `prepared.rows_kernel` emits
one preparation for aliased readers, preserving each reader's offset.
Quant-side preparation (`forms.PREPARED_QUANT`) folds a pending packing only
under an admitted cost-profile recipe; otherwise packing receives
materialized inputs. Device-side nonfinite checking remains the
packing backend's contract; rows preparation does not assert that arbitrary
inputs are finite.

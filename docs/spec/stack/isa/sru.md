# ISA: the Streaming Row Unit

The Streaming Row Unit (unit kind `SR`, RTL top `sru_cu` around `sru_core`)
as the stack drives it: the profile it reads, the configuration map and the
five instructions, the pool schedule, and the `send sr[..]` block the
compiler turns into them (`ktpu-l1::lower::sru`, `ktpu-isa::unit::sru`,
`ktpu-verify::sim::row`).

**No clause on this page is `silicon`.** The v9t6 card has no SRU: its die
is two clusters and two vector cores
(`src/kohakutpu/top/generated/ktpu_ship_1x2_2c2v_1m_nol2_pump.v`: MG
(1,1), (1,2); VC (2,1), (2,2); board `multimesh_v9t6` is four of these
dies). The only image with
SRUs is the `4+2s` die of board `sru_v9t7`, which is simulation only (no
bitstream). RTL evidence is the xsim benches of `scripts/py/xsim.py:2325-2390`
(`docs/projects/kohakutpu/sru.md:187-200`); no Verilated-card test runs a
compiled `send sr[..]` block.

## Instructions

Each is one 256-bit payload, opcode in [255:252].

- **ISA.SR.010** `RTL` CFG (op 1) encodes the configuration word address in [251:244] and the value in [31:0]. The shell pulses cfg_we with those fields and the core writes that configuration word. These are payload bit positions for die.noc.data_bits [256]. (code: software/kohakutpu/compiler/crates/ktpu-isa/src/unit/sru/mod.rs:50-64, :246-249; src/kohakutpu/sru/sru_cu.v:515-525; src/kohakutpu/sru/sru_core.v:104-108; evidence: tests/sru/sru_cu_tb.v:263-279; scripts/py/sru/cu_vectors.py:33-34, :115-139)
- **ISA.SR.011** `RTL` LOAD (op 2) has what [251:250], first [249:240], addr [239:200], and words [199:188], counting die.word_bytes [32] bytes per memory word. what 0 loads four table entries per word from bits 64k +: 36; what 1 loads two column entries per word, each holding eight FP16 values in 128 bits, converted to E8M15. what 2 loads one row per word from the upper 24 bits of each of the first three 32-bit fields. (code: software/kohakutpu/compiler/crates/ktpu-isa/src/unit/sru/mod.rs:65-77, :250-260; src/kohakutpu/sru/sru_cu.v:335-372, :527-533; evidence: tests/sru/sru_cu_tb.v:263-279; scripts/py/sru/cu_vectors.py:95-113, :137-139)

Strides count die.word_bytes [32]-byte words; poff counts destination granules. The encoder writes words only for stream A, and writes zero there for memory A. Stream words controls initial and replenished credits; the shell does not compare it with NW * NSR. ## The pool schedule

- **ISA.SR.030** `RTL` For a nonempty pool program, M = (die.word_bytes / 2) / sr.profile.F_LANES chunks per word and II = NOPS * M cycles per window. In the SRU RTL a word has sixteen elements and slot i*M+e selects operation i and chunk e. KW selects an earlier window's word; the window can accept a word only at its first slot. This is an issue opportunity, not an unconditional throughput guarantee. SRU profile facts are null on v9t6. (code: software/kohakutpu/compiler/crates/ktpu-isa/src/unit/sru/config.rs:222-228, :306-343, :418-428; src/kohakutpu/sru/pool/sru_pool.v:78-108, :126-173; evidence: tests/sru/sru_core_tb.v:156-167, :183-224; scripts/py/sru/core_vectors.py:65-78, :612-643)
- **ISA.SR.031** `RTL` The scheduler reads sr.ldep, sr.wlead and sr.taps from the machine [null on v9t6; sru_v9t7 values are 18, 2 and 32]. It assigns each operation the earliest slot i*M+k*II satisfying earlier-result dependencies, then adds ceil(WLEAD/II) to its word-window depth. A result tap depth is sigma_i-sigma_k-LDEP and must fit [0,TAPS). RTL word histories shift once per window and result histories every cycle; the selected tap is registered at the operand stage. (code: software/kohakutpu/compiler/crates/ktpu-isa/src/unit/sru/config.rs:208-239, :306-343, :408-422; machines/sru_v9t7.json:192-194; src/kohakutpu/sru/pool/sru_pool.v:136-173, :198-216, :249-303; evidence: tests/sru/sru_core_tb.v:156-167,183-224; scripts/py/sru/core_vectors.py:65-78, :632-643 invokes the Rust scheduler and checks resulting execution)
- **ISA.SR.032** `unproven` The pool scheduler refuses a self or forward result reference, more than sr.profile.H_TAPS distinct earlier results for an operation, a result-tap depth outside [0, sr.taps), or KW >= sr.taps [no SRU instance on v9t6]. Independently, zero lanes or a lane count that does not divide the word element count is refused under ISA.SR.030. Unknown named sources and nonnumeric operation fields fail ISA.SR.022. L1 wraps schedule/configuration failures with the message prefix "the pool cannot run this program". (code: software/kohakutpu/compiler/crates/ktpu-isa/src/unit/sru/config.rs:306-325, :346-420; software/kohakutpu/compiler/crates/ktpu-l1/src/lower/sru.rs:464-469; evidence: host implementation inspection only)
- **ISA.SR.033** `unproven` The core changes the active pass only when its tracked pipeline is empty. A nonzero NOPS program issues only at pool window starts; with zero NOPS the pool is bypassed and an input word can issue each cycle in S_ISSUE. Both cases still require output reservation space and buffered data or valid A and required B. Thus II describes steady-state pool issue spacing, not end-to-end job throughput. (code: src/kohakutpu/sru/sru_core.v:151-166, :324-325, :532-537, :703-727; src/kohakutpu/sru/pool/sru_pool.v:85-108; evidence: implementation inspection only; tests/sru/sru_core_tb.v:201-214 checks completion and word count, not exact throughput)

## Semantics

- **ISA.SR.040** `RTL` A job processes NSR sub-rows of NW words. The SRU word layout is a four-by-four FP16 sub-tile: element (r,c) occupies lane 4r+c. For sub-row g and word h, the mask uses row 4g+r+ROWOFF and column 4h+c+COLOFF; row-state addressing instead starts from ROW0+4g. These fixed RTL sub-tile dimensions describe the SRU configuration [no SRU instance on v9t6]. (code: src/kohakutpu/sru/stream/sru_unpack.v:15-19; src/kohakutpu/sru/sru_core.v:243-267, :529, :648-675, :708-755; evidence: tests/sru/sru_core_tb.v:156-167, :211-224; scripts/py/sru/core_vectors.py:198-218)
- **ISA.SR.041** `unproven` With BUF disabled the sequencer runs pass zero directly from A and, when enabled, B. With BUF enabled and storage present, incoming A fills alternating buffer halves; pass zero performs the fill-stage statistics/finalise path, then the sequencer starts replay at pass one and continues until p equals NPASS. Buffer-half ownership allows a following sub-row fill to overlap replay. NPASS=0 does not skip replay: after pass zero the two-bit pass counter advances to one and wraps through the encoded pass space until it reaches zero. The emitter infers NPASS from the highest specified pass only when its value is zero. (code: src/kohakutpu/sru/sru_core.v:113-114, :143-175, :534-537, :674-701, :703-755; software/kohakutpu/compiler/crates/ktpu-l1/src/lower/sru.rs:450-457; evidence: implementation inspection only)
- **ISA.SR.042** `unproven` The data path unpacks A to E8M15, applies the optional mask to A, then uses either the pool result or the masked word. Enabled R2 accumulates that result per row in arrival order using sru_red sum followed by sru_sum2e8; it aligns element magnitudes with eight guard bits and arithmetically rescales the signed accumulator when the running exponent grows, rather than forming an ideal single-rounding sum. The output converts to the selected FP16 form before optional MXFP7 packing. R1 separately reduces raw input FP16 words before masking, using a sign-folded bit-pattern maximum, not IEEE maxNum: NaNs participate in that order. (code: src/kohakutpu/sru/sru_core.v:182-194, :233-275, :324-340, :355-393; src/kohakutpu/sru/stream/sru_red.v:58-86, :132-204; evidence: implementation inspection only; RUL.098 specifies the detailed sum arithmetic)
- **ISA.SR.043** `unproven` A pool FMA computes (NA ? -a : a) * b + (NC ? -c : c) in E8M15 with one ties-to-even rounding; there is no B sign-toggle field, though B may contain a negative value. Exponent-zero operands are signed zero. For finite operands the product sign is sa XOR sb, a zero product with nonzero addend returns the addend, and a zero addend takes the product sign. Two zero terms yield negative zero only when both are negative; exact cancellation yields positive zero. Bounds are checked after rounding: adjusted exponent <=0 produces signed zero and >=255 signed infinity. NaNs, zero times infinity and opposite infinities produce canonical NaN. A function operation uses a as x and b as k. EXP/FIX map x scaled by PRE through a truncated, saturated fixed-point representation; EXP subtracts clamped floor(k), while FIX clamps its segment and interpolation coordinate at the interval endpoints. Enabled MANT/HALF use mantissa and exponent mapping; HALF rejects negative nonzero x but not negative zero. NEG changes exponent scaling and zero/infinity handling. Reciprocal or square-root approximations depend on the loaded table, not the mode name alone. The signed table slope multiplies the interpolation coordinate shifted by CS within sixteen bits, then adds the table intercept before shared normalization/rounding. (code: src/kohakutpu/sru/pool/sru_pool.v:341-354; src/kohakutpu/sru/lane/sru_plane.v:133-171, :198-218, :256-279, :294-365, :374-419, :431-483, :557-588; software/kohakutpu/compiler/crates/ktpu-l1/src/lower/sru.rs:290-336, :356-397; evidence: implementation inspection; tests/sru/lane/sru_plane_tb.v:59-107, :191-225 reads variable vector counts, and coverage of the sixteen-bit CS overflow case is not established)
- **ISA.SR.044** `unproven` Finalise starts after required pass statistics are ready and the pipeline is empty. Each instruction issues the sub-row's four rows and waits for four results before advancing. ADD/SUB/MUL/FMA route through pool lane zero; RCP/RSQRT use that lane's mantissa path when sr.profile.FIN_RCP is enabled [no SRU instance on v9t6]. With FIN_RCP disabled those opcodes instead select MOV. MOV, MAX and MIN all replace an exponent-zero selected value with positive zero. MUL supplies an addend zero with the product sign. With no pool, arithmetic finalise requests have no result-valid response and finalise does not finish. (code: src/kohakutpu/sru/sru_core.v:296-321, :492-526, :623-644, :684-700, :714-719; src/kohakutpu/sru/pool/sru_pool.v:341-354; evidence: implementation inspection only)
- **ISA.SR.045** `unproven` Row state stores three E8M15 scalars per row in the RTL row-state RAM, capacity sr.rows [null on v9t6; the SRU RAM has 512 rows]. A sub-row loads four rows into a parity-selected working set, applies finalise writes there, then writes those four rows back. ROW0 supplies the first row base; the RAM address is truncated to its encoded row-index width, so indices wrap rather than raising a bounds fault. External row-state writes are accepted only while the core is idle. (code: src/kohakutpu/sru/sru_core.v:280-283, :411-420, :529, :627-632, :662-674, :745-755; evidence: implementation inspection only; tests/sru/sru_core_tb.v:215-224 checks ordinary row-state results, not wrapping)
- **ISA.SR.046** `unproven` With the relevant output features present and the pass marked EMIT, OUT=1 enqueues one FP16 sub-tile word per issued input word. OUT=2/3 routes through the MXFP7 packer in A/B layout. Each complete group of eight input sub-tile words produces four packed words; a sub-row must be a multiple of eight input words for the stated NW/2 output count. An incomplete final group is not flushed by the packer. With HAS_MX7 disabled, the core maps every nonzero OUT request to FP16, while the shell still derives its output length from the requested OUT bits. sr.profile.HAS_MX7 is null on v9t6, which has no SRU. - **ISA.SR.047** `unproven` FP16 conversion is selected by sr.profile.F16_IEEE [null on v9t6, which has no SRU]. ## Flow control

- **ISA.SR.050** `unproven` For stream A, RUN initially posts min(sr.fifo_depth, words) credits to (ax, ay), then replenishes up to sr.burst per group of that many A pops [both parameters null on v9t6; the SRU shell uses groups of eight]. Total posting is bounded by words, not validated against NW * NSR. The verifier reports a stream word-count mismatch, rejects nonzero landing buffers and counts only COUNT-marked arrivals. The RTL CU_DATA receiver uses the descriptor burst length but does not check its buffer or COUNT fields before writing payloads into A. (code: src/kohakutpu/sru/sru_cu.v:374-408, :563-569; software/kohakutpu/compiler/crates/ktpu-verify/src/sim/units/row.rs:113-130, :235-257; software/kohakutpu/compiler/crates/ktpu-verify/src/sim/card.rs:139-153; evidence: implementation inspection only)
- **ISA.SR.051** `unproven` Peer RUN output bursts contain min(remaining output words in this sub-row, sr.burst) words [sr.burst null on v9t6; the SRU shell cap is eight]. A header starts only when the entire burst is in the output FIFO and the shared credit count covers it. The burst length is deducted regardless of the RUN count bit. The descriptor addresses (px, py), buffer pbuf and the current granule offset, with COUNT equal to count. The offset starts at poff and increments modulo its encoded width after each word. (code: src/kohakutpu/sru/sru_cu.v:253-281, :395-396, :452-480, :544-559; software/kohakutpu/compiler/crates/ktpu-verify/src/sim/units/row.rs:289-313; evidence: implementation inspection only; tests/sru/sru_cu_tb.v:182-200 and scripts/py/sru/cu_vectors.py:167-196 exercise COUNT-set peer traffic, not COUNT-clear spending or offset wrap)
- **ISA.SR.052** `unproven` The A/B memory walkers reserve FIFO space on request issue and restore it when the core pops words. A request is bounded by the remaining sub-row length, free reserved capacity and the shell limit of 32 words; it waits for the smaller of the remaining length and the configured minimum run. The verifier instead makes memory A immediately available. Its stream-A progress model limits input by (completed output sub-rows + sr.held) * NW + sr.fifo_depth, substituting all job sub-rows as completed for non-peer output [sr.held and sr.fifo_depth null on v9t6]. - **ISA.SR.053** `unproven` The verifier reports residual COUNT-tracked A words and output credits when received totals differ from consumed totals. ## The `send sr[..]` block

The compiler's text form (`docs/projects/kohakutpu/ir/ktpu.md` s2.4).
Nothing runs this form on a model, so every clause here is `unproven`.

- **ISA.SR.060** `unproven` A send block holds `job`, `pass` (a block of `op` and `fin`), `load`, `run`, `store`, `post`; none binds a name and only `pass` takes a block. (code: software/kohakutpu/compiler/crates/ktpu-l1/src/lower/sru.rs:97-145; evidence: host reader implementation only)

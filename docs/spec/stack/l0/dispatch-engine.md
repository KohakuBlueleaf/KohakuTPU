# L0 dispatch engine

The hardware queue beside a node's processor that issues control-register
writes at one a cycle and holds each `WAIT` on a completion counter it keeps
itself; how the firmware drives it; and how `engine.lower` turns a bound
package into the entries it runs. The RTL is
`src/kohakuaccel/sysnode/dispatch/dispatch_engine.v` inside
`src/kohakuaccel/pe/rv64-sys/rv64_syscore.v`; the firmware side is
`software/firmware/kohakuaccel/package/interp.c` (engine mode) with registers in
`software/firmware/kohakuaccel/include/ka/dispatch/de.h`; the writer side is
`software/rust/crates/ktpu-l0/src/engine.rs`.

**What the card ran.** Every 2026-10-21 v9t6 package was lowered by
`engine.lower` into `ENGINE` steps and ran through the engine: a node without
one, or with boot flag `NOENGINE`, fails an `ENGINE` step with `BAD_STEP`, and
the runs completed. Those entries were mailbox writes for fetch requests (every
unit had a fetch port), mover writes and `WAIT`s on unit counters and the mover
source. The RTL testbench `tests/sysnode/dispatch_engine_tb.v`
(`vlt.py dispatch_engine`: randomised entry streams against a reference model,
with negative builds `NEG_GO`, `NEG_MV`, `NEG_ROOM`, `NEG_WAIT` that must fail)
covers the interlocks, claims, counters, overflow and clear.

## The engine

- **L0.DE.001** `silicon` `STAT` (control offset `0x300`, read) carries `0xDE01` in `[63:48]` on a node with an engine. The firmware runs a package through the engine when the magic is present, boot flag `NOENGINE` is clear, the package names at most `fw.engine_units` [16] units and every unit's class uses the generic classifier. (code: software/firmware/kohakuaccel/package/interp.c:896-910; software/firmware/kohakuaccel/include/ka/dispatch/de.h:19,32; doc: docs/spec/dispatch-engine.md:80-81; docs/spec/package-format.md:307-313; evidence: every card package ran in engine mode; LOG:90 value `de01064302350040` ([debug/firmware.md](../debug/firmware.md) `LOG`, the v9t6 card log))
- **L0.DE.035** `unproven` `STAT` reads 0 on a node without an engine; a package that fails any of those conditions runs on the firmware path. (code: software/firmware/kohakuaccel/package/interp.c:896-910; evidence: the v9t6 node has an engine and every card package met the conditions)
- **L0.DE.002** `silicon` An entry is a 6-bit code and a 64-bit value: codes 0-31 write target register `code` with the value; code 32 is a `WAIT`. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:5-9,59; software/firmware/kohakuaccel/include/ka/dispatch/de.h:20; doc: docs/spec/dispatch-engine.md:25-32; evidence: every card package)
- **L0.DE.003** `silicon` A store of value `v` at control offset `0x200 + 8c` (`c < 32`) queues a write entry of code `c`; a store at `0x300` queues a `WAIT`. (code: software/firmware/kohakuaccel/include/ka/dispatch/de.h:12-13,38; doc: docs/spec/dispatch-engine.md:72-73; evidence: every card package)
- **L0.DE.004** `silicon` On the RV64 node the write targets are the processor's control registers: codes 0-7 the dispatch mailbox at `0x40 + 8c` (0 `DST`, 1-4 `ARG0`-`ARG3`, 5 `GO`), codes 8-23 the mover at `0x100 + 8(c - 8)`. (code: software/firmware/kohakuaccel/include/ka/dispatch/de.h:26-29; ktpu-l0/src/engine.rs; doc: docs/spec/dispatch-engine.md:34-38; evidence: the card's fetch requests and moves)
- **L0.DE.005** `RTL` Codes 24-31 write the interlink window at `0xC0 + 8(c - 24)`; a `RING` is code 26 (`0xD0`). (code: software/firmware/kohakuaccel/include/ka/dispatch/de.h:30; ktpu-l0/src/engine.rs; evidence: software/application/tests/test_l1_examples.py::test_ring_slot_and_bell (its node 0 package lowers `RING` to code 26))
- **L0.DE.006** `silicon` A `WAIT`'s value is `src [60:56] | want [node.engine.counter_bits - 1 : 0]` (`node.engine.counter_bits` [12]); the queue holds until `(count(src) - want) mod 2^ctr_bits` is below `2^(ctr_bits - 1)`. A source below `fw.engine_units` [16] is that unit counter; source 16 is the mover's done count since the last clear. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:14-16,163-168; ktpu-l0/src/engine.rs; doc: docs/spec/dispatch-engine.md:40-44; evidence: every card package's `AWAIT`, `BARRIER` and move waits; tests/sysnode/dispatch_engine_tb.v checks each `WAIT` against the model's counter)
- **L0.DE.007** `silicon` A `WAIT` stays within `2^(ctr_bits - 1)` [2048] of its count only because every stream is credit-bounded: a unit's credit is at most `unit.inst_depth` [512] in flight, so the want of the next `WAIT` never passes the count by more than that. (code: ktpu-l0/src/engine.rs; doc: docs/spec/dispatch-engine.md:42-44; evidence: every card package)
- **L0.DE.008** `RTL` One entry leaves the head per cycle, in queue order. A write is held while: the processor writes a shared control window that cycle; it is a mailbox `GO` (code 5) and a flit is still offered or the previous `GO` is under `GO_GAP` [3] cycles old; it is a mover code (8-23) and the mover's configuration queue has no room; it is an interlink code (24-31) and a move the engine started is running or owed. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:18-26,170-182; evidence: tests/sysnode/dispatch_engine_tb.v (each interlock, with `NEG_GO`, `NEG_ROOM`, `NEG_MV`))
- **L0.DE.009** `RTL` A `CU_SIGNAL` from a source mapped to a counter, with code `0x00` (`INST_COMPLETE`) or `0x01` (`BATCH_COMPLETE`), while the engine is enabled and not clearing, is claimed: its counter rises by one and the processor's completion queue never sees it. Every other completion (a fault, an acknowledgement, any other code, an unmapped source) reaches the processor's completion queue. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:7-9,134-143; doc: docs/spec/dispatch-engine.md:60-66; evidence: tests/sysnode/dispatch_engine_tb.v (claim checked every cycle))
- **L0.DE.010** `silicon` `MAP` (control offset `0x310`, write): `[31]` valid, `[19:16]` counter, `[11:8]` y, `[3:0]` x maps a source coordinate to a counter; the map has `2^(2 die.noc.pos_bits)` [256] entries. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:122,155-160; software/firmware/kohakuaccel/include/ka/dispatch/de.h:15; doc: docs/spec/dispatch-engine.md:77; evidence: every card package's `WAIT`s were met through the counters these maps feed)
- **L0.DE.011** `silicon` `CTL` (control offset `0x308`, write): `[0]` enable, `[1]` clear (queue emptied, counters zeroed over `fw.engine_units` cycles, mover count rebased). (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:67; software/firmware/kohakuaccel/include/ka/dispatch/de.h:14; doc: docs/spec/dispatch-engine.md:75; evidence: written 3 then 2 around every card package)
- **L0.DE.012** `silicon` Reading `0x380 + 8k` gives counter `k`. (code: software/firmware/kohakuaccel/include/ka/dispatch/de.h:16; software/firmware/kohakuaccel/package/interp.c:938-945; doc: docs/spec/dispatch-engine.md:76-78; evidence: the firmware read both counters after the card failure: LOG:86-88 `inflight 3913` and `3916` are `(0 - counter) mod 4096` for `sent 0`, and `outstanding 7829` their sum; tests/sysnode/dispatch_engine_tb.v:289-295 checks every counter against its model)
- **L0.DE.036** `RTL` Reading `MOVES` (the engine's read 1, control offset `0x308`) gives `[43:32]` moves started since the clear. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:243; software/firmware/kohakuaccel/include/ka/dispatch/de.h:14; doc: docs/spec/dispatch-engine.md:76-78; evidence: tests/sysnode/dispatch_engine_tb.v:296-298)
- **L0.DE.037** `unproven` `MOVES [11:0]` is the moves done since the clear. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:163,243; doc: docs/spec/dispatch-engine.md:76-78; evidence: the testbench does not read the field and no firmware path reads `MOVES`)
- **L0.DE.013** `silicon` `STAT` fields: `[47:40]` log2 depth, `[39:36]` log2 counters, `[35]` overflow, `[34]` clearing, `[33]` head blocked, `[32]` enabled, `[31:16]` entries issued, `[15:0]` entries queued. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:240-242; software/firmware/kohakuaccel/include/ka/dispatch/de.h:32-36; doc: docs/spec/dispatch-engine.md:74; evidence: the firmware read the magic, depth, issued, queued and overflow fields for every card package (interp.c:661-682,686-697,882-894,901-923); LOG:90 value `de01064302350040` decodes as depth 64, 16 counters, no overflow, not clearing, head blocked, enabled, 0x235 issued, 64 queued (the queue full); tests/sysnode/dispatch_engine_tb.v checks magic, queued and overflow)
- **L0.DE.014** `RTL` A write queued while the queue is full is dropped and sets the overflow bit until the next clear. (code: src/kohakuaccel/sysnode/dispatch/dispatch_engine.v:77-78; doc: docs/spec/dispatch-engine.md:81-82; evidence: tests/sysnode/dispatch_engine_tb.v:203-212)
- **L0.DE.015** `silicon` The queue's depth is `node.engine.depth` [64, the `rv64_syscore` default `DE_DEPTH`]; the firmware reads it from `STAT [47:40]` and never queues past it. (code: src/kohakuaccel/pe/rv64-sys/rv64_syscore.v:39,821-823; software/firmware/kohakuaccel/package/interp.c:922-923; evidence: every card package; LOG:90 `STAT [47:40]` is 6, 64 entries, with 64 queued)

## The firmware in engine mode

- **L0.DE.016** `silicon` Before a package's first step the firmware unmaps the coordinates it mapped for the previous package, maps unit `i`'s coordinate to counter `i`, writes `CTL` 3 (clear and enable), and takes the queue's room as its depth. (code: software/firmware/kohakuaccel/package/interp.c:911-928; doc: docs/spec/dispatch-engine.md:86-90; evidence: every card package)
- **L0.DE.017** `silicon` After the last step the firmware queues the end barrier (a `WAIT` per unit for the larger of its words sent and its expected count, then a `WAIT` on the mover source for the package's GOs), waits until `STAT`'s queued count is 0, and writes `CTL` 2 (clear, disabled). (code: software/firmware/kohakuaccel/package/interp.c:870-879,882-894,933-948,1556-1559; doc: docs/spec/dispatch-engine.md:90; evidence: every card package)
- **L0.DE.041** `unproven` The next entry's words are read ahead (L0.NQ.053) between queueing the end barrier and waiting for the drain, while the engine issues on its own; reading them writes no engine register, and the next package's unmap, map and `CTL` 3 (L0.DE.016) follow this package's `CTL` 2 and completion. (code: software/firmware/kohakuaccel/package/interp.c (`ka_package_run`))
- **L0.DE.018** `silicon` The firmware queues an entry only while it holds room; with none left it reads `STAT` and takes `depth - queued` as its new room. (code: software/firmware/kohakuaccel/package/interp.c:684-707; doc: docs/spec/dispatch-engine.md:80-82; evidence: every card package longer than 64 entries)
- **L0.DE.019** `silicon` While it waits for room or for the drain, the firmware fails `TIMEOUT` with detail 11 (`ENGINE`, value the raw `STAT`; RUL.032) when the issued count has not moved for one timeout, whatever the queue is held on; the host decodes the head-blocked bit and the head entry's index (`STAT [31:16]`, entries issued) from the value. (code: software/firmware/kohakuaccel/package/interp.c:673-680; doc: docs/spec/dispatch-engine.md:90-96; evidence: LOG:84,89,90: `TIMEOUT` detail 2 at the `ENGINE` step 0, value `STAT` with the queue full and its head blocked, after a `steps` phase of 10,741,399 cycles under a bound of about 2,000,000)
- **L0.DE.038** `unproven` While it waits for room or for the drain, the firmware also pops whatever reaches the processor's completion queue (a fault fails the package `UNIT_FAULT`), reads `MVSTAT` and fails `MOVER_FAULT` on a mover fault, and fails `BAD_STEP` (detail `0xDE`, value `STAT`) on overflow. (code: software/firmware/kohakuaccel/package/interp.c:658-672; doc: docs/spec/dispatch-engine.md:90-96; evidence: no card log or test shows a unit fault, a mover fault or an overflow)
- **L0.DE.020** `silicon` After a failure in engine mode the firmware hands each unit's `(sent - counter) mod 2^12` to its own in-flight count, so the quiesce drains those completions, and writes `CTL` 2. (code: software/firmware/kohakuaccel/package/interp.c:931-948; doc: docs/spec/dispatch-engine.md:90-92; evidence: LOG:86-89: `sent 0` (the firmware counts no word of an `ENGINE` step) gave `inflight 3913` and `3916`, `outstanding 7829`, and the quiesce ran out its bound (`barrier` 2,025,680 cycles); see conflict 8)
- **L0.DE.021** `silicon` Mailbox writes are deduplicated: a write of `DST` or `ARG0`-`ARG3` whose value the register already holds from an earlier entry is not queued. The lowering resets its record at each `ENGINE` step's start; the firmware resets its record after each step it runs itself in engine mode. (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:709-718,1470; evidence: every card package's fetch requests repeat `DST`, `ARG0`-`ARG2`)

## `ENGINE` steps

- **L0.DE.022** `silicon` `engine.lower(pkg)` returns a package with the same units, buffers, signature, `ack_reserve` and checksum flag whose steps are `ENGINE` steps (and the steps the engine cannot carry, L0.STEP.058), its entries in new payloads appended after the package's own, and ending with the end barrier's entries. (code: ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:321-327; evidence: every card package)
- **L0.DE.023** `silicon` An `ENGINE` step's payloads hold three entries each: word 0 holds the three code bytes in bytes 0-2 (`0xFF` for none), words 1-3 the three values; the step's count is the number of entries. (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:847-863; doc: docs/spec/package-format.md:316-318; evidence: every card package)
- **L0.DE.024** `silicon` The firmware copies an `ENGINE` step's entries into the engine in order without decoding them. A code with bit 6 (`0x40`, `REL`) set has `((package address with bit 38 cleared) + payload table offset) << 24` added to its value and the bit removed: a fetch request's `ARG3` then names a payload by its offset in the package. (code: software/firmware/kohakuaccel/package/interp.c:838-866; ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/include/ka/package/format.h:76-78; doc: docs/spec/package-format.md:318-319; evidence: every card dispatch was a `REL` fetch request)
- **L0.DE.025** `unproven` A code above 32 once `REL` is removed fails the package with `BAD_STEP`, detail 11, value the code word. (code: software/firmware/kohakuaccel/package/interp.c:855-858; doc: docs/spec/package-format.md:320)
- **L0.DE.026** `unproven` An `ENGINE` step whose entries run past the payload table fails `BAD_LAYOUT`, detail its first payload, value `n_payload`. (code: software/firmware/kohakuaccel/package/interp.c:842-844)
- **L0.DE.027** `silicon` The node runs a lowered package's entries exactly as written: every credit wait, mailbox write and `WAIT` was decided by the writer, which tracks each unit's words sent, credit and `AWAIT`s as the firmware would. (code: ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:321-325; evidence: every card package)

## What the lowering writes

- **L0.DE.028** `silicon` A `DISPATCH` to a unit with a fetch port becomes fetch runs (L0.STEP.044, L0.STEP.045): per run a `WAIT` on the unit for `sent + n - room` when positive, `DST`, `ARG0`, `ARG1`, `ARG2` (deduplicated), `ARG3` with `REL` and value `payload offset << 24 | 0x60 << 8 | n`, then `GO` 1. (code: ktpu-l0/src/engine.rs; evidence: every card dispatch)
- **L0.DE.029** `unproven` A `DISPATCH` to a unit without a fetch port becomes per word: a `WAIT` on the unit for `sent + 1 - credit` when positive, `DST = y << 8 | x`, `ARG0`-`ARG3` (deduplicated), `GO` 1. (code: ktpu-l0/src/engine.rs)
- **L0.DE.030** `silicon` `AWAIT u n` becomes `WAIT(u, expected)` after `expected += n`; `BARRIER` becomes `WAIT(u, max(sent, expected))` for every unit, then `WAIT(16, GOs)`; `MOVER` becomes one entry of code `8 + register / 8` per pair, then `WAIT(16, GOs)` unless `POSTED`; `MWAIT n` becomes `WAIT(16, n)`. A `WAIT` whose want is not positive is left out. (code: ktpu-l0/src/engine.rs; evidence: every card package)
- **L0.DE.031** `RTL` `RING` becomes one entry of code 26 with the ring value of L0.STEP.031. A package whose entries would hold more than `node.ring_depth` RING entries between waits keeps every `RING` a step instead, run on the firmware path with its room wait (RUL.046, L0.STEP.032). (code: ktpu-l0/src/engine.rs; evidence: software/application/tests/test_l1_examples.py::test_ring_slot_and_bell)
- **L0.DE.032** `unproven` `FETCH` becomes fetch runs at its absolute address (no `REL`); `REPEAT` becomes its repetitions written out as payloads and sent as a `DISPATCH`. (code: ktpu-l0/src/engine.rs)
- **L0.DE.033** `RTL` `engine.lower` returns a package holding a `JUMP` or a `PATCH` unchanged. (code: ktpu-l0/src/engine.rs; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory, ::test_tiles_from_a_count_in_memory)
- **L0.DE.039** `unproven` `engine.lower` refuses (`PackageError`) a package with relocations, one with more than `fw.engine_units` [16] units, and one already holding an `ENGINE` step. (code: ktpu-l0/src/engine.rs)
- **L0.DE.040** `offline` Before a lowered package is sent, the host reads its `ENGINE` entries back as the node reads them (L0.DE.023, L0.DE.024) and refuses the package, naming this clause, unless every `DISPATCH` of the bound package is carried exactly and in order by its unit's fetch runs (`DST` the typed `MEM_RD_REQ` to the unit's own port, `ARG0`-`ARG2` as L0.STEP.044 writes them, `ARG3` with `REL` naming payloads `[arg, arg + count)`) or by mailbox words equal to those payloads (L0.DE.029); a `REPEAT`'s words by runs of payloads the lowering appended; a `FETCH` by runs at its absolute address without `REL` (L0.DE.032); each run at most `min(room, 255)` words after a `WAIT` on its unit for exactly `sent + n - room` when that is positive (L0.STEP.045); and every `WAIT` names a unit of the package or the mover (L0.DE.006); more than `node.ring_depth` RING entries between waits are refused naming RUL.046. The reader is written from these clauses with its own constants, sharing none with the lowering. (code: software/rust/crates/ktpu-l0/src/replay.rs; software/rust/crates/ktpu/src/python/mod.rs (`bind`); evidence: software/rust/crates/ktpu-l0/tests/clauses/de.rs: each of the mutants `l0.lower/no_rel`, `untyped_dst`, `fetch_depth`, `run_cap`, `src_mover` refused, `l0.check/off` lets a corrupted package by; every bound golden package passes)
- **L0.DE.034** `RTL` In engine mode the firmware queues the entries of an unlowered package's steps itself, from its own counts, the same entries as the lowering writes (with absolute payload addresses for fetch runs). (code: software/firmware/kohakuaccel/package/interp.c:720-836,1422-1457; doc: docs/spec/package-format.md:329-335; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory, ::test_tiles_from_a_count_in_memory)

# L0 sysnode queue

How a host hands work to a sysnode's dispatcher firmware and gets results back:
the queue region in card memory, the submission and completion rings, the
status codes, the stdio rings, the package heap and the sysnode's region heaps.
Both sides poll. The firmware side is
`software/kohakuaccel/firmware/queue/service.c` with the layout in
`software/kohakuaccel/firmware/include/ka/queue/layout.h` and the codes in
`software/kohakuaccel/firmware/include/ka/package/status.h`; the host side is
`software/kohakuaccel/driver/kohakuaccel/driver/node/queue/` (`client.py` `NodeQueue`,
`layout.py`). The boot block that names the region is
[boot-block.md](boot-block.md).

**What the card ran.** The 2026-10-21 v9t6 runs used one queue on sysnode 0, at
the start of its staging store, 1 MB, 64 submission and 64 completion entries,
4096 bytes of stdout and 256 of stdin
(software/kohakutpu/application/kohakutpu/application/runtime/card/common.py:37-42, :130-142; software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:285-299).
Every package was a `RUN` entry with no bindings; the runtime read each
completion's status and cycles and the stdout ring (the boot flag `TIMING`
lines). `NOP`, `STOP`, the heap opcodes, stdin, `SIGNAL` progress completions
and the region heaps were not exercised there.

## The region

- **L0.NQ.001** `silicon` Every address in the protocol is unit-global (mesh in `[37:36]`); the firmware reaches the region through the processor's uncached alias (bit `node.uncached_bit` [38]), so it never reads a stale copy of what the host wrote. (code: software/kohakuaccel/firmware/include/ka/hal/mem.h:8-17; software/kohakuaccel/firmware/queue/service.c:170-216; doc: docs/spec/node-queue.md:31-37; evidence: every card run)
- **L0.NQ.002** `silicon` The runtime reserves each sysnode’s queue at the start of its staging arena, using unit-global `1 << 39 | mesh << 36`. With staging enabled, the driver reaches it through that mesh’s memory window as `window | address`, retaining the complete low address. The host UP requester reaches the same converged staging decode as other requesters. (code: software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:231-251, :285-299; software/kohakutpu/application/kohakutpu/application/runtime/machine.py:67-69; software/kohakutpu/compiler/crates/ktpu-machine/src/card.rs:130-138; software/kohakuaccel/driver/kohakuaccel/driver/transport/rebase.py:82-86; src/kohakuaccel/sysnode/core/mag.v:620-636, :1120-1126, :1157-1192; src/kohakuaccel/sysnode/core/mag_dram_port.v:139-145, :621-625; evidence: The card queue uses staging; driver mapping is also af7c1bb:software/driver/kohakuaccel/driver/transport/rebase.py:79-83.)
- **L0.NQ.003** `unproven` `NodeQueue` refuses a region base that is not 4096-byte aligned. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:333-334; evidence: the card's staging base is aligned, so the refusal never ran)
- **L0.NQ.004** `silicon` Before the firmware boots the host writes the header line and zeroes everything up to the SQ (`0x440`), so every index starts at 0. The firmware takes its indices (CQ tail, stdout written and lost, stdin read, SQ head) from the region. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:464-501; software/kohakuaccel/firmware/queue/service.c:206-214, :310; doc: docs/spec/node-queue.md:77-80; evidence: every card boot)
- **L0.NQ.045** `unproven` Firmware starts from the indices already stored in the queue. Continuation therefore requires the host to preserve that queue; the runtime restart path instead stops the core and reinitializes the queue before restarting firmware. (code: software/kohakuaccel/firmware/queue/service.c:206-214, :310; software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:437-442; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.005** `silicon` Each fixed publication line has one writer; fields owned by that writer may share a line. Host publication uses complete `fw.queue.line` [64]-byte lines; firmware publishes individual eight-byte words. (code: software/kohakuaccel/firmware/include/ka/queue/layout.h:14-49; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:476-479, :903-906; software/kohakuaccel/firmware/queue/service.c:40-44, :86-87; evidence: af7c1bb:software/firmware/kohakuaccel/queue/service.c:25-30, :68-69 and af7c1bb:software/driver/kohakuaccel/driver/node/queue/client.py:136-142, :285-288 preserve this ownership.)
- **L0.NQ.006** `unproven` The fixed lines are: `0x000` host: magic `0x314555455551414B` ("KAQUEUE1"), the version the host speaks (the firmware accepts only `KA_Q_VERSION` 4), `sq_n | cq_n << 16`, `so_bytes | si_bytes << 32`, and at `0x020` the queue epoch (the host generation, initially 0 and incremented by initialization and non-no-op package invalidation); `0x040` firmware: state, ABI version, entries completed, fatal code, and at `0x060` the list ABI version (`KA_Q_LIST_VERSION` 1); `0x080` host: SQ tail; `0x0C0` firmware: SQ head; `0x100` firmware: CQ tail; `0x140` host: CQ head; `0x180` firmware: stdout bytes written, then bytes lost; `0x1C0` host: stdout read; `0x200` host: stdin written; `0x240` firmware: stdin read; `0x280` firmware: unit count, unit words from `0x2C0`; `0x340..0x43f` reserved; `0x440` the SQ. (code: software/kohakuaccel/firmware/include/ka/queue/layout.h:6-50; software/kohakuaccel/firmware/queue/service.c:25-45, :178-179, :204; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:131-189, :419-439; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:454-479, :692-715; doc: docs/spec/node-queue.md:90-108; evidence: every card run used af7c1bb:software/firmware/kohakuaccel/include/ka/queue/layout.h:6-25, version 3, no epoch or list ABI word, and firmware heap lines at `0x340`)
- **L0.NQ.007** `unproven` Without an established queue, fatal publication requires valid boot identity and regions, a nonzero queue region matching the boot queue address, queue-line alignment and sufficient extent for the firmware state line. Missing, invalid, mismatched or undersized fallback regions suppress publication. (code: software/kohakuaccel/firmware/queue/service.c:25-45; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.NQ.008** `silicon` The SQ is `sq_n` entries of 64 bytes at `0x440`; the CQ, `cq_n` entries of 32 bytes, follows it; the stdout ring starts at the next 64-byte line after the CQ; the stdin ring follows the stdout ring. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:502-506; software/kohakuaccel/firmware/queue/service.c:193-197; doc: docs/spec/node-queue.md:104-107; evidence: every card run)
- **L0.NQ.046** `unproven` Host geometry requires ring depths in 1..65535. Both geometry and info-line construction require each stdio size to be positive, less than 2^32 and a multiple of the queue line size. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:413-417, :428, :499-501; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.NQ.009** `unproven` Indices are cumulative entry or byte counts; ring slots use modulo capacity. Firmware waits while CQ tail minus host CQ head is at least CQ capacity. Full stdout waits at most the boot timeout before dropping remaining output; stdin consumption has no analogous full-ring wait. Firmware counters use finite-width uint64_t arithmetic. (code: software/kohakuaccel/firmware/queue/service.c:16-23, :59-103, :113-119, :206-214, :310-315; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:912-916)

## Firmware state and units

- **L0.NQ.010** `unproven` The firmware line holds the state (0 none, 1 ready, 2 stopped, 3 fatal), the ABI version (`KA_Q_VERSION`, 4), the entries completed and a fatal code; the firmware writes the ABI, done, fatal and list ABI words before the state word. The firmware writes ready only after it has published its units; the host polls until ready before its first submission. (code: software/kohakuaccel/firmware/queue/service.c:25-45, :303-308; software/kohakuaccel/firmware/include/ka/queue/layout.h:8; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:503-509, :555-583; doc: docs/spec/node-queue.md:93,254-256; evidence: every card boot waited for ready on af7c1bb:software/firmware/kohakuaccel/queue/service.c:25-31,206-213, which wrote ABI version 3 and its region heap lines before ready)
- **L0.NQ.047** `unproven` The host raises on a fatal state while it waits for ready: `BootRefused` (its refusal `code` and `reason`) when the fatal code is `KA_EXIT_BOOTARGS | reason`, else `FirmwareFatal`; both are `RuntimeError` subclasses carrying the firmware line and stdout. A stopped line raises `RuntimeError`. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:231-265, :555-583; evidence: no card boot went fatal)
- **L0.NQ.011** `unproven` The fatal hook flushes stdout only when Q.q is established. It then requests fatal state publication, which can refuse the fallback write if boot identity, region validation, queue address, alignment or extent checks fail. (code: software/kohakuaccel/firmware/queue/service.c:25-55; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.NQ.012** `silicon` The firmware publishes the units it serves (given in the boot block or enumerated) before ready: their count at `0x280`, the unit words from `0x2C0`, 8 bytes each, at most `fw.max_units` [16]. (code: software/kohakuaccel/firmware/queue/service.c:303-307; doc: docs/spec/node-queue.md:75-76,102; evidence: written at every card boot (af7c1bb:software/firmware/kohakuaccel/queue/service.c:205-209, line for line); the card runtime takes its units from the memory agent's scan (software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:202-230) and reads nothing here)
- **L0.NQ.048** `unproven` `NodeQueue.units` decodes the published units as `(type, mesh, x, y)`. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:535-553; evidence: no card or Verilated runtime path calls it)

## Submissions

- **L0.NQ.013** `unproven` An SQ entry is 64 bytes: word0 opcode in bits7:0 and binding count in31:16, word1 tag, words2–7 opcode arguments. The Python submission path, when not delegated to native_run, stages entries; flush writes contiguous batches before one SQ-tail publication. Reaching batch size or polling flushes. Firmware processes entries in order and publishes completion before advancing SQ head; ordinary entries increment done, while STOP exits separately. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:790-799, :842-910, :922-933; software/kohakuaccel/firmware/queue/service.c:311-383; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:452-465; evidence: af7c1bb:software/driver/kohakuaccel/driver/node/queue/client.py:285-290 publishes each entry and tail immediately.)
- **L0.NQ.014** `silicon` `NodeQueue` numbers its submissions 1, 2, ... and the completion returns the entry's tag. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:812-814, :154-155, :973-975; evidence: every card package)
- **L0.NQ.015** `silicon` `RUN` (1): word 2 the package's unit-global address, word 3 its length in bytes, word 4 the bindings' address or 0, word 5 the per-wait timeout in sysnode cycles (0 takes the boot block's), word 6 flags (`[0]` verify the checksum, `[1]` raise the host interrupt). (code: software/kohakuaccel/firmware/queue/service.c:325-336; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:19-21, :441-465; doc: docs/spec/node-queue.md:122; evidence: every card package (bindings 0, timeout 0, flags 0))
- **L0.NQ.016** `unproven` With `RUN` flag `IRQ` the firmware writes 1 to control offset `0x38` (toggling the host interrupt line) after posting the completion. (code: software/kohakuaccel/firmware/queue/service.c:349-353; src/kohakuaccel/pe/rv64-sys/rv64_syscore.v:623, :675-676; doc: docs/spec/node-queue.md:122)
- **L0.NQ.017** `unproven` With bindings, `NodeQueue` writes them (at most `fw.max_buffers` [64], else `ValueError`) as 64-bit words into the binding array of the entry's SQ slot, whole lines, and puts that array's address in word 4 and the count in word 0 `[31:16]`. The runtime package-binding path returns an empty RUN binding list. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:832-864; software/kohakutpu/application/kohakutpu/application/runtime/packages.py:233-246)
- **L0.NQ.018** `unproven` NOP returns the submitted tag, OK, and zero detail, step, cycles and value. (code: software/kohakuaccel/firmware/queue/service.c:113-134, :356-357; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.019** `unproven` `STOP` (2), word 2 the exit value: the firmware prints its counters, posts an `OK` completion, advances the SQ head, writes state stopped and exits with `KA_EXIT_STOP | (value & 0xFFFFFFFF)`. (code: software/kohakuaccel/firmware/queue/service.c:358-371; software/kohakuaccel/firmware/include/ka/hal/cpu.h:38; doc: docs/spec/node-queue.md:123)
- **L0.NQ.020** `unproven` Opcode 6 is `LIST` (L0.NQ.057); any opcode other than 0, 1, 2 and 6 completes `BAD_OP` (0x40), detail the opcode. (code: software/kohakuaccel/firmware/queue/service.c:354-357, :372-377; software/kohakuaccel/firmware/include/ka/queue/layout.h:102-118; doc: docs/spec/node-queue.md:202)
- **L0.NQ.053** `unproven` Unless SERIALQ is set, a standalone RUN supplies a next-SQ-entry peek callback. After successfully queuing its end barrier, when the engine remains active and the package is not localized in scratchpad, firmware can read the following queued SQ entry while the engine drains. The copied entry is served in queue order. LIST items do not supply this callback. (code: software/kohakuaccel/firmware/queue/service.c:142-160, :257-264, :316-335; software/kohakuaccel/firmware/package/interp.c:1880-1896)
- **L0.NQ.054** `unproven` Read-ahead may fetch the next submission while the dispatch engine drains, provided no failure is recorded at the peek point. That read does not guarantee execution: a subsequent drain failure enters quarantine before the prefetched submission can run. (code: software/kohakuaccel/firmware/package/interp.c:1077-1102, :1888-1905; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.NQ.055** `unproven` PKGT idle is the cycles between the previous result snapshot and this run’s start, or0 for the first run. The preceding timing printing therefore lies in this idle interval. (code: software/kohakuaccel/firmware/package/interp.c:1781-1782, :1930, :1961-1969; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.056** `unproven` Queue version `fw.queue.version` [4] adds cq_n run records of `fw.queue.record.bytes` [128] after stdin. Firmware writes each record before its CQ entry. Records carry tag, stdout count, timing fields, list_index, item_tag and the epoch captured when SQ dispatch starts. RUN records carry its timing; LIST terminal records sum invoked RUN timings componentwise. NOP, STOP, header-refused LIST and SIGNAL progress use zero timings. The host decodes the supplied record layout and refuses a mismatched tag with RecordSkew. Image ABI defaults an absent queue-version word to3, whose geometry has no records. (code: software/kohakuaccel/firmware/queue/service.c:113-128, :163-167, :234-286, :323-324, :356-366; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:957-996; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/layout.py:28-52, :489-514; software/kohakuaccel/driver/kohakuaccel/driver/node/boot/abi.py:23-54; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.057** `unproven` Production LIST flag bit 0 requests chaining for nonfinal items. Eligible packages queue end barriers without stopping or clearing the engine; following eligible packages reuse coordinate-matched counters and rebase WAITs by accumulated targets. An ineligible package ends a held chain. Draining chain settlement compares counts with accumulated dispatch/completion targets modulo counter width and reports BAD_STEP detail 0xdc on mismatch. A fault discovered while a later item queues can be attributed to that item. Measuring and debug builds disable chaining. The host execution-list preparation helper sets the flag only when KOHAKUTPU_LIST_CHAIN=1. (code: software/kohakuaccel/firmware/queue/service.c:257-264; software/kohakuaccel/firmware/package/interp.c:70-78, :955-1020, :1026-1101, :1880-1896; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/execution.py:41-58)
- **L0.NQ.058** `unproven` With nap enabled, list submission predicts due time using its last measured duration. Before due, sleep is bounded by nap and remaining predicted time; after due the wait uses exponential backoff capped by backoff. An unpredicted wait past spin also naps for min(nap, age/16). (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:760-765, :1043-1073; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.021** `unproven` Dispatcher queue opcodes3–5 return BAD_OP with detail the opcode; there is no dispatcher queue memory-allocation service. The dedicated memory mutant disables this refusal. (code: software/kohakuaccel/firmware/queue/service.c:372-377; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)

## Completions

- **L0.NQ.022** `unproven` A completion has four 64-bit words: tag; status[15:0], detail[31:16], step[63:32]; cycles; value. Firmware writes the run record, CQ words, then CQ tail. Host polling validates its completion snapshot and records before publishing CQ head. (code: software/kohakuaccel/firmware/queue/service.c:113-138; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:957-996; evidence: af7c1bb:software/firmware/kohakuaccel/queue/service.c:87-100 writes CQ without a preceding run record.)
- **L0.NQ.023** `unproven` The firmware never posts into a full CQ: it waits, yielding, until the host's CQ head leaves room. (code: software/kohakuaccel/firmware/queue/service.c:116-118; doc: docs/spec/node-queue.md:258-259)
- **L0.NQ.024** `silicon` A `RUN` completion's step is the failing step's index, or on success the index the step loop ended at (the step count after running off the end); its cycles count sysnode cycles from the start of the run, before the header read, to the result, the quiesce after a failure included. (code: software/kohakuaccel/firmware/package/interp.c:1781, :1925-1930; software/kohakuaccel/firmware/queue/service.c:341-350; doc: docs/spec/node-queue.md:154-156; evidence: the card runtime reports every run's cycles from this field (card.py:353,437-440); LOG:84 step 0 and 12,768,463 cycles for the failed package 0x83b, its quiesce included ([debug/firmware.md](../debug/firmware.md) `LOG`, the v9t6 card log))
- **L0.NQ.025** `silicon` A failed `RUN`'s value is the failure's value; a successful one's is the firmware's count of instruction words it dispatched itself (fetch runs and mailbox words it queued or sent), which does not count entries copied from `ENGINE` steps. (code: software/kohakuaccel/firmware/queue/service.c:349-350; software/kohakuaccel/firmware/package/interp.c:766-767, :790-791, :876-909; doc: docs/spec/node-queue.md:157; evidence: every card completion carried it (af7c1bb:software/firmware/kohakuaccel/queue/service.c:241-242, the same value); LOG:89 `sent 0` is that count for a lowered package, LOG:90 the failure's value)
- **L0.NQ.026** `unproven` SIGNAL posts PROGRESS (0x01) with the enclosing SQ tag: the RUN tag for standalone RUN or LIST tag for a LIST item. Detail is the signal count truncated to 16 bits, step is the SIGNAL index, cycles is the absolute sysnode cycle counter, and value is its 64-bit argument. Stdout is flushed first. (code: software/kohakuaccel/firmware/queue/service.c:131-132, :163-168, :251-263, :321-324)
- **L0.NQ.027** `unproven` Polling stores PROGRESS completions separately in `NodeQueue.progress`; only final completions populate the final-result map and retire package tags. Wait checks the final-result map. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:997-1012, :1045-1083; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.NQ.049** `silicon` `wait(check=True)` raises NodeError on a non-OK final completion, carrying that completion and stdout. `wait(check=False)` and `take` return the completion without that status check. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1074-1094; evidence: af7c1bb:software/driver/kohakuaccel/driver/node/queue/client.py:338-350 checks status only in checked wait; recorded TIMEOUT failure confirms the raising path.)
- **L0.NQ.028** `silicon` Status `0x00` is `OK`. (code: software/kohakuaccel/firmware/include/ka/package/status.h:7; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/status.py:7; doc: docs/spec/node-queue.md:186; evidence: every successful card package)
- **L0.NQ.029** `silicon` Status `0x30` is `TIMEOUT` (detail L0.STEP.005). Detail and step are 16 and 32 bits in the completion. (code: software/kohakuaccel/firmware/include/ka/package/status.h:23; software/kohakuaccel/firmware/queue/service.c:131-132; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/status.py:23; doc: docs/spec/node-queue.md:182-207; evidence: LOG:84,90: `TIMEOUT`, `status 30 detail 2 step 0`)
- **L0.NQ.050** `unproven` The other status codes: `0x01 PROGRESS`, `0x10 BAD_MAGIC`, `0x11 BAD_VERSION`, `0x12 BAD_SIGNATURE` (value the sysnode's signature), `0x13 BAD_CHECKSUM` (value the sum computed), `0x14 BAD_STEP`, `0x15 TOO_LARGE`, `0x16 BAD_RELOC`, `0x17 BAD_UNIT`, `0x18 BAD_LAYOUT`, `0x20 UNIT_FAULT` (detail the unit index, value the completion word), `0x21 MBOX_OVERFLOW` (reserved, raised nowhere), `0x22 MOVER_FAULT` (detail the mover's fault code), `0x23 NO_REACH`, `0x24 CONTRACT` (an `ASSERT_ZERO` step whose register is nonzero: detail the low 16 bits of the step count, value the register), `0x40 BAD_OP`, `0x50 NO_MEMORY`, `0x51 NO_SLOTS`, `0x52 BAD_FREE`, `0x53 BAD_ARG`, `0x54 HEAP_BUSY`. (code: software/kohakuaccel/firmware/include/ka/package/status.h:6-30; software/kohakuaccel/firmware/package/interp.c:1622-1626; software/kohakuaccel/firmware/queue/service.c:131-132; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/status.py:6-30; doc: docs/spec/node-queue.md:184-210)

## stdio

- **L0.NQ.030** `silicon` Everything the firmware prints goes to the stdout ring once the queue service has started: byte `i` at ring offset `(written mod so_bytes)`, stored as whole 8-byte words, then the written count and the lost count are stored. The host reads the bytes between its read count and the written count (at most `so_bytes`), wrapping at the ring's end, and writes its read count line. (code: software/kohakuaccel/firmware/queue/service.c:59-88, :297; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1226-1260; doc: docs/spec/node-queue.md:214-220; evidence: the card runtime read every run's `PKGT` timing line through this ring)
- **L0.NQ.031** `unproven` A full stdout ring holds the firmware for one boot timeout; then the remaining bytes of that write are dropped and added to the lost count. (code: software/kohakuaccel/firmware/queue/service.c:64-74; doc: docs/spec/node-queue.md:215-217)
- **L0.NQ.032** `unproven` The host checks stdin capacity before modifying ring data: outstanding bytes are the written count minus the firmware consumed count modulo 2^64. Input larger than ring capacity minus outstanding bytes raises ValueError. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1286-1290; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.NQ.033** `unproven` Without `native_poll`, poll reads the six-line status block from0x040 through0x180 and extracts state, SQ head, CQ tail and stdout count, reading stdout when its count changes. With native polling it obtains the header and poll count from the callback. ## Host-only allocation

RUL.024 is the queue contract: opcodes 3..5 are reserved and return `BAD_OP`.
Dispatcher images exclude `os/heap`, and heap statistics are not published.
The fixed 0x340 offset is reserved ABI space. Allocator policy tests of the
standalone `osprobe` do not establish queue support. See
[memory.md](memory.md); vectors `RUL.024.host_contract` and
`RUL.024.card_refuses`.

- **L0.NQ.038** `unproven` Queue opcode 3 is reserved and returns `BAD_OP`; it cannot configure a firmware region heap. Regions are assigned through the boot block. (tier-1 vector: RUL.024.card_refuses) (code: software/kohakuaccel/firmware/queue/service.c:372-377)
- **L0.NQ.039** `unproven` Queue opcode 4 is reserved and returns `BAD_OP`; the production dispatcher queue provides no DRAM allocation service. (tier-1 vector: RUL.024.card_refuses) (code: software/kohakuaccel/firmware/queue/service.c:372-377)
- **L0.NQ.040** `unproven` Queue opcode 5 is reserved and returns `BAD_OP`; allocation lifetimes belong to the host. (tier-1 vector: RUL.024.card_refuses) (code: software/kohakuaccel/firmware/queue/service.c:372-377)
- **L0.NQ.041** `unproven` Queue offsets 0x340..0x43f are reserved. The firmware publishes no heap statistics there. (code: software/kohakuaccel/firmware/include/ka/queue/layout.h:14-50)
- **L0.NQ.042** `unproven` Dispatcher images carry no region-heap bookkeeping and exclude `os/heap` sources. (code: software/kohakutpu/firmware/build.py:190-208; tier-0 vector: RUL.024.host_contract)
- **L0.NQ.043** `unproven` The queue client and its daemon proxy expose no heap configuration, allocation, free or heap-statistics methods. The standalone heap policy module is not a queue protocol. (code: software/kohakuaccel/driver/kohakuaccel/driver/daemon/client.py:142-210)

## What a host owes

- **L0.NQ.044** `silicon` The host writes the region's header and zeroes its indices before the firmware boots; writes the boot block after the image and before boot; waits for ready before the first submission; writes whole 64-byte lines, the SQ entry before the SQ tail; reads the CQ tail before the entries it publishes and advances the CQ head after; reads a package's results from memory only after its completion. (code: software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:278-361; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:464-501, :769-1012; doc: docs/spec/node-queue.md:252-263; evidence: every card run followed this order)
- **L0.NQ.052** `unproven` The device applies its configured positive max_inflight limit, or no limit for None, collecting oldest first when reached and retrying under allocation pressure. Successful collection releases submission references; reusable scratch windows can outlive one collection. Queue polling retires package tags on final completion; SQ binding slots are reusable after head advancement.

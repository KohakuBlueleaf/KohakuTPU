# L0 node queue

How a host hands work to a node's dispatcher firmware and gets results back:
the queue region in card memory, the submission and completion rings, the
status codes, the stdio rings, the package heap and the node's region heaps.
Both sides poll. The firmware side is
`software/firmware/kohakuaccel/queue/service.c` with the layout in
`software/firmware/kohakuaccel/include/ka/queue/layout.h` and the codes in
`software/firmware/kohakuaccel/include/ka/package/status.h`; the host side is
`software/driver/kohakuaccel/driver/node/queue/` (`client.py` `NodeQueue`,
`layout.py`). The boot block that names the region is
[boot-block.md](boot-block.md).

**What the card ran.** The 2026-10-21 v9t6 runs used one queue on node 0, at
the start of its staging store, 1 MB, 64 submission and 64 completion entries,
4096 bytes of stdout and 256 of stdin
(software/application/kohakutpu/application/runtime/card.py:62-65,76-89,211-218).
Every package was a `RUN` entry with no bindings; the runtime read each
completion's status and cycles and the stdout ring (the boot flag `TIMING`
lines). `NOP`, `STOP`, the heap opcodes, stdin, `SIGNAL` progress completions
and the region heaps were not exercised there.

## The region

- **L0.NQ.001** `silicon` Every address in the protocol is unit-global (mesh in `[37:36]`); the firmware reaches the region through the processor's uncached alias (bit `node.uncached_bit` [38]), so it never reads a stale copy of what the host wrote. (code: software/firmware/kohakuaccel/include/ka/hal/mem.h:8-17; software/firmware/kohakuaccel/queue/service.c:114-145; doc: docs/spec/node-queue.md:31-37; evidence: every card run)
- **L0.NQ.002** `silicon` The card runtime puts each node's queue region at the start of that node's staging store (`1 << 39 | mesh << 36`), `Q_SIZE` 1 MB long, and the host reaches it through that mesh's memory window. (code: software/application/kohakutpu/application/runtime/card.py:62,211-218; doc: docs/spec/node-queue.md:39-45; evidence: every card run)
- **L0.NQ.003** `unproven` `NodeQueue` refuses a region base that is not 4096-byte aligned. (code: software/driver/kohakuaccel/driver/node/queue/client.py:94-95; evidence: the card's staging base is aligned, so the refusal never ran)
- **L0.NQ.004** `silicon` Before the firmware boots the host writes the header line and zeroes everything up to the SQ (`0x440`), so every index starts at 0. The firmware takes its indices (CQ tail, stdout written and lost, stdin read, SQ head) from the region. (code: software/driver/kohakuaccel/driver/node/queue/client.py:134-151; software/firmware/kohakuaccel/queue/service.c:136-145,215; doc: docs/spec/node-queue.md:77-80; evidence: every card boot)
- **L0.NQ.045** `unproven` A restarted firmware continues a queue the host still holds. (code: software/firmware/kohakuaccel/queue/service.c:136-145,215; doc: docs/spec/node-queue.md:77-80; evidence: no card log records a restart, and `NodeCard.restart` re-initialises every queue before it boots (card.py:243-246))
- **L0.NQ.005** `silicon` Each field has one writer and sits alone at the start of its own `LINE`-byte line (`LINE` 64); the host writes whole lines only; the firmware writes single 8-byte words with uncached stores. (code: software/driver/kohakuaccel/driver/node/queue/layout.py:13,86-89; software/firmware/kohakuaccel/include/ka/queue/layout.h:9-10; doc: docs/spec/node-queue.md:82-88; evidence: every card run (XDMA writes 64-byte lines))
- **L0.NQ.006** `silicon` The fixed lines are: `0x000` host: magic `0x314555455551414B` ("KAQUEUE1"), version 3, `sq_n | cq_n << 16`, `so_bytes | si_bytes << 32`; `0x040` firmware: state, ABI version, entries completed, fatal code; `0x080` host: SQ tail; `0x0C0` firmware: SQ head; `0x100` firmware: CQ tail; `0x140` host: CQ head; `0x180` firmware: stdout bytes written, then bytes lost; `0x1C0` host: stdout read; `0x200` host: stdin written; `0x240` firmware: stdin read; `0x280` firmware: unit count, unit words from `0x2C0`; `0x340..0x43f` reserved; `0x440` the SQ. (code: software/firmware/kohakuaccel/include/ka/queue/layout.h:6-26; software/driver/kohakuaccel/driver/node/queue/layout.py:11-27; doc: docs/spec/node-queue.md:90-107; evidence: every card run)
- **L0.NQ.007** `unproven` A region whose magic or version is not the firmware's, or whose geometry has a zero ring depth, a zero stdio size or a stdio size that is not a multiple of 64, makes the firmware print the reason to the console and exit with `KA_EXIT_BOOTARGS | 0x10`. (code: software/firmware/kohakuaccel/queue/service.c:112-129,197-201; software/firmware/kohakuaccel/include/ka/hal/cpu.h:37)
- **L0.NQ.008** `silicon` The SQ is `sq_n` entries of 64 bytes at `0x440`; the CQ, `cq_n` entries of 32 bytes, follows it; the stdout ring starts at the next 64-byte line after the CQ; the stdin ring follows the stdout ring. (code: software/driver/kohakuaccel/driver/node/queue/layout.py:98-103; software/firmware/kohakuaccel/queue/service.c:130-134; doc: docs/spec/node-queue.md:104-107; evidence: every card run)
- **L0.NQ.046** `unproven` The host's `geometry` refuses (`ValueError`) ring depths outside 1-65535 and stdio sizes that are not whole nonzero lines. (code: software/driver/kohakuaccel/driver/node/queue/layout.py:94-97; evidence: the card runtime's geometry is valid, so the refusal never ran)
- **L0.NQ.009** `silicon` Indices count entries or bytes ever, never wrapped; a slot is the index modulo its ring's size; a ring is empty when its two indices are equal and full when they differ by its size. (code: software/firmware/kohakuaccel/queue/service.c:90,217-221; software/driver/kohakuaccel/driver/node/queue/client.py:262-266; doc: docs/spec/node-queue.md:109-111; evidence: every card run)

## Firmware state and units

- **L0.NQ.010** `silicon` The firmware line holds the state (0 none, 1 ready, 2 stopped, 3 fatal), the ABI version (the queue version, 3), the entries completed and a fatal code. The firmware writes ready only after it has published its units and region heap lines; the host polls until ready before its first submission. (code: software/firmware/kohakuaccel/queue/service.c:25-31,205-214; software/driver/kohakuaccel/driver/node/queue/client.py:153-158,179-186; doc: docs/spec/node-queue.md:93,228-230; evidence: every card boot waited for ready)
- **L0.NQ.047** `unproven` The host raises on a fatal state while it waits for ready (`RuntimeError` with the firmware line and stdout). (code: software/driver/kohakuaccel/driver/node/queue/client.py:187-190; evidence: no card boot went fatal)
- **L0.NQ.011** `unproven` On a fatal trap the firmware flushes stdout and writes state fatal with the trap's code. (code: software/firmware/kohakuaccel/queue/service.c:33-41)
- **L0.NQ.012** `silicon` The firmware publishes the units it serves (given in the boot block or enumerated) before ready: their count at `0x280`, the unit words from `0x2C0`, 8 bytes each, at most `fw.max_units` [16]. (code: software/firmware/kohakuaccel/queue/service.c:205-209; doc: docs/spec/node-queue.md:72-73,102; evidence: written at every card boot (service.c unchanged since af7c1bb); the card runtime takes its units from the memory agent's scan (card.py:157-171) and reads nothing here)
- **L0.NQ.048** `unproven` `NodeQueue.units` decodes the published units as `(type, mesh, x, y)`. (code: software/driver/kohakuaccel/driver/node/queue/client.py:160-177; evidence: no card or Verilated runtime path calls it)

## Submissions

- **L0.NQ.013** `silicon` A submission entry is 64 bytes, written whole: word 0 `[7:0]` the opcode and `[31:16]` the number of bindings, word 1 the tag, words 2-7 by opcode, unused words 0. The host writes the entry, then the SQ tail line. The firmware runs entries one at a time in order: it runs the entry, posts its completion, counts it done, then advances the SQ head, so a slot is free once the head has passed it (the next entry may be read before that, L0.NQ.053). (code: software/driver/kohakuaccel/driver/node/queue/client.py:280-288; software/firmware/kohakuaccel/queue/service.c:216-276; doc: docs/spec/node-queue.md:113-132; evidence: every card package)
- **L0.NQ.014** `silicon` `NodeQueue` numbers its submissions 1, 2, ... and the completion returns the entry's tag. (code: software/driver/kohakuaccel/driver/node/queue/client.py:266-268,313-321; evidence: every card package)
- **L0.NQ.015** `silicon` `RUN` (1): word 2 the package's unit-global address, word 3 its length in bytes, word 4 the bindings' address or 0, word 5 the per-wait timeout in node cycles (0 takes the boot block's), word 6 flags (`[0]` verify the checksum, `[1]` raise the host interrupt). (code: software/firmware/kohakuaccel/queue/service.c:227-237; software/driver/kohakuaccel/driver/node/queue/layout.py:41-45; doc: docs/spec/node-queue.md:121; evidence: every card package (bindings 0, timeout 0, flags 0))
- **L0.NQ.016** `unproven` With `RUN` flag `IRQ` the firmware writes 1 to control offset `0x38` (toggling the host interrupt line) after posting the completion. (code: software/firmware/kohakuaccel/queue/service.c:243-245; doc: docs/spec/node-queue.md:121)
- **L0.NQ.017** `unproven` With bindings, `NodeQueue` writes them (at most `fw.max_buffers` [64], else `ValueError`) as 64-bit words into the binding array of the entry's SQ slot, whole lines, and puts that array's address in word 4 and the count in word 0 `[31:16]`. No current stack path submits bindings. (code: software/driver/kohakuaccel/driver/node/queue/client.py:26-27,272-279; software/application/kohakutpu/application/runtime/packages.py)
- **L0.NQ.018** `unproven` `NOP` (0) completes `OK` with every field 0. (code: software/firmware/kohakuaccel/queue/service.c:250-251)
- **L0.NQ.019** `unproven` `STOP` (2), word 2 the exit value: the firmware prints its counters, posts an `OK` completion, advances the SQ head, writes state stopped and exits with `KA_EXIT_STOP | (value & 0xFFFFFFFF)`. (code: software/firmware/kohakuaccel/queue/service.c:256-268; software/firmware/kohakuaccel/include/ka/hal/cpu.h:38; doc: docs/spec/node-queue.md:122)
- **L0.NQ.020** `unproven` Any other opcode completes `BAD_OP` (0x40), detail the opcode. (code: software/firmware/kohakuaccel/queue/service.c:269-270; doc: docs/spec/node-queue.md:167)
- **L0.NQ.053** `unproven` Unless boot flag `SERIALQ` (bit 5) is set, once a `RUN` on the dispatch engine has queued its end barrier without failing, and its package is not held in the scratchpad (L0.PKG.029), the firmware reads the words of the entry after it, if the host has queued one, while the engine drains; that entry is then served from those words in its turn. Nothing else of it is done ahead. (code: software/firmware/kohakuaccel/package/interp.c (`ka_package_run`, `ka_package_ahead`); software/firmware/kohakuaccel/queue/service.c (`peek`, `entry`); evidence: software/driver/tests/test_exec_list.py on the firmware double)
- **L0.NQ.054** `unproven` An entry read ahead (L0.NQ.053), whatever its opcode, runs in its turn after the running entry completes; a `RUN` that fails reads nothing ahead, and an entry queued only after the one before it completed is read in its turn. (code: software/firmware/kohakuaccel/queue/service.c (`peek`); evidence: software/driver/tests/test_exec_list.py on the firmware double)
- **L0.NQ.055** `unproven` A run's `PKGT` line (L0.BOOT.010) ends `idle I`: the node cycles from the previous run's result to this one's start. (code: software/firmware/kohakuaccel/package/interp.c (`ka_package_run`))
- **L0.NQ.056** `unproven` Version 4 of the region (`fw.queue.version`) holds a run record ring after the stdin ring: `cq_n` records of `fw.queue.record.bytes` [128]. Before it writes CQ entry `i`, the firmware writes record `i mod cq_n`: the entry's tag, the stdout bytes written at that point, and for a `RUN` its timing words (`head`, `copy`, `bind`, `steps`, `barrier`, `local`, `total`, `first`, `last`, `sent`, `idle`, as in its PKGT line), else 0; field offsets and widths are `fw.queue.record.fields`, from queue/layout.h. A host given that layout decodes each completion's record and refuses one whose tag is not the completion's (`RecordSkew`). The host speaks the version the image's `.ka_abi` word 4 names (3 for an image without it); version 3 has no record ring. (code: software/firmware/kohakuaccel/queue/service.c (`push_cq`); software/driver/kohakuaccel/driver/node/queue/layout.py (`Record`, `geometry`); scripts/py/machine/table.py (`fw_queue_record`); evidence: software/driver/tests/test_run_record.py on the firmware double)
- **L0.NQ.021** `RTL` Opcodes 3..5 are reserved and return BAD_OP with detail the opcode. No firmware memory-management operations exist. (vector: RUL.024.card_refuses; mutant: memory/firmware-refusals-disabled)

## Completions

- **L0.NQ.022** `silicon` A completion entry is 32 bytes: word 0 the tag, word 1 `status [15:0] | detail [31:16] | step [63:32]`, word 2 cycles, word 3 a value. The firmware writes the entry, then the CQ tail (its run record before both, L0.NQ.056); the host reads the tail, then the entries it publishes, then writes the CQ head line. (code: software/firmware/kohakuaccel/queue/service.c:87-101; software/driver/kohakuaccel/driver/node/queue/client.py:297-324; doc: docs/spec/node-queue.md:134-145,232-233; evidence: every card package's completion)
- **L0.NQ.023** `unproven` The firmware never posts into a full CQ: it waits, yielding, until the host's CQ head leaves room. (code: software/firmware/kohakuaccel/queue/service.c:90-92; doc: docs/spec/node-queue.md:232-233)
- **L0.NQ.024** `silicon` A `RUN` completion's step is the failing step's index, or on success the index the step loop ended at (the step count after running off the end); its cycles count node cycles from the start of the run, before the header read, to the result, the quiesce after a failure included. (code: software/firmware/kohakuaccel/package/interp.c:1477,1565-1581; software/firmware/kohakuaccel/queue/service.c:239-242; doc: docs/spec/node-queue.md:139-140; evidence: the card runtime reports every run's cycles from this field (card.py:353,437-440); LOG:84 step 0 and 12,768,463 cycles for the failed package 0x83b, its quiesce included ([debug/firmware.md](../debug/firmware.md) `LOG`, the v9t6 card log))
- **L0.NQ.025** `silicon` A failed `RUN`'s value is the failure's value; a successful one's is the firmware's count of instruction words it dispatched itself (fetch runs and mailbox words it queued or sent), which does not count entries copied from `ENGINE` steps. (code: software/firmware/kohakuaccel/queue/service.c:241-242; software/firmware/kohakuaccel/package/interp.c:736-737,760-761,840-866; doc: docs/spec/node-queue.md:141; evidence: every card completion carried it (service.c:241-242 unchanged since af7c1bb); LOG:89 `sent 0` is that count for a lowered package, LOG:90 the failure's value)
- **L0.NQ.026** `unproven` A `SIGNAL` step posts a `PROGRESS` (0x01) completion: the `RUN`'s tag, detail the signal's 32-bit value truncated to 16 bits, step the `SIGNAL`'s index, cycles the node's cycle counter (not relative to the run), value the signal's 64-bit value; stdout is flushed first. (code: software/firmware/kohakuaccel/queue/service.c:105-110,95; doc: docs/spec/node-queue.md:141,152)
- **L0.NQ.027** `RTL` The host keeps `PROGRESS` completions apart (`NodeQueue.progress`) and waits for each tag's final completion. (code: software/driver/kohakuaccel/driver/node/queue/client.py:318-321,326-339; evidence: software/application/tests/test_l1_examples.py::test_memops (its package signals before it ends, and the run succeeds only if the host waits past the progress completion))
- **L0.NQ.049** `silicon` A final completion that is not `OK` raises `NodeError` carrying the completion and the node's stdout. (code: software/driver/kohakuaccel/driver/node/queue/client.py:62-74,340-341; evidence: LOG:83-90: `NodeError: tag 0x83b: TIMEOUT ...`, then `node said:` and the node's lines)
- **L0.NQ.028** `silicon` Status `0x00` is `OK`. (code: software/firmware/kohakuaccel/include/ka/package/status.h:7; software/driver/kohakuaccel/driver/node/queue/layout.py:49; doc: docs/spec/node-queue.md:151; evidence: every successful card package)
- **L0.NQ.029** `silicon` Status `0x30` is `TIMEOUT` (detail L0.STEP.005). Detail and step are 16 and 32 bits in the completion. (code: software/firmware/kohakuaccel/include/ka/package/status.h:22; software/firmware/kohakuaccel/queue/service.c:95; software/driver/kohakuaccel/driver/node/queue/layout.py:64; doc: docs/spec/node-queue.md:147-172; evidence: LOG:84,90: `TIMEOUT`, `status 30 detail 2 step 0`)
- **L0.NQ.050** `unproven` The other status codes: `0x01 PROGRESS`, `0x10 BAD_MAGIC`, `0x11 BAD_VERSION`, `0x12 BAD_SIGNATURE` (value the node's signature), `0x13 BAD_CHECKSUM` (value the sum computed), `0x14 BAD_STEP`, `0x15 TOO_LARGE`, `0x16 BAD_RELOC`, `0x17 BAD_UNIT`, `0x18 BAD_LAYOUT`, `0x20 UNIT_FAULT` (detail the unit index, value the completion word), `0x21 MBOX_OVERFLOW` (reserved, raised nowhere), `0x22 MOVER_FAULT` (detail the mover's fault code), `0x23 NO_REACH`, `0x40 BAD_OP`, `0x50 NO_MEMORY`, `0x51 NO_SLOTS`, `0x52 BAD_FREE`, `0x53 BAD_ARG`, `0x54 HEAP_BUSY`. (code: software/firmware/kohakuaccel/include/ka/package/status.h:6-29; software/driver/kohakuaccel/driver/node/queue/layout.py:48-73; doc: docs/spec/node-queue.md:147-172)

## stdio

- **L0.NQ.030** `silicon` Everything the firmware prints goes to the stdout ring once the queue service has started: byte `i` at ring offset `(written mod so_bytes)`, stored as whole 8-byte words, then the written count and the lost count are stored. The host reads the bytes between its read count and the written count (at most `so_bytes`), wrapping at the ring's end, and writes its read count line. (code: software/firmware/kohakuaccel/queue/service.c:43-70,202; software/driver/kohakuaccel/driver/node/queue/client.py:428-454; doc: docs/spec/node-queue.md:176-182; evidence: the card runtime read every run's `PKGT` timing line through this ring)
- **L0.NQ.031** `unproven` A full stdout ring holds the firmware for one boot timeout; then the remaining bytes of that write are dropped and added to the lost count. (code: software/firmware/kohakuaccel/queue/service.c:48-58; doc: docs/spec/node-queue.md:180-182)
- **L0.NQ.032** `unproven` stdin: the host writes the bytes into the ring in whole 64-byte lines, then its written count line; the firmware reads one byte at a time from the word holding it and stores its read count. (code: software/driver/kohakuaccel/driver/node/queue/client.py:456-469; software/firmware/kohakuaccel/queue/service.c:72-85; doc: docs/spec/node-queue.md:192-194)
- **L0.NQ.033** `silicon` One host poll reads three lines from the CQ tail, taking the CQ tail at `+0` and the stdout written count at `+0x80`, and reads stdout whenever the written count moved. (code: software/driver/kohakuaccel/driver/node/queue/client.py:297-304; evidence: every card run)

## The package heap

- **L0.NQ.034** `silicon` Past the rings the region is the host's: from the first 64-byte line after the stdin ring (after the run record ring in version 4, L0.NQ.056), a binding array of 64 eight-byte addresses per SQ slot; from the next 4096-byte boundary after those, the package heap to the region's end. The firmware never allocates in it; an entry names its package's address and length. (code: software/driver/kohakuaccel/driver/node/queue/client.py:102-106; doc: docs/spec/node-queue.md:196-200; evidence: every card package was uploaded into this heap)
- **L0.NQ.035** `silicon` `NodeQueue.upload` writes a new package padded to whole 64-byte lines at the heap's top. (code: software/driver/kohakuaccel/driver/node/queue/client.py:212-243; doc: docs/spec/node-queue.md:200-203; evidence: every card package)
- **L0.NQ.051** `unproven` `NodeQueue.upload` refuses (`ValueError`) a package whose length is not a multiple of 32; finds a still-resident package by its SHA-1 digest and does not write it again; final completion removes a package with no remaining submitted references; and, when the heap is full, waits until nothing submitted is outstanding and starts the heap again from its base. (code: software/driver/kohakuaccel/driver/node/queue/client.py:204-211,231-236,415-419; doc: docs/spec/node-queue.md:200-203; evidence: no card log records the upload counters, so neither a digest hit nor a heap restart is known to have happened)
- **L0.NQ.036** `unproven` With a `spill` callback, packages use the shared allocator and remain until the last submitted reference completes. Final completion polling returns the span through `unspill`; progress does not. Runtime allocation pressure collects oldest first. Without `spill`, queue-local spans are reclaimed and coalesced by completion. (code: software/driver/kohakuaccel/driver/node/queue/client.py:215-226,401-413; software/application/kohakutpu/application/runtime/card.py:76-89)
- **L0.NQ.037** `unproven` `submit` waits, polling, while the SQ is full. (code: software/driver/kohakuaccel/driver/node/queue/client.py:261-265)

## Host-only allocation

RUL.024 is the queue contract: opcodes 3..5 are reserved and return `BAD_OP`.
Dispatcher images exclude `os/heap`, and heap statistics are not published.
The fixed 0x340 offset is reserved ABI space. Allocator policy tests of the
standalone `osprobe` do not establish queue support. See
[memory.md](memory.md); vectors `RUL.024.host_contract` and
`RUL.024.card_refuses`.

- **L0.NQ.038** `unproven` Queue opcode 3 is reserved and returns `BAD_OP`; it cannot configure a firmware region heap. Regions are assigned through the boot block. (tier-1 vector: RUL.024.card_refuses)
- **L0.NQ.039** `unproven` Queue opcode 4 is reserved and returns `BAD_OP`; the firmware allocates no DRAM. (tier-1 vector: RUL.024.card_refuses)
- **L0.NQ.040** `unproven` Queue opcode 5 is reserved and returns `BAD_OP`; allocation lifetimes belong to the host. (tier-1 vector: RUL.024.card_refuses)
- **L0.NQ.041** `unproven` Queue offsets 0x340..0x43f are reserved. The firmware publishes no heap statistics there. (code: software/firmware/kohakuaccel/include/ka/queue/layout.h)
- **L0.NQ.042** `unproven` Dispatcher images carry no region-heap bookkeeping and exclude `os/heap` sources. (code: software/firmware/build.py `DISPATCH_EXCLUDE`; tier-0 vector: RUL.024.host_contract)
- **L0.NQ.043** `unproven` The queue client and its daemon proxy expose no heap configuration, allocation, free or heap-statistics methods. The standalone heap policy module is not a queue protocol. (tests: driver/tests/test_node_queue.py, driver/tests/test_daemon_node.py)

## What a host owes

- **L0.NQ.044** `silicon` The host writes the region's header and zeroes its indices before the firmware boots; writes the boot block after the image and before boot; waits for ready before the first submission; writes whole 64-byte lines, the SQ entry before the SQ tail; reads the CQ tail before the entries it publishes and advances the CQ head after; reads a package's results from memory only after its completion. (code: software/application/kohakutpu/application/runtime/card.py:204-230; software/driver/kohakuaccel/driver/node/queue/client.py:134-151,246-324; doc: docs/spec/node-queue.md:226-237; evidence: every card run followed this order)
- **L0.NQ.052** `unproven` The runtime may submit a run while earlier ones are in flight (`NodeCard.submit`, `Device.submit`; `run` is `collect(submit())`): each in-flight run keeps its package, its binding slot and its scratch until its completion is collected, at most `Device.max_inflight` [2] are held (past that the oldest is collected first; under memory pressure, oldest first with a retry after each completion), and each run is given the report text its node printed for it, in submission order: up to the stdout count its run record carries (L0.NQ.056), or, from a region without records, through its PKGT line. Its phases come from its record when it has one. (code: software/application/kohakutpu/application/runtime/card.py (`submit`, `collect`, `_segment`); software/application/kohakutpu/application/runtime/device.py (`submit`, `collect`); evidence: software/application/tests/runtime/test_inflight.py, on no card)

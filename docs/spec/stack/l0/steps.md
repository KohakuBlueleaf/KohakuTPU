# L0 steps

What a sysnode does with each step: the opcodes, their flags, the per-unit counts
and waits, credit, completions, the mover, the interlink signals, the package
registers, raw flits and fetch. The step encoding is [package.md](package.md)
L0.PKG.025; how steps become dispatch-engine entries is
[dispatch-engine.md](dispatch-engine.md).

**Which steps the card ran.** The 2026-10-21 v9t6 packages were L1 kernels
lowered by `Program.build` and `engine.lower`. Their sysnode statements
(counts from the run's statement tally) map to steps as follows
(software/kohakuaccel/compiler/crates/ka-package/src/program.rs,
ktpu-l1/src/lower/node/mod.rs): `send` (8423 in 290
kernels) to `DISPATCH`; `mark` with `wait ... upto=` (7752 each) to `AWAIT`;
`barrier` (163) and every program's end to `AWAIT`s and `BARRIER`; `move` to
`MOVER` then `BARRIER`, `move posted` (119) to `MOVER` with `POSTED`; `wait
moves` to `MWAIT`. The tally does not split `wait` forms: the L2 synchroniser
emits only `wait U upto=M` and `wait moves T`
(ktpu-l2/src/lower/sync.rs), and the 119
`wait` statements without `upto` equal the 119 posted moves. `engine.lower`
turned all of these into `ENGINE` steps, and every unit had a fetch port, so
every `DISPATCH` went out as fetch requests. No card kernel held `fetch`,
`ring`, `wait slot`, `wait bell`, `signal`, `settle`, `store`, `load`, `ctrl`,
an ALU statement, `goto`, `push`, `recv` or `query`. Clauses about those are
RTL where a Verilated-card run exercises them, else unproven.

## Software contract and immediate-address extensions

Firmware ELF `.ka_abi` word 5 advertises package feature bits. Bit 0 denotes
`ASSERT_ZERO`, immediate-address `LOAD`, and runtime-frontier `AWAIT`. Runtimes using these operations
require that capability before submitting packages to the firmware.

`ASSERT_ZERO` (opcode 22) names package register `unit` and a 32-bit contract
code in `count`; flags and argument are zero. Zero continues. Nonzero ends the
package with completion status `CONTRACT` (0x24), detail the contract code,
and value the register. It does not create a hardware unit fault. The producer
must drain and synchronize before loading and checking its status word.

`LOAD` with flags exactly `IMM` (2) reads the low 64 bits of payload `arg`
**without dereferencing them**. The payload can carry an ordinary relocation.
It permits affine descriptor PATCHes to add a runtime offset to a relocated
base rather than embedding an unrelocatable base in an ALU immediate. Literal
payloads are appended after dispatched payloads so PATCH indices stay stable.

## Execution model

- **L0.STEP.001** `unproven` Each package resets its software dispatch state and registers. A held chain preserves and rebases hardware completion counters. The interpreter advances in step order except for taken JUMPs and round-robin grouping of consecutive DISPATCH/REPEAT steps. (code: software/kohakuaccel/firmware/package/interp.c:1003-1048, :1314-1335, :1795-1804, :1845-1878; software/kohakuaccel/firmware/dispatch/engine.c:64-106; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.STEP.002** `unproven` An engine package queues an end barrier. Ordinary completion drains the engine; a chain continuation may instead retain the engine and return with work outstanding. Software per-unit sent counts do not include words issued by a copied ENGINE stream. (code: software/kohakuaccel/firmware/package/interp.c:876-911, :1880-1899; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.STEP.003** `unproven` An opcode the firmware does not know fails the package with `BAD_STEP` (0x14), detail the opcode, value step word 0. An `ENGINE` step on a sysnode that runs the package without a dispatch engine fails the same way. (code: software/kohakuaccel/firmware/package/interp.c:1652-1653; doc: docs/spec/package-format.md:219-220,321-322)
- **L0.STEP.004** `unproven` The package has `fw.package.regs` [16] 64-bit registers, zero at its start, used by `LOAD`, `ALU`, `JUMP`, `PATCH` and the `REG` flag; they do not outlive the package. (code: software/kohakuaccel/firmware/package/interp.c:33, :1802-1804, :1258-1509; doc: docs/spec/package-format.md:360)
- **L0.STEP.005** `unproven` A zero RUN timeout selects the boot timeout. Firmware waits check elapsed cycles; mover waits restart their timeout on progress and engine waits restart when the issue count changes. These are wait or no-progress budgets, not a total package-duration bound. (code: software/kohakuaccel/firmware/package/interp.c:494-518, :644-650, :1795; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.STEP.060** `unproven` A nonzero RUN timeout replaces the boot block's. On the firmware path the `TIMEOUT` detail is what was awaited: 1 credit, 2 `AWAIT`, 3 barrier, 4 mover, 5 doorbell, 6 mailbox offer, 7 signal slot, 8 RX flit, 9 acknowledgement, 10 ring room. (code: software/kohakuaccel/firmware/package/interp.c:1795, :1138-1141; software/kohakuaccel/firmware/include/ka/package/status.h:32-44; doc: docs/spec/node-queue.md:204; evidence: the one logged `TIMEOUT` is engine-mode, detail 2 (L0.DE.019))
- **L0.STEP.006** `unproven` Failures requiring quarantine disable dispatch, report the saved engine snapshot, publish fatal state and exit before ordinary per-unit reporting, quiesce and result finalization. Other failures print production counters or emit debug UNIT records, quiesce, and report the last attempted interpreter step. (code: software/kohakuaccel/firmware/package/interp.c:1077-1102, :1902-1928; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:1565-1581 prints failure counters and quiesces before returning a result.)
- **L0.STEP.077** `unproven` Read-ahead is skipped when failure is already known at the peek point. A drain failure can be detected after lookahead has read the next entry. (code: software/kohakuaccel/firmware/package/interp.c:1880-1896, :939-940; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.STEP.061** `unproven` The firmware keeps the first failure's status, detail and value; a later failure in the same run changes none of them. (code: software/kohakuaccel/firmware/dispatch/engine.c:48-61, :383-399; doc: docs/spec/package-format.md:426-431; evidence: the logged failure is a single one)

## Credit and completions

- **L0.STEP.007** `unproven` Dispatch is credit-gated. Firmware mailbox dispatch checks per-unit in-flight credit; fetch runs use room = min(credit, fetch depth) and wait before issuing a run that would exceed room. Host lowering requests retirement frontier sent + n - room for fetch runs; its WAIT helper can raise the target under F-004. (code: software/kohakuaccel/firmware/package/interp.c:755-795; software/kohakuaccel/firmware/dispatch/engine.c:240-242, :252-323; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:138-152, :207-256)
- **L0.STEP.008** `silicon` With boot `cq_depth` 0 there is no sysnode-wide bound on outstanding completions (the firmware's cap is `0xFFFFFFFF`). (code: software/kohakuaccel/firmware/package/interp.c:1787-1788; doc: docs/spec/package-format.md:233-236; evidence: the card booted with `cq_depth` 0 (card/__init__.py:300-306))
- **L0.STEP.009** `unproven` The mailbox firmware path enforces the package aggregate outstanding cap. Firmware engine dispatch clips each unit credit to the package cap but enforces per-unit credit, not an aggregate cap; host-lowered streams use their package-table credits without the boot cap. (code: software/kohakuaccel/firmware/dispatch/engine.c:98-105, :240-242, :314-323; software/kohakuaccel/firmware/package/interp.c:755-795, :1815-1822; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:198-202; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)
- **L0.STEP.010** `unproven` Completion accounting separates acknowledgements from retirements. An ACK increments only acks and does not decrement inflight. A non-ACK increments retired and decrements inflight when nonzero; a generic fault also records unit failure. (code: software/kohakuaccel/firmware/dispatch/engine.c:144-163, :193-202; evidence: af7c1bb:software/firmware/kohakuaccel/dispatch/engine.c:96-104, :136-142, :296-312 includes ACKs in the received count used by mailbox barriers.)
- **L0.STEP.011** `unproven` The writer initializes ack_reserve to zero and reserve_acks keeps the maximum requested value. The public call dispatcher exposes reserve_acks; firmware reads the header field and when boot cq_depth is nonzero, subtracts it from the cap with a floor of one. (code: software/kohakuaccel/compiler/crates/ka-package/src/build/mod.rs:144, :717-719; software/kohakuaccel/compiler/crates/ka-package/src/calls.rs:521-522; software/kohakuaccel/firmware/package/interp.c:1537, :1815-1822)
- **L0.STEP.012** `unproven` With acknowledgement fencing enabled, the compute endpoint holds completion until its tracked local writes are acknowledged. An error acknowledgement latches a write fault that changes completion to SIG_FAULT. Writes excluded from this tracking are not ordered by that completion. (code: src/kohakuaccel/noc/endpoint/noc_cu_base.v:219-227, :340-346, :368-387; evidence: Code inspection; no qualifying card or named RTL witness established for this complete statement.)

## `DISPATCH` (1)

- **L0.STEP.014** `silicon` `DISPATCH` unit `u`, count `n`, argument `first`: payloads `[first, first + n)` go to unit `u` in order as instructions, each counted as one sent under `u`'s credit. (code: software/kohakuaccel/firmware/package/interp.c:229-258, :798-816; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:207-256; doc: docs/spec/package-format.md:181; evidence: L1 `send`, every card kernel)
- **L0.STEP.015** `silicon` Program.build flushes pending words in half-instruction-depth pieces interleaved across units. A full flush drains all queued units; a unit-specific flush sends only the needed prefix through that unit. (code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:497, :579-641, :911-926)
- **L0.STEP.016** `silicon` Firmware DISPATCH uses a unit fetch port when fetching is enabled, the package has no relocations and NOFETCH is clear; the payload address is the package address with bit 38 cleared plus its payload offset. Host lowering also converts fetch-capable DISPATCH to fetch entries. NOFETCH controls firmware conversion, not fetch requests already encoded in an ENGINE stream. (code: software/kohakuaccel/firmware/package/interp.c:237-241, :806-808, :1821; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:207-246)
- **L0.STEP.017** `unproven` A `DISPATCH` to a unit without a fetch port sends each payload through the dispatch mailbox: `DST` (`y << 8 | x`, written when it changes), `ARG0`-`ARG3`, then `GO` once the previous flit is taken (mailbox `STAT [15]` clear), draining completions when the mailbox's completion queue reaches half of `node.cq_depth` [16]. A wait for credit fails `TIMEOUT` detail 1; a wait for the previous flit, detail 6. (code: software/kohakuaccel/firmware/dispatch/engine.c:252-304; software/kohakuaccel/firmware/include/ka/dispatch/engine.h:65-100)
- **L0.STEP.018** `unproven` A `DISPATCH` whose payloads run past the table fails `BAD_LAYOUT` (0x18), detail `first`, value `n_payload`. (code: software/kohakuaccel/firmware/package/interp.c:234-236, :803-805)
- **L0.STEP.019** `unproven` On the firmware path without the engine and with boot flag `SERIAL` clear, a run of consecutive `DISPATCH` and `REPEAT` steps naming at least two distinct units, none fetching or foreign, goes out round-robin: one word of each unit in turn, each unit's own steps in order, up to 32 units, and the completions are drained after the run. (code: software/kohakuaccel/firmware/package/interp.c:423-488; doc: docs/spec/package-format.md:222-227)

- **L0.STEP.021** `unproven` await_to records a wait frontier event and an await-sent placeholder. CFG frontier lowering rejects a mark undefined on any incoming path, eliminates covered waits, emits a known completion delta when available, and otherwise selects runtime sent or a saved mark frontier, with path specialization attempted where applicable. (code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:516-520, :944; software/kohakuaccel/compiler/crates/ka-package/src/program/frontiers.rs:239-269, :287-304; evidence: af7c1bb:software/compiler/kohakuaccel/compiler/program.py:370-379 records static sent counts and passes a static count to tokenless waits.)
- **L0.STEP.062** `unproven` CFG frontier analysis decides whether a tokenless wait is already covered. An uncovered tokenless wait uses a known completion delta when available and otherwise runtime sent; label occurrence alone does not choose or suppress the wait. (code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:516-520, :944; software/kohakuaccel/compiler/crates/ka-package/src/program/frontiers.rs:239-269, :287-304; evidence: af7c1bb:software/compiler/kohakuaccel/compiler/program.py:370-379 records static sent counts and passes a static count to tokenless waits.)

CFG frontier analysis selects completion deltas, runtime-sent waits or saved mark frontiers and removes covered waits. Label occurrence alone does not determine the encoding. (code: software/kohakuaccel/compiler/crates/ka-package/src/program/frontiers.rs:239-269, :287-304)

(code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:944, :949-954; software/kohakuaccel/compiler/crates/ka-package/src/program/frontiers.rs:239-269; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)

## `MOVER` (4) and `MWAIT` (10)

- **L0.STEP.024** `silicon` `MOVER` count `n`, argument `first`: `n` payloads, each two `(register, value)` pairs (bytes 0-7 register, 8-15 value, 16-23 register, 24-31 value), written in order to the mover's command register at control offset `0x100 + register`. (code: software/kohakuaccel/firmware/package/interp.c:561-585, :835-865; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:315-343; doc: docs/spec/package-format.md:266-275; evidence: L1 `move`, 411 in 292 card kernels)
- **L0.STEP.063** `unproven` A `MOVER` pair whose register is all ones is skipped; the builder pads a move with an odd number of writes with one. (code: software/kohakuaccel/firmware/package/interp.c:569-571, :854-856; software/kohakuaccel/compiler/crates/ka-package/src/build/mod.rs:658-686; evidence: the tally does not count writes per move, so no card move is known to have been padded)
- **L0.STEP.025** `silicon` A write to register `0x00` with bit 16 set is a GO and starts one move; the package counts its GOs from its start. (code: software/kohakuaccel/firmware/package/interp.c:579-581, :687-689; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:330-333; doc: docs/spec/package-format.md:271-272; evidence: as L0.STEP.024)
- **L0.STEP.026** `silicon` A non-POSTED MOVER waits for the package GO frontier before later stream work; in engine mode the interpreter can queue ahead of that wait. POSTED omits this wait. BARRIER and package-end ordering wait for all preceding GOs; MWAIT waits only for its requested absolute frontier. (code: software/kohakuaccel/firmware/package/interp.c:585, :865, :913-921, :1608-1609; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:315-343, :478)
- **L0.STEP.027** `unproven` Firmware engine MWAIT passes its requested absolute mover frontier through de_wait. The mover path clamps a target farther behind the sent frontier than half the counter mask to the oldest representable target, then emits a positive wait using the saved mover-room state. (code: software/kohakuaccel/firmware/package/interp.c:719-735, :1695-1696; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **L0.STEP.064** `unproven` An absolute move count does not belong inside a loop: `Program.build` refuses (`PackageError`) `wait moves` past a label. (code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:897-903)
- **L0.STEP.028** `silicon` `Program.build` writes L1 `move` as `MOVER` then `BARRIER`, `T = move posted` as `MOVER` with `POSTED`, and `wait moves T` as `MWAIT` up to the GOs issued through post `T`. (code: software/kohakuaccel/compiler/crates/ka-package/src/program.rs:879-909; evidence: as L0.STEP.026, L0.STEP.027)
- **L0.STEP.029** `unproven` A mover register at or past `node.mover_span` [0x80], or not 8-byte aligned, fails the package with `NO_REACH` (0x23), detail the register, value its value; `engine.lower` refuses it. (code: software/kohakuaccel/firmware/package/interp.c:572-573, :857-858; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:319-328)
- **L0.STEP.030** `unproven` On the firmware path a mover write waits for room in the mover's configuration queue (`MVSTAT [33]`, then `node.mover_room_writes` [8] writes before it is read again); a mover wait fails `TIMEOUT` detail 4 only after one timeout with no move completing; a mover fault (`MVSTAT [31:28]` nonzero) fails `MOVER_FAULT` (0x22), detail the fault code, value `MVSTAT`. ## `RING` (5), `WAIT_BELL` (6), `WAIT_SLOT` (13)

Fenced, the ring leaves only once this sysnode's mover is idle and its outbound writes and processor stores are on the link. The sysnode writes `(m & 3) | (s & 0xFF) << 8 | amount << 16 | fence << 32` to interlink register `0xD0`. ## `FETCH` (12) and fetch requests

- **L0.STEP.044** `silicon` A fetch run of `n` words for unit `u` at address `a` is one `MEM_RD_REQ` to the port: `DST = 1 << 24 | 0 << 20 | port` (typed, type 0), `ARG0 = ARG1 = 0`, `ARG2 = ((y << 4) | x) << 40 | 1 << 30` (the unit as peer 0), `ARG3 = a << 24 | 0x60 << 8 | n`, then `GO`; the port delivers each word to `u` as an instruction whose source is the sysnode, so `u`'s completions return to the sysnode. (code: software/kohakuaccel/firmware/package/interp.c:771-795; software/kohakuaccel/compiler/crates/ka-package/src/engine.rs:214-235; src/kohakuaccel/sysnode/core/mag_mem_port.v:1273-1282; doc: docs/spec/package-format.md:289-298; evidence: every card dispatch)
- **L0.STEP.045** `silicon` A fetch run carries at most `min(room, 255)` words, `room = min(credit, unit.inst_depth [512])`, and goes out only once all of it fits within `room` in flight; the next run's address is `a + 32 n`.

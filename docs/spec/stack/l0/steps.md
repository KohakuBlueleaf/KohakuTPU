# L0 steps

What a node does with each step: the opcodes, their flags, the per-unit counts
and waits, credit, completions, the mover, the interlink signals, the package
registers, raw flits and fetch. The step encoding is [package.md](package.md)
L0.PKG.025; how steps become dispatch-engine entries is
[dispatch-engine.md](dispatch-engine.md).

**Which steps the card ran.** The 2026-10-21 v9t6 packages were L1 kernels
lowered by `Program.build` and `engine.lower`. Their node statements
(counts from the run's statement tally) map to steps as follows
(ktpu-l0/src/program.rs,
ktpu-l1/src/lower/node/mod.rs): `send` (8423 in 290
kernels) to `DISPATCH`; `mark` with `wait ... upto=` (7752 each) to `AWAIT`;
`barrier` (163) and every program's end to `AWAIT`s and `BARRIER`; `move` to
`MOVER` then `BARRIER`, `move posted` (119) to `MOVER` with `POSTED`; `wait
moves` to `MWAIT`. The tally does not split `wait` forms: the L2 synchroniser
emits only `wait U upto=M` and `wait moves T`
(ktpu-l2/src/lower/sync.rs), and the 119
`wait` statements without `upto` equal the 119 posted moves. `engine.lower`
turned all of these into `ENGINE` steps, and every unit had a fetch port, so
every `DISPATCH` went out as fetch requests. No card kernel held `fetch`,
`ring`, `wait slot`, `wait bell`, `signal`, `settle`, `store`, `load`, `ctrl`,
an ALU statement, `goto`, `push`, `recv` or `query`. Clauses about those are
RTL where a named Verilated-card test in
`software/application/tests/test_l1_examples.py` runs them (board
`multimesh_v9` by default, which also has a fetch port), else unproven.

## Software contract and immediate-address extensions

Firmware ELF `.ka_abi` word 5 advertises package feature bits. Bit 0 denotes
`ASSERT_ZERO`, immediate-address `LOAD`, and runtime-frontier `AWAIT`. Runtimes using these operations
require that capability before submitting packages to the firmware.

`ASSERT_ZERO` (opcode 22) names package register `unit` and a 32-bit contract
code in `count`; flags and argument are zero. Zero continues. Nonzero ends the
package with completion status `CONTRACT` (0x24), detail the contract code,
and value the register. It does not create a hardware unit fault. The producer
must drain and synchronize before loading and checking its status word.

`LOAD` with flags exactly `IMM` (2) reads the low 64 bits of payload `arg`
**without dereferencing them**. The payload can carry an ordinary relocation.
It permits affine descriptor PATCHes to add a runtime offset to a relocated
base rather than embedding an unrelocatable base in an ALU immediate. Literal
payloads are appended after dispatched payloads so PATCH indices stay stable.

## Execution model

- **L0.STEP.001** `silicon` Steps run in list order from step 0, except where a `JUMP` is taken. For each unit the node keeps the instructions sent, in flight (sent and not retired), completions received and completions expected; every count, and every package register, is zero at the package's start. (code: software/firmware/kohakuaccel/package/interp.c:1490-1498,1534-1555; software/firmware/kohakuaccel/dispatch/engine.c:22-40,62; doc: docs/spec/package-format.md:173-175; evidence: every card package)
- **L0.STEP.002** `silicon` Reaching the end of the step list is a `BARRIER`: the package completes only once every unit has retired everything sent to it, every `AWAIT` holds and every move the package started is done. (code: software/firmware/kohakuaccel/package/interp.c:1556-1563; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:218; evidence: every card package ended so)
- **L0.STEP.003** `unproven` An opcode the firmware does not know fails the package with `BAD_STEP` (0x14), detail the opcode, value step word 0. An `ENGINE` step on a node that runs the package without a dispatch engine fails the same way. (code: software/firmware/kohakuaccel/package/interp.c:1415-1416; doc: docs/spec/package-format.md:218-219,320-321)
- **L0.STEP.004** `RTL` The package has `fw.package.regs` [16] 64-bit registers, zero at its start, used by `LOAD`, `ALU`, `JUMP`, `PATCH` and the `REG` flag; they do not outlive the package. (code: software/firmware/kohakuaccel/include/ka/package/format.h:63-65; software/firmware/kohakuaccel/package/interp.c:36,1496-1498; doc: docs/spec/package-format.md:359; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory)
- **L0.STEP.005** `silicon` With the RUN entry's timeout 0, every wait is bounded by the boot block's timeout in node cycles; a wait that exceeds it fails the package with `TIMEOUT` (0x30). (code: software/firmware/kohakuaccel/package/interp.c:1490; software/firmware/kohakuaccel/include/ka/package/status.h:22; doc: docs/spec/node-queue.md:166; evidence: LOG:84,90 ([debug/firmware.md](../debug/firmware.md) `LOG`, the v9t6 card log): package 0x83b failed `TIMEOUT` under the boot block's bound, RUN timeout 0)
- **L0.STEP.060** `unproven` A nonzero RUN timeout replaces the boot block's. On the firmware path the `TIMEOUT` detail is what was awaited: 1 credit, 2 `AWAIT`, 3 barrier, 4 mover, 5 doorbell, 6 mailbox offer, 7 signal slot, 8 RX flit, 9 acknowledgement, 10 ring room. (code: software/firmware/kohakuaccel/package/interp.c:983-987,1490; software/firmware/kohakuaccel/include/ka/package/status.h:32-43; doc: docs/spec/node-queue.md:166; evidence: the one logged `TIMEOUT` is engine-mode, detail 2 (L0.DE.019))
- **L0.STEP.006** `silicon` A failing package stops at the failing step: the firmware prints each unit's counts (`PKGF` lines), lets what is in flight retire (bounded by the timeout), pops every completion the mailbox still holds, and reports the failing step's index. (code: software/firmware/kohakuaccel/package/interp.c:1565-1575; software/firmware/kohakuaccel/dispatch/engine.c:315-331; doc: docs/spec/package-format.md:425-430; evidence: LOG:84-89: step 0, the `PKGF` lines, and a `barrier` phase of 2,025,680 cycles, the quiesce running out one bound with 7829 outstanding)
- **L0.STEP.077** `unproven` A failing package reads nothing ahead (L0.NQ.053): the entry after it is read in its turn. (code: software/firmware/kohakuaccel/package/interp.c (`ka_package_run`); evidence: software/driver/tests/test_exec_list.py on the firmware double)
- **L0.STEP.061** `unproven` The firmware keeps the first failure's status, detail and value; a later failure in the same run changes none of them. (code: software/firmware/kohakuaccel/dispatch/engine.c:12-20; doc: docs/spec/package-format.md:425-430; evidence: the logged failure is a single one)

## Credit and completions

- **L0.STEP.007** `silicon` An instruction word goes to unit `u` only while `u` holds fewer than its credit in flight. In a lowered package this is a `WAIT` on `u`'s retirement counter for `sent + n - credit` before the words that would exceed it. (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/dispatch/engine.c:182-185,253; doc: docs/spec/package-format.md:228-237; evidence: every card package's fetch runs were credit-bounded so)
- **L0.STEP.008** `silicon` With boot `cq_depth` 0 there is no node-wide bound on outstanding completions (the firmware's cap is `0xFFFFFFFF`). (code: software/firmware/kohakuaccel/package/interp.c:1479-1480; software/driver/kohakuaccel/driver/node/boot/args.py:38; doc: docs/spec/package-format.md:233-236; evidence: the card booted with `cq_depth` 0 (card.py:219-221))
- **L0.STEP.009** `unproven` With boot `cq_depth` nonzero the node keeps at most `cq_depth - ack_reserve` completions outstanding (at least 1), and every unit's credit is at most that. (code: software/firmware/kohakuaccel/package/interp.c:1505-1507; software/firmware/kohakuaccel/dispatch/engine.c:58-61; doc: docs/spec/package-format.md:233-237,248-253)
- **L0.STEP.010** `unproven` On the firmware path each completion is read by the unit's class; the generic reading is: `SIG_FAULT` (4) fails the package with `UNIT_FAULT` (0x20), detail the unit's index, value the completion word; `SIG_DATA_RECEIVED` (3) is an acknowledgement, counted as received and retiring nothing; every other code is received and retires one instruction in flight. A completion from a coordinate not in the unit table is counted as a stray; a fault from one fails the package with detail `0xFFFF`. (code: software/firmware/kohakuaccel/dispatch/engine.c:86-151; software/firmware/kohakuaccel/unit/registry.c:8-18; doc: docs/spec/package-format.md:239-246)
- **L0.STEP.011** `unproven` `ack_reserve` (header word 4) is the most acknowledgements any round awaits beyond the words it dispatched; the writer keeps the maximum asked by `reserve_acks`, and no stack path asks. (code: ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:248-253)
- **L0.STEP.012** `unproven` A compute unit sends its completion only once every memory write it issued is acknowledged, so a `BARRIER` orders a round that writes before a round, or a host, that reads; a write the memory port refuses returns its unit's completion as `SIG_FAULT`. (doc: docs/spec/package-format.md:255-263; evidence: no test observes the ordering)

## `END` (0)

- **L0.STEP.013** `unproven` `END` stops reading steps; the end's barrier follows, and a successful completion reports the step index after the `END`. No stack path writes `END`. (code: software/firmware/kohakuaccel/package/interp.c:1357-1359,1534-1555,1579; ktpu-l0/src/engine.rs)

## `DISPATCH` (1)

- **L0.STEP.014** `silicon` `DISPATCH` unit `u`, count `n`, argument `first`: payloads `[first, first + n)` go to unit `u` in order as instructions, each counted as one sent under `u`'s credit. (code: ktpu-l0/src/build/mod.rs; ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:243-273,768-784; doc: docs/spec/package-format.md:180; evidence: L1 `send`, every card kernel)
- **L0.STEP.015** `silicon` `Program.build` sends each unit's queued words at every synchronisation point, cut into pieces of `unit.inst_depth / 2` [256] words and interleaved across units piece by piece. (code: ktpu-l0/src/program.rs; evidence: every card kernel's dispatches)
- **L0.STEP.016** `silicon` A `DISPATCH` to a unit with a fetch port, in a package with no relocations and with boot flag `NOFETCH` clear, is not sent word by word: the unit's port streams the payloads out of the package in memory as fetch requests (L0.STEP.044-L0.STEP.046), the payload address being the package's address with bit 38 cleared plus the payload's offset. (code: software/firmware/kohakuaccel/package/interp.c:248-253,773-776; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:288-300; evidence: every card dispatch (v9t6 `fetch_port` (0, 2)))
- **L0.STEP.017** `unproven` A `DISPATCH` to a unit without a fetch port sends each payload through the dispatch mailbox: `DST` (`y << 8 | x`, written when it changes), `ARG0`-`ARG3`, then `GO` once the previous flit is taken (mailbox `STAT [15]` clear), draining completions when the mailbox's completion queue reaches half of `node.cq_depth` [16]. A wait for credit fails `TIMEOUT` detail 1; a wait for the previous flit, detail 6. (code: software/firmware/kohakuaccel/include/ka/dispatch/engine.h:62-91; software/firmware/kohakuaccel/dispatch/engine.c:194-241; ktpu-l0/src/engine.rs)
- **L0.STEP.018** `unproven` A `DISPATCH` whose payloads run past the table fails `BAD_LAYOUT` (0x18), detail `first`, value `n_payload`. (code: software/firmware/kohakuaccel/package/interp.c:245-247,770-772)
- **L0.STEP.019** `unproven` On the firmware path without the engine and with boot flag `SERIAL` clear, a run of consecutive `DISPATCH` and `REPEAT` steps naming at least two distinct units, none fetching or foreign, goes out round-robin: one word of each unit in turn, each unit's own steps in order, up to 32 units, and the completions are drained after the run. (code: software/firmware/kohakuaccel/package/interp.c:470-542,1530,1538; doc: docs/spec/package-format.md:221-226)

## `AWAIT` (2)

- **L0.STEP.020** `silicon` `AWAIT` unit `u`, count `n`: `u`'s expected count rises by `n`, and the node holds until `u`'s received count reaches it. Counts are cumulative over the package, so an `AWAIT` is an increment. (code: software/firmware/kohakuaccel/dispatch/engine.c:287-294; software/firmware/kohakuaccel/package/interp.c:1370-1371,1442-1444; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:181,366-367; evidence: L1 `wait U upto=M`, 7752 in the card kernels)
- **L0.STEP.021** `silicon` `Program.build` writes, for `wait U upto=M`, an `AWAIT` raising `U`'s expected count to the words sent to `U` before mark `M`; it writes none when the count already holds. (code: ktpu-l0/src/program.rs; evidence: as L0.STEP.020)
- **L0.STEP.062** `RTL` `Program.build` writes, for `wait U`, an `AWAIT` raising `U`'s expected count to every word sent to `U` so far. (code: ktpu-l0/src/program.rs; evidence: software/application/tests/test_l1_examples.py::test_push_and_recv (`wait vc[0]`), ::test_ring_slot_and_bell; no card kernel holds `wait U` without `upto`)

After a node label, the builder uses `AWAIT` with `IMM` (2), count and argument
zero, to wait for that unit's current runtime sent frontier. Static source-order
totals are not execution totals across a backedge. The firmware sets that unit's
expected frontier to its runtime sent count; other units are not awaited.
Before overwriting a patched dispatch body, the previous traversal on its unit
is retired. This preserves unit-specific dependencies across counter wrap.

## `BARRIER` (3)

- **L0.STEP.022** `silicon` `BARRIER` holds until nothing is in flight on any unit, every unit's received count reaches its expected count, and every move the package started is done. (code: software/firmware/kohakuaccel/package/interp.c:1372-1373,870-879; software/firmware/kohakuaccel/dispatch/engine.c:296-313; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:182; evidence: L1 `barrier` (163) and every program's end)
- **L0.STEP.023** `silicon` `Program.build` writes for `barrier` an `AWAIT` per unit up to everything sent, then a `BARRIER`; the builder never writes a `BARRIER` right after another. (code: ktpu-l0/src/program.rs; ktpu-l0/src/build/mod.rs; evidence: as L0.STEP.022)

## `MOVER` (4) and `MWAIT` (10)

- **L0.STEP.024** `silicon` `MOVER` count `n`, argument `first`: `n` payloads, each two `(register, value)` pairs (bytes 0-7 register, 8-15 value, 16-23 register, 24-31 value), written in order to the mover's command register at control offset `0x100 + register`. (code: software/firmware/kohakuaccel/package/interp.c:614-639,802-836; ktpu-l0/src/engine.rs; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:265-274; evidence: L1 `move`, 411 in 292 card kernels)
- **L0.STEP.063** `unproven` A `MOVER` pair whose register is all ones is skipped; the builder pads a move with an odd number of writes with one. (code: ktpu-l0/src/build/mod.rs; ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:622-624,821-823; evidence: the tally does not count writes per move, so no card move is known to have been padded)
- **L0.STEP.025** `silicon` A write to register `0x00` with bit 16 set is a GO and starts one move; the package counts its GOs from its start. (code: software/firmware/kohakuaccel/package/interp.c:632-635,830-832; ktpu-l0/src/engine.rs; ktpu-l0/src/program.rs; doc: docs/spec/package-format.md:270-271; evidence: as L0.STEP.024)
- **L0.STEP.026** `silicon` A `MOVER` without `POSTED` holds until every move the package has started is done; with `POSTED` the node goes on, and an `MWAIT`, a `BARRIER` or the end waits for those moves. (code: software/firmware/kohakuaccel/package/interp.c:638,835; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:183,206; evidence: blocking `move` (292) and `move posted` (119) in the card kernels)
- **L0.STEP.027** `silicon` `MWAIT` count `n` holds until `n` of the package's moves, counted from its start, are done. The count is absolute. (code: software/firmware/kohakuaccel/package/interp.c:1376-1377,1449-1450; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:189,367-368; evidence: L1 `wait moves`, 119 in the card kernels)
- **L0.STEP.064** `unproven` An absolute move count does not belong inside a loop: `Program.build` refuses (`PackageError`) `wait moves` past a label. (code: ktpu-l0/src/program.rs)
- **L0.STEP.028** `silicon` `Program.build` writes L1 `move` as `MOVER` then `BARRIER`, `T = move posted` as `MOVER` with `POSTED`, and `wait moves T` as `MWAIT` up to the GOs issued through post `T`. (code: ktpu-l0/src/program.rs; evidence: as L0.STEP.026, L0.STEP.027)
- **L0.STEP.029** `unproven` A mover register at or past `node.mover_span` [0x80], or not 8-byte aligned, fails the package with `NO_REACH` (0x23), detail the register, value its value; `engine.lower` refuses it. (code: software/firmware/kohakuaccel/package/interp.c:625-627,824-826; ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/include/ka/hal/node.h:29)
- **L0.STEP.030** `unproven` On the firmware path a mover write waits for room in the mover's configuration queue (`MVSTAT [33]`, then `node.mover_room_writes` [8] writes before it is read again); a mover wait fails `TIMEOUT` detail 4 only after one timeout with no move completing; a mover fault (`MVSTAT [31:28]` nonzero) fails `MOVER_FAULT` (0x22), detail the fault code, value `MVSTAT`. (code: software/firmware/kohakuaccel/package/interp.c:544-608; software/firmware/kohakuaccel/include/ka/hal/node.h:91-96)

## `RING` (5), `WAIT_BELL` (6), `WAIT_SLOT` (13)

- **L0.STEP.031** `RTL` `RING` mesh `m` (unit field), slot `s` (count), argument `amount [15:0] | fence [16]`: mesh `m`'s signal slot `s` gains the amount (0 counts 1) and its doorbell count from this mesh rises by one. Fenced, the ring leaves only once this node's mover is idle and its outbound writes and processor stores are on the link. The node writes `(m & 3) | (s & 0xFF) << 8 | amount << 16 | fence << 32` to interlink register `0xD0`. (code: software/firmware/kohakuaccel/package/interp.c:1008-1009,1451-1453; ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/include/ka/hal/node.h:37; doc: docs/spec/package-format.md:184; evidence: software/application/tests/test_l1_examples.py::test_ring_slot_and_bell, ::test_remote_store (two-node Verilated card))
- **L0.STEP.032** `unproven` On the firmware path the node keeps at most `node.ring_depth` [4] of its own rings queued in the interlink (a fifth would be dropped): it waits until fewer are queued, failing `TIMEOUT` detail 10, value the interlink's sent count. (code: software/firmware/kohakuaccel/package/interp.c:980-1012; software/firmware/kohakuaccel/include/ka/hal/node.h:41-46)
- **L0.STEP.033** `unproven` The builder refuses a ring slot outside 0-255 or an amount outside 1-65535; the mesh field carries `il.meshes` [4] meshes. (code: ktpu-l0/src/build/mod.rs; software/firmware/kohakuaccel/package/interp.c:1008)
- **L0.STEP.034** `RTL` `WAIT_BELL` mesh `m`, count `n`: holds until `n` doorbells from mesh `m` have arrived that no earlier `WAIT_BELL` consumed, then consumes them. The counts are the interlink's 16-bit per-mesh counts taken from the firmware's start. (code: software/firmware/kohakuaccel/package/interp.c:950-973; software/firmware/kohakuaccel/queue/service.c:204; doc: docs/spec/package-format.md:185; evidence: software/application/tests/test_l1_examples.py::test_ring_slot_and_bell)
- **L0.STEP.065** `unproven` A ring that lands before the waiting package begins is found; a `WAIT_BELL` timeout fails `TIMEOUT` detail 5, value the doorbell counts. (code: software/firmware/kohakuaccel/package/interp.c:950-973; software/firmware/kohakuaccel/queue/service.c:204; evidence: test_ring_slot_and_bell does not order node 0's ring before node 1's package, and no test times out)
- **L0.STEP.035** `RTL` `WAIT_SLOT` slot `s`, count `n`: selects slot `s`, holds until the interlink reports slot `s` holding at least `n`, and with flag `CONSUME` subtracts `n` from it. A slot only grows unless consumed. The node has `il.slots` [16] slots. (code: software/firmware/kohakuaccel/package/interp.c:1014-1037; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:192,337-345; evidence: software/application/tests/test_l1_examples.py::test_ring_slot_and_bell, ::test_remote_store)
- **L0.STEP.066** `unproven` `WAIT_SLOT` with `s >= 16` fails `BAD_STEP`, detail 13, value `s`; a timeout fails `TIMEOUT` detail 7, value the signal word. (code: software/firmware/kohakuaccel/package/interp.c:1018-1026)
- **L0.STEP.036** `unproven` A select or a consume lands two interlink registers deep, so the firmware reads the signal word twice after each before trusting it. (code: software/firmware/kohakuaccel/package/interp.c:1014-1035)

## `REPEAT` (9)

- **L0.STEP.039** `unproven` `REPEAT` unit `u`, count `n`, argument `first [31:0] | repeats [47:32] | increments [63:48]`: payloads `[first, first + n)` are the template; the increments follow it, two per payload, each `index [31:0] | bit [39:32] | width [47:40]` in its half's first 64 bits and the delta in its second. Repetition `r` (0 to `repeats - 1`) sends every template word, word `index` with its field `[bit, bit + width)` plus `r × delta` modulo 2^width, each as `DISPATCH` would. (code: ktpu-l0/src/build/mod.rs; software/firmware/kohakuaccel/package/interp.c:322-458; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:188,276-286)
- **L0.STEP.040** `unproven` The firmware fails a `REPEAT` whose template and increments run past the payload table with `BAD_LAYOUT`, and one with an increment whose index is past the template or below the previous one, whose width is 0 or above 64, or whose field passes bit 256 with `BAD_STEP`, detail the increment's number, value its first word. (code: software/firmware/kohakuaccel/package/interp.c:339-363,428-431)
- **L0.STEP.041** `unproven` The writer refuses an empty template, `repeats` outside 1-65535, more than 65535 increments, a field outside the word, a negative delta, and a delta that wraps the field within the repetitions. (code: ktpu-l0/src/build/mod.rs)
- **L0.STEP.042** `unproven` The firmware sends a `REPEAT` word by word, never through a fetch port; `engine.lower` writes the repetitions out as new payloads and sends them as a `DISPATCH`. No stack path writes `REPEAT`: `Program.build` uses `dispatch`, and `dispatch_periodic` has no caller. (code: software/firmware/kohakuaccel/package/interp.c:444-458; ktpu-l0/src/engine.rs; ktpu-l0/src/build/mod.rs; ktpu-l0/src/program.rs; doc: docs/spec/package-format.md:299-300)

(code: software/firmware/kohakuaccel/package/interp.c:838-866,1454-1455; ktpu-l0/src/engine.rs; doc: docs/spec/package-format.md:190,315-321; evidence: every card package's steps were `ENGINE` steps)

## `FETCH` (12) and fetch requests

- **L0.STEP.044** `silicon` A fetch run of `n` words for unit `u` at address `a` is one `MEM_RD_REQ` to the port: `DST = 1 << 24 | 0 << 20 | port` (typed, type 0), `ARG0 = ARG1 = 0`, `ARG2 = ((y << 4) | x) << 40 | 1 << 30` (the unit as peer 0), `ARG3 = a << 24 | 0x60 << 8 | n`, then `GO`; the port delivers each word to `u` as an instruction whose source is the node, so `u`'s completions return to the node. (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:741-766; software/firmware/kohakuaccel/dispatch/engine.c:243-280; doc: docs/spec/package-format.md:288-297; evidence: every card dispatch)
- **L0.STEP.045** `silicon` A fetch run carries at most `min(room, 255)` words, `room = min(credit, unit.inst_depth [512])`, and goes out only once all of it fits within `room` in flight; the next run's address is `a + 32 n`. (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:227-237,747-763; software/firmware/kohakuaccel/dispatch/engine.c:251-260; doc: docs/spec/package-format.md:191,297-299; evidence: every card dispatch)
- **L0.STEP.046** `unproven` `FETCH` unit `u`, count `n`, argument an absolute address: `u`'s fetch port reads `n` words from the address in fetch runs (L0.STEP.044, L0.STEP.045), counted as sent to `u`. A unit without a fetch port fails `BAD_STEP`, detail 12, value the unit; a unit index past the table fails `BAD_UNIT`. `Program.build` writes L1 `fetch` after the unit's queued words, and a patched address lands in step bits `[127:64]`. (code: software/firmware/kohakuaccel/package/interp.c:221-238,1378-1385,1456-1457; ktpu-l0/src/build/mod.rs; ktpu-l0/src/program.rs; doc: docs/spec/package-format.md:191)

## `STORE` (14), `LOAD` (15), `CTRL` (21)

- **L0.STEP.047** `RTL` `STORE` count `n`, argument `first`: `n` payloads of two `(address, value)` pairs each, laid out as `MOVER`'s; a pair whose address is all ones is skipped. Each pair is a 64-bit store through the processor's uncached path, completed before the next, in order. With flag `REG` the value is package register `value & 15`. (code: software/firmware/kohakuaccel/package/interp.c:1046-1081; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:193,208,347-355; evidence: software/application/tests/test_l1_examples.py::test_memops, ::test_loop_runs_a_count_from_memory (`REG`))
- **L0.STEP.067** `unproven` A `STORE` address not 8-byte aligned fails `BAD_STEP`, detail 14, value the address. (code: software/firmware/kohakuaccel/package/interp.c:1046-1081)
- **L0.STEP.048** `RTL` A `STORE` to an address naming another mesh in `[37:36]` is a posted remote write over the interlink, landing by the remote-write rule (staging by its full address); a fenced `RING` after it is its release. (doc: docs/spec/package-format.md:349-353; evidence: software/application/tests/test_l1_examples.py::test_remote_store)
- **L0.STEP.049** `RTL` `LOAD` register `rd`, argument a payload: the address is the payload's `[63:0]`. With flag `CTRL` an 8-byte-aligned offset below `node.ctrl_bytes` [0x400] reads that control register; without it an 8-byte-aligned address is read through the uncached path. (code: software/firmware/kohakuaccel/package/interp.c:1083-1105; software/firmware/kohakuaccel/include/ka/hal/node.h:31; doc: docs/spec/package-format.md:194,359-361; evidence: software/application/tests/test_l1_examples.py::test_memops (both forms), ::test_loop_runs_a_count_from_memory)
- **L0.STEP.068** `unproven` With flag `INDEXED` the `LOAD` address adds register `i [3:0]` (the count field). Any other address fails `NO_REACH`, detail 15, value the address; `rd >= 16` fails `BAD_STEP`, detail 15. (code: software/firmware/kohakuaccel/package/interp.c:1083-1105; evidence: no test L1 program loads with an index)
- **L0.STEP.050** `RTL` `CTRL` count `n`, argument `first`: `(offset, value)` pairs laid out as `STORE`'s, each a control-region write; offset `0x1D0` (transform bank select) is writable. (code: software/firmware/kohakuaccel/package/interp.c:1039-1081; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:200,400-407; evidence: software/application/tests/test_l1_examples.py::test_memops (`ctrl xf_sel`, read back through `xf_data`))
- **L0.STEP.069** `unproven` The other writable `CTRL` offsets are `0x38` (host interrupt), the interlink window `0xC0`-`0xF8` (8-byte aligned), `0x1C8` (D-cache, run and waited until done) and `0x1D8` (transform bank data); any other fails `NO_REACH`, detail the offset, value the value. `REG` works as in `STORE`. (code: software/firmware/kohakuaccel/package/interp.c:1039-1081; doc: docs/spec/package-format.md:200,400-407; evidence: test_memops writes `0x1D0` only)

## `ALU` (16), `JUMP` (17), `PATCH` (18)

- **L0.STEP.051** `RTL` `ALU` register `rd`, count `op [7:0] | ra [11:8] | rb [15:12]`: `rd := ra op b`, `b` the argument with flag `IMM`. Ops 0 `MOV` (`b`), 1 `ADD`, 3 `MUL` (modulo 2^64). (code: software/firmware/kohakuaccel/package/interp.c:1107-1132; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:195,361-364; evidence: software/application/tests/test_l1_examples.py::test_memops (`ADD`), ::test_loop_runs_a_count_from_memory (`MOV`, `MUL`, `ADD`), ::test_tiles_from_a_count_in_memory (`MUL`, `ADD`), all with `IMM`)
- **L0.STEP.070** `unproven` Without flag `IMM`, `b` is register `rb`. Ops 2 `SUB`, 4 `AND`, 5 `OR`, 6 `XOR`, 7 `SHL`, 8 `SHR` (logical, by `b & 63`), 9 `MIN`, 10 `MAX` (unsigned), 11 `DIVU` (by zero: all ones), 12 `REMU` (by zero: `ra`). Another op fails `BAD_STEP`, detail 16, value the count; `rd >= 16` fails `BAD_STEP`, detail 16, value `rd`. (code: software/firmware/kohakuaccel/package/interp.c:1107-1132; ktpu-verify/src/sim/node.rs; doc: docs/spec/package-format.md:195,361-364)
- **L0.STEP.052** `RTL` `JUMP` target step `t` (unit field), count `cond [7:0] | ra [11:8] | rb [15:12]`: when `ra cond b` holds the next step is `t`. Condition 3 is `LTU`. (code: software/firmware/kohakuaccel/package/interp.c:1134-1156; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:196,364-366; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory, ::test_tiles_from_a_count_in_memory (`goto top if r2 < r1`, register `b`, taken and not taken))
- **L0.STEP.071** `unproven` `JUMP` conditions 0 always, 1 `EQ`, 2 `NE`, 4 `GEU`, 5 `LT`, 6 `GE` (5 and 6 signed), and an immediate `b` with flag `IMM`. `t = n_step` ends the package; `t > n_step` fails `BAD_STEP`, detail 17, value `t`, taken or not; another condition fails `BAD_STEP`, detail 17. (code: software/firmware/kohakuaccel/package/interp.c:1134-1156; doc: docs/spec/package-format.md:196,364-366)
- **L0.STEP.053** `RTL` `PATCH` register `r`, count a word index, argument `bit [7:0] | width [15:8] | shift [23:16] | steps [24] | add [26]`: with `steps` 0 and `add` 0, bits `[bit, bit + width)` of that payload become `r >> shift` modulo 2^width. The node writes the word in the package in memory, which a fetch port reads. (code: software/firmware/kohakuaccel/package/interp.c:1158-1198; ktpu-l0/src/format/mod.rs; doc: docs/spec/package-format.md:197,370-378; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory (mover payloads), ::test_tiles_from_a_count_in_memory (fetched `MG` payloads))
- **L0.STEP.072** `unproven` `PATCH` with `steps` 1 patches a step; with `add` the field becomes `r >> shift` plus its old value. The node also writes its scratchpad copy of a local package and flushes the D-cache when the package is cached. `r >= 16`, width 0 or above 64, shift above 63, `bit + width` above 256 (payload) or 128 (step), or an index past its table fails `BAD_STEP`, detail 18, value the argument. (code: software/firmware/kohakuaccel/package/interp.c:1158-1198; doc: docs/spec/package-format.md:197,370-378; evidence: no test patches a step or adds, and every test package sits uncached in staging)
- **L0.STEP.054** `RTL` `Program.build` computes a field patch `(register + const) >> shift` through register 15, which a program never names (it uses r0-r14), and before re-patching a unit's words inside a loop waits for that unit to retire everything sent to it. (code: ktpu-l0/src/program.rs; doc: docs/spec/package-format.md:380-382; evidence: software/application/tests/test_l1_examples.py::test_tiles_from_a_count_in_memory)

## `SEND` (19) and `RECV` (20)

- **L0.STEP.055** `RTL` `SEND` unit `u`, count `n`, argument `first [31:0] | type [35:32]`: `n` flits of that type to `u` through the mailbox, `DST = 1 << 24 | type << 20 | y << 8 | x`, outside credit and completion counts. Without flag `MEM` they are payloads `[first, first + n)`; with `MEM` payload `first` is a `CU_DATA` descriptor and `n` 32-byte words follow, loaded uncached from the address in payload `first + 1 [63:0]` at 32-byte steps. Each `GO` waits for the previous flit to be taken (draining completions; `TIMEOUT` detail 6). With flag `ACK` the step then holds until `u`'s acknowledgement count rises. (code: software/firmware/kohakuaccel/package/interp.c:1200-1259; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:198,212-213,384-392; evidence: software/application/tests/test_l1_examples.py::test_memops (`query`: a `CU_CTRL` `SEND`), ::test_push_and_recv (`MEM`, `ACK`))
- **L0.STEP.073** `unproven` A `SEND` naming a unit index past the table or a foreign unit fails `BAD_UNIT`; a wait for the previous flit fails `TIMEOUT` detail 6; an `ACK` wait fails `TIMEOUT` detail 9, value `u`. (code: software/firmware/kohakuaccel/package/interp.c:1200-1259)
- **L0.STEP.056** `RTL` `RECV` unit `u` (named), count `n`, argument a payload: for each of `n` flits the node waits for one in its RX queue (draining completions), writes its four payload words at `address + 32 k` (the payload's `[63:0]`) through the uncached path, and pops it. (code: software/firmware/kohakuaccel/package/interp.c:1261-1286; ktpu-l0/src/build/mod.rs; doc: docs/spec/package-format.md:199,394-398; evidence: software/application/tests/test_l1_examples.py::test_push_and_recv, ::test_a_drain_into_the_node, ::test_memops (each `RECV` names its unit))
- **L0.STEP.074** `unproven` `RECV` unit `0xFFFF` takes flits from any source. With `u` named, a flit whose source `x [23:20]`, `y [19:16]` is not `u`'s fails `BAD_UNIT`, detail `u`, value the flit header; a wait for a flit fails `TIMEOUT` detail 8, value the flit's number. (code: software/firmware/kohakuaccel/package/interp.c:1261-1286; evidence: no test `recv` omits `from=`, and none receives a stray flit or times out)
- **L0.STEP.057** `unproven` The node's RX queue holds `node.rx_depth` [8] flits and holds the node's inbound link while full. (doc: docs/spec/package-format.md:397-398)

## Steps under the dispatch engine

- **L0.STEP.058** `RTL` `engine.lower` keeps every step it cannot carry as a step (everything except `DISPATCH`, `REPEAT`, `AWAIT`, `BARRIER`, `MOVER`, `MWAIT`, `FETCH`, `RING`, `END`), closing the `ENGINE` step before it. In engine mode the firmware lets the engine's queue drain before running such a step, so it acts after everything queued before it; an `ALU` step is the exception and runs at once (L0.STEP.059). (code: ktpu-l0/src/engine.rs; software/firmware/kohakuaccel/package/interp.c:1458-1471; doc: docs/spec/package-format.md:310-311,332-335; evidence: software/application/tests/test_l1_examples.py::test_memops, ::test_push_and_recv)
- **L0.STEP.075** `unproven` `engine.lower` stops at `END` and refuses (`PackageError`) a package already holding an `ENGINE` step. (code: ktpu-l0/src/engine.rs; evidence: no stack path writes `END`, and the runtime lowers each package once)
- **L0.STEP.059** `RTL` In engine mode, for a package not lowered (it jumps or patches), the firmware queues `DISPATCH`, `AWAIT`, `BARRIER` and `MOVER` as engine entries from counts it keeps itself; `ALU`, `JUMP` and `PATCH` run at once without waiting for the engine; every other step waits for the engine to drain. (code: software/firmware/kohakuaccel/package/interp.c:1420-1473; doc: docs/spec/package-format.md:329-335; evidence: software/application/tests/test_l1_examples.py::test_loop_runs_a_count_from_memory (`MOVER`, `BARRIER`, `LOAD`, `STORE`), ::test_tiles_from_a_count_in_memory (`DISPATCH`, `AWAIT`))
- **L0.STEP.076** `unproven` In the same mode `REPEAT`, `MWAIT`, `RING` and `FETCH` are queued as engine entries the same way. (code: software/firmware/kohakuaccel/package/interp.c:1440-1457; evidence: no test package that jumps or patches holds them)

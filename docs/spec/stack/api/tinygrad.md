# TG: the tinygrad device (`ktpugrad`)

`kohakutpu.application.ktpugrad` makes `KTPU` a tinygrad device: every
kernel tinygrad schedules is planned (`lower.plan`), run as generated DSL
kernels (`run.execute`) and nothing is computed on the host. Buffers and
forms are the runtime's (`tensor.md` API.FORM, API.MEM). Clause format, ids
and evidence tags: `../README.md`.

Evidence on this page:

- `silicon`: LeNet (`software/application/examples/tinygrad/mnist_mlp.py
  --model lenet --no-jit`, v9t6 node 0 over XDMA, 2 steps of 64 and a
  64-image evaluation) trained on the card on 2026-10-21 matching the CPU
  (loss 2.3320 / 2.2305 vs CPU f32 2.3324 / 2.2289; accuracy 0.5312 vs
  0.5469),
  with the code at `af7c1bb`. A clause is `silicon` only where the code it
  states is unchanged since (`git diff HEAD`: in `ktpugrad/` only `run.py`
  changed; `seam.py`, `device.py`, `lower.py`, `bridge.py`, `nn.py`,
  `uops.py`, `fold.py`, `domain.py`, `window.py` did not) and the run
  necessarily took it. A refusal or error path is never `silicon`.
  The kernels it ran, by kind (rows 170, walk
  74, transpose 38, copy 36, expand 35, flat 32, fill 30, quant 25, mm 15).
- `RTL`: `software/application/tests/ktpugrad/test_tinygrad.py` on the
  Verilated card (the runtime's default model), current tree: 76 of 80 pass;
  `k10`, `n10`, `n10_out`, `n84_epilogue` miss the 2e-2 tolerance (MXFP7
  precision). A clause cites the passing case.
- `unproven`: neither. Offline checks (`test_compile.py`, `test_window.py`)
  are not hardware-value evidence. TinyJit replay
  has never run on the card.

Machine facts are machine-schema parameters with the v9t6 value in brackets:
`vc.descriptors` [8 memory views a vector-core kernel], `die.word_bytes`
[32], `vc.lanes` [16], `vc.count` [2], `mg.count` [2], `card.profiles` [sys
clock: low 100 MHz, ship 300 MHz] (`boards/multimesh_v9t6.json:25-45`,
`:74-95`). The stack's own constants: a column block of 32 values (the
stack's block width), a widest block of 256 columns, and a statistic word of
`vc.lanes` values.

Generated kernels receive core and cluster counts from the active machine,
without defaults. Stage trips cover all `node.vc` instances that have work,
with the balanced, exact-once split of API.ROW.007 (RUL.016).
Both tensor frontends use `_product` for products: N is padded to whole
`vc.vlmax / mg.lanes` column blocks from the schema (one vector register
across a cluster GT4 row band), while logical N is retained.

## 1. Registration and the seam

- **TG.REG.001** `silicon` Importing `kohakutpu.application.ktpugrad` installs the device: `register()` puts a module `tinygrad.runtime.ops_ktpu` holding `KTPUDevice` into `sys.modules` (no file written into tinygrad), and `install()` routes lowering through the seam. `Device["KTPU"]` then resolves. (code: software/application/kohakutpu/application/ktpugrad/__init__.py:16-29; device.py:30-31, :311-321; seam.py:212-227; doc: docs/projects/kohakutpu/tinygrad.md:23-27; evidence: the LeNet run imported `ktpugrad` and ran on `KTPU`)
- **TG.REG.002** `silicon` `install()` saves the pinned options' previous values once, sets the pins (TG.PIN.*), sets the per-device buffer cap, reads `KTPU_TINYGRAD_FUSE`, swaps tinygrad's buffer-removal rules for the fuse mode, and patches `engine.realize.to_program` and `tensor.run_linear`; a second call changes nothing. (code: seam.py:212-227; evidence: host path of the LeNet run's import (TG.REG.001); seam.py unchanged since af7c1bb)
- **TG.REG.003** `unproven` `uninstall()` restores the pinned options, the buffer cap, tinygrad's buffer-removal rules, `to_program` and `run_linear`; the device stays registered. `installed()` reports whether `to_program` is the seam's. (code: seam.py:230-245)
- **TG.REG.004** `unproven` `python -m kohakutpu.application.ktpugrad --autoload [--site DIR]` writes `kohakutpu_ktpu.pth` holding `import kohakutpu.application.tinygrad_hook` into site-packages (default: this interpreter's purelib); `--remove` deletes it; `--check` runs a [64, 128] softmax on KTPU against numpy and prints the error, kernel count and cycles. The hook adds a meta-path finder that answers only `tinygrad.runtime.ops_ktpu` by importing `ktpugrad`, so `DEV=KTPU` works with no import in the script. (code: software/application/kohakutpu/application/ktpugrad/__main__.py:19-59; software/application/kohakutpu/application/tinygrad_hook.py:13-39; doc: tinygrad.md:29-31)
- **TG.SEAM.001** `silicon` `to_program(ast, renderer)` passes every non-KTPU renderer to tinygrad's own; for KTPU it plans the ast once by `ast.key` (`PLANS[key]`) and returns a PROGRAM uop whose sources are the sink (with `Estimates(ops=out_n, lds=2 out_n, mem=2 out_n)`), the ast's PARAMs, `SOURCE "ktpu KIND NAME"` and `BINARY = ast.key`. (code: seam.py:179-209; plans.py:4-5; inventory A-091; evidence: every LeNet kernel was lowered through it)
- **TG.SEAM.002** `RTL` A plan refusal at lowering raises `KTPUUnsupported` carrying clause TG.PLAN.010 in its `clause` attribute and diagnostic; nothing is computed another way. (code: seam.py:186-192; plans.py:8-9; doc: tinygrad.md:19-21; evidence: test_tinygrad.py `test_refused_by_clause` (`Tensor.rand`: the BITCAST / THREEFRY plan refusal of TG.PLAN.010 at lowering))
- **TG.SEAM.003** `unproven` `capture(run, strict=True)` returns every ast `run()` hands to lowering, in order; it requires the seam installed (else `KTPUUnsupported`); with `strict=False` a refusal ends the run and the asts so far are returned. (code: seam.py:248-264)

## 2. tinygrad options pinned

- **TG.PIN.001** `silicon` While installed: `NOOPT=1`, `BEAM=0`, `PARALLEL=0`, `NO_MEMORY_PLANNER=1`, `DEFAULT_FLOAT=half`, `SPLIT_REDUCEOP=0`, `WINO=0`, `PCONTIG=0`, process-wide. (code: seam.py:54-63, :218-219; doc: tinygrad.md:48-57; inventory A-042; evidence: host path of the LeNet run's `install()`)
- **TG.PIN.002** `silicon` The scheduler's buffer cap for KTPU is `vc.descriptors` [8] (the output and 7 reads): tinygrad cuts wider kernels. (code: seam.py:64-65, :220; inventory A-040, A-090; evidence: host path of the LeNet run's `install()`)
- **TG.PIN.003** `silicon` Producer inlining follows `KTPU_TINYGRAD_FUSE`: `elementwise` (default) keeps a computed producer read inside a consumer's reduction as its own kernel, inlining reloads (a buffer read, or one padded by an index-only gate with zero else) and elementwise consumers as tinygrad does. The rule applies only to buffers on KTPU. (code: seam.py:66-116, :221-225; doc: tinygrad.md:58; evidence: the LeNet run's schedules (the run's record names no fuse mode: the default))
- **TG.PIN.004** `unproven` `KTPU_TINYGRAD_FUSE=0` keeps every computed producer; `1` is tinygrad's own rule; any other value is refused (`ValueError`). (code: seam.py:66-116, :221-225; evidence: the LeNet run and the card tests use the default; refusal)

## 3. Device, allocator, renderer, program

- **TG.DEV.001** `silicon` `KTPUDevice` is a tinygrad `Compiled` device over the runtime device (`runtime.device.device()`), with `KTPUAllocator`, renderer `KTPURenderer`, runtime `KTPUProgram` and graph `KTPUGraph`; `synchronize()` drains submitted runtime kernels. (code: device.py:294-308; evidence: the LeNet run's device)
- **TG.DEV.002** `silicon` `KTPURenderer` declares no float4, no locals, no shared memory, no threads, `shared_max` 0, `global_max` and `local_max` (1, 1, 1), no tensor cores; `render()` raises (the seam plans instead). (code: device.py:82-99; inventory A-043; evidence: the LeNet run's renderer)
- **TG.DEV.003** `silicon` `KTPUProgram(dev, lib)` looks its plan up by the program binary (the ast key). A call maps its buffers to the plan's parameter slots in sorted slot order and runs `run.execute`. (code: device.py:102-125; evidence: every LeNet kernel ran through it)
- **TG.DEV.004** `RTL` A waited program call returns summed card cycles divided by the active sysnode clock (`card.sys_hz`, RUL.008). An ordinary queued call returns no completed timing value. `dev.last_runs` holds the call's runs or submissions. (code: device.py `seconds`, `KTPUProgram.__call__`; evidence: queue vectors and `test_memory_jit.py` on v9t6s)
- **TG.DEV.005** `silicon` The allocator's opaque buffer is a `Storage` of the requested size (word-rounded accessible extent, no allocation tail; API.MEM.002); free releases the storage and its forms; a sub-buffer (`_offset`) is a `StorageView` of the base. (code: device.py:36-79; evidence: every LeNet buffer)
- **TG.DEV.006** `silicon` `copyin` writes the bytes. After it the row-major form is the only valid one, the host bytes are kept when the write covers the whole buffer from offset 0, and the element type is unknown. (code: device.py:50-65; evidence: LeNet's uploads of weights and batches (`Tensor(x[idx], device=device)`, mnist_mlp.py:98-99))
- **TG.DEV.007** `silicon` `copyout` reads the row-major bytes when they are valid or no kernel wrote the buffer; otherwise the padded rows compacted on the host side of the read (API.FORM.009), as the element type the last kernel wrote. (code: device.py:67-74; evidence: LeNet's `loss.item()` and its evaluation logits (N 10 in rows 32 apart), mnist_mlp.py:105, :113)
- **TG.DEV.008** `unproven` A binary with no plan raises `RuntimeError` ("did not come through the seam"); a `Refused`, `RowsError` or `FormError` in `run.execute` raises `KTPUUnsupported` naming the kernel. (code: device.py:102-125; evidence: error paths, no card or passing RTL run)
- **TG.DEV.009** `unproven` A `copyin` at an offset or of a length not whole 32-byte words reads the covering words first and keeps the bytes past the buffer. (code: device.py:50-65; evidence: LeNet's uploads are whole buffers of whole words; no card test is known to write part of a word)
- **TG.DEV.010** `RTL` `copyout` of a buffer whose current form is its f16 form widens it. (code: device.py:67-74; forms.py:287-289; evidence: test_tinygrad.py `f32_input`: the f32 output is written as its f16 form (TG.RUN.013) and read back widened)

### Queued execution contracts

The knob is `KOHAKUTPU_QUEUE` (`1`: queued, default; `0`: synchronous), or the
attached runtime's `queued` option. These contracts are witnessed by frozen
`tg/queue` vectors on the v9t6s Verilated card and their named mutants.

- **TG.QUEUE.001** `RTL` Kernel calls submit in order without collecting; a host read collects the necessary prefix and observes the last writer's values.
- **TG.QUEUE.002** `RTL` Admission bounds the union of pending binding allocations by the runtime's byte budget, collecting oldest completions before adding a new working set.
- **TG.QUEUE.003** `RTL` Owner release does not reuse memory pinned by an uncollected run; completion releases the final pin.
- **TG.QUEUE.004** `RTL` Host writes wait for pending readers as well as writers of the logical storage's forms.
- **TG.QUEUE.005** `RTL` Explicit device synchronization collects all pending runs.
- **TG.QUEUE.006** `RTL` The per-node uncollected bound comes from its attached SQ/CQ layout.
- **TG.QUEUE.007** `RTL` Recorded replay submits without a final wait, and a dependent host read observes its output.
- **TG.QUEUE.008** `RTL` A firmware fault names its plan, generated run and exact completion; later results are discarded rather than reported as another kernel's success.

## 4. Plans (lowering)

- **TG.PLAN.001** `silicon` `lower.plan(ast)` accepts one stored loop nest: `SINK -> STORE` or `SINK -> END(STORE, ranges..)` with every range a constant count. (code: lower.py:104-108; uops.py:15-38; evidence: every LeNet kernel was planned through it)
- **TG.PLAN.002** `silicon` The store is into a buffer at an index that is one dense row-major walk of the loop nest with offset 0. The output ranges are ordered outermost first by their stride. (code: lower.py:110-121, :288-301; evidence: every LeNet kernel)
- **TG.PLAN.003** `silicon` A range read as `r // d` or `r % d` (nested divisions whose split points divide each other and the extent) is split into mixed-radix digits so every index is affine; a reduction over a split range reduces over its digits; `x // c` and `x % c` over digits fold when the terms c does not divide stay inside [0, c). (code: lower.py:158-280; doc: tinygrad.md:67-77; evidence: LeNet's `avg_pool2d` and its gradient, `flatten` and GroupNorm reshapes (mnist_mlp.py:64-67) index ranges by `//` and `%`; lower.py unchanged since af7c1bb)
- **TG.PLAN.004** `silicon` Plan kinds: `const` (the stored value reads no buffer: evaluated with numpy over the nest in tinygrad's integer semantics, cast to the output type, written from the host), `matmul` (TG.PLAN.008), `copy` (one read of a buffer at the output's own index, offset 0, same element type), else `vector` (an expression of `kernels.expr` ops over reads). (code: lower.py:122-155; fold.py:1-5; doc: tinygrad.md:89-92; evidence: LeNet's `Tensor.zeros` optimizer state (nn.py:68-74, const), its products (tally mm 15), copies (tally copy 36), vector kernels (rows 170, flat 32))
- **TG.PLAN.005** `silicon` A read is an `Access`: the parameter slot, its element type, its stride over each range, its element offset. (code: lower.py:30-46, :385-440; evidence: every LeNet kernel's reads)
- **TG.PLAN.006** `silicon` ALU ops map to expression ops: ADD add, MUL mul, RECIPROCAL recip, EXP2 exp2, LOG2 log2, WHERE where; `RECIPROCAL(SQRT x)` is one `rsqrt`. (code: lower.py:78-101, :346-354; evidence: tally `vadd` 4441, `vmul` 7225, `vinv` 664, `vexp2` 378 (SiLU, softmax), `vlog2` 8 (`log_softmax`), `vsel` 1272 in 47 kernels (38 of them transposes' lane masks), `vrsqrt` 131 (LeNet's GroupNorm / LayerNorm `rsqrt`))
- **TG.PLAN.007** `silicon` A REDUCE is ADD (sum) or MAX (max) over loop ranges. (code: lower.py:101, :372-383; evidence: LeNet's sums (losses, norms, gradients) and `log_softmax`'s max: tally `vadd xor` 408, `vmax xor` 196)
- **TG.PLAN.008** `silicon` A plan with one reduction that sums a product of two buffer reads, A reading [.., M, K] and B [.., N, K] in any layout, N the output's innermost live range and M the innermost range A reads and B does not, is a `matmul` plan; the epilogue is the store's expression with the product as `Load(0)`. (code: lower.py:453-539; evidence: LeNet's `Linear` products and their gradients, tally mm 15 kernels)
- **TG.PLAN.009** `silicon` A cast to a float type is the value. (code: lower.py:362-370; evidence: LeNet's half reductions (tinygrad accumulates half sums in float and casts back))
- **TG.PLAN.010** `RTL` An unsupported plan, including BITCAST or THREEFRY, is refused by clause TG.PLAN.010. `Tensor.rand` on KTPU raises `KTPUUnsupported` / `Refused` carrying that clause; tests assert its id, never explanatory message text. (code: lower.py:340-360; inventory A-038; evidence: test_tinygrad.py:326-334 `test_refused_by_clause`; doc: tinygrad.md:154-156)
- **TG.PLAN.011** `unproven` `lower.plan` refuses anything but one stored loop nest of constant ranges ("not one stored loop nest; it holds OPS"). (code: lower.py:104-108; evidence: refusal, no card or RTL run)
- **TG.PLAN.012** `unproven` A store not into a buffer is refused; a range outside the nest, a nest range the store does not index (a broadcast store), or a non-dense walk is refused. (code: lower.py:110-121, :288-301; evidence: refusals, no card or RTL run)
- **TG.PLAN.013** `RTL` An index-only subexpression inside data math is folded into an f16 table read (a constant when it is one value over the nest); a padded read `INDEX(buf, WHERE(gate, idx, Invalid))` keeps its gate as a table (`where(gate, read, 0)`). (code: lower.py:385-440; evidence: test_tinygrad.py `arange_times` (a folded table), `pad`, `conv2d_padded` (gates))
- **TG.PLAN.014** `unproven` A gate that reads data is refused; an index not affine in the loop is refused. (code: lower.py:385-440; evidence: refusals, no card or RTL run)
- **TG.PLAN.015** `RTL` MAX is `max`, SQRT `sqrt`, SIN `sin`, TRUNC `trunc`, CMPLT `cmplt`; AND on bools is `and` (a product, 0.0 / 1.0 in a lane). (code: lower.py:78-101, :346-354; evidence: test_tinygrad.py `floor_ceil` (trunc), `relu` (max), `sqrt_abs`, `sin`, `where` (cmplt), `bools`; no record ties a tally `vmax` to an ALU MAX of LeNet's rather than a reduction tree)
- **TG.PLAN.016** `unproven` SUB is `sub`, FDIV `div`, NEG `neg`, POW `pow`, CMPNE `cmpne`, CMPEQ `cmpeq`, MULACC `fma`; OR / XOR on bools are `or` / `xor`; a WHERE on a constant condition picks its arm. (code: lower.py:78-101, :346-354; evidence: none is in a LeNet kernel (no `vneg`, `vfma`, compare in the tally) and no passing card test is known to emit them)
- **TG.PLAN.017** `unproven` A REDUCE MUL is `prod`; another reduce op or a reduction over anything but ranges is refused. (code: lower.py:101, :372-383; evidence: no card test reduces by MUL; refusal)
- **TG.PLAN.018** `RTL` In a `matmul` plan, A's other ranges are batches (B shared when it reads none of them). (code: lower.py:453-539; evidence: test_tinygrad.py `batched_n48`)
- **TG.PLAN.019** `unproven` A cast to bool is `cmpne x, 0`; a cast to any other non-float type is refused ("a cast to TYPE"). (code: lower.py:362-370; evidence: no card test is known to cast to bool; refusal)
- **TG.PLAN.020** `unproven` Refusal diagnostics may explain the unsupported operation. Their wording is not an interface: TG.PLAN.010 is the stable clause id asserted by callers and tests. (code: lower.py `Refused`; plans.py `KTPUUnsupported`; test: `test_refused_by_clause`)

## 5. Running a plan

A row reduction's statistic is compact f16 storage, 16 row values a 32-byte
word, including its final partial word. Producers, statistics-only math,
read-back and row broadcasts use this one form (RUL.030); there is no
`[n, 32]` statistic layout. A full row output materialises register rows
from those values before packing ordinary rows.

- **TG.RUN.001** `silicon` `run.execute(dev, plan, bufs)` runs a plan with the parameter slots bound to storages and returns the runs; a `const` plan writes its value from the host, its row-major form the only valid one, host bytes kept for a whole buffer. (code: run.py:68-104; evidence: every LeNet kernel ran through `execute`; Adam16's `Tensor.zeros(..).contiguous()` state (nn.py:68-74) is a `const` plan; run.py:1-153 unchanged since af7c1bb)
- **TG.RUN.002** `silicon` For `vector` and `copy` plans, a read of a buffer held only in its padded-rows form `("rows", n, np)`, whose walk stays inside one row and has no negative step, is re-strided onto that form (a row step of n becomes np) and read as f16; a `copy` that reads such an alias runs as `vector`. (code: run.py:36-83; evidence: LeNet's `n1` LayerNorm (a reduction, its own kernel) reads `l1`'s product of 120 columns held only in rows 128 apart (API.FORM.004, the tally's mm `out: f16[64, 128]`))
- **TG.RUN.003** `RTL` A `vector` plan takes the first path in this order: window contraction (when it reduces) -> folded tables under its reductions uploaded -> kept ranges only tables read, enumerated -> a contraction (one sum of a product of two buffer reads) as matmul -> an epilogue contraction materialised -> `where` selectors cut into boxes, else padded reads un-gated -> more than 7 reads narrowed -> a bare read (move, transpose, flip, gather) -> several reduction range sets materialised -> flat (no reduction, dense output) -> one long range refolded into rows -> rows. (code: run.py:1374-1410; evidence: test_tinygrad.py's passing cases, each taking the path its clause names (TG.RUN.004-.022); the kept-ranges tables path (TG.RUN.021) and un-gated reads (TG.RUN.010) have no named case; the af7c1bb order the card ran had one more step (elementwise math over statistic forms), so the current `_vector` is not the one that ran)
- **TG.RUN.004** `RTL` window: one sum of the product of two reads where a read is a window (two ranges at one stride, signed) or a gate bounds it -- a convolution, its two gradients, a pool. Each side is laid out dense `[batch.., outer.., K.., lane]` as f16 (gathered with zeros outside the gate's box, the lane innermost and padded to whole 16-element words; a lane of one holds 16 copies of each value on the M side), the product runs on the clusters into a temporary, the rest of the expression reads it. (code: run.py:1188-1370; window.py; doc: tinygrad.md:100; evidence: test_tinygrad.py `conv2d`, `conv2d_padded`, `conv2d_one_channel`, `avg_pool2d`, `test_conv_gradients`, `test_avg_pool_gradient`)
- **TG.RUN.005** `silicon` move: one read stored as it is whose source and destination walks are whole 32-byte words (from a word-aligned byte, adjacent levels merged): one mover copy with signed walks (slices, row flips, permutes keeping the innermost axis, row broadcasts, windows). (code: run.py:507-569; kernels/convert.py:22-38; evidence: test_tinygrad.py `row_slice`, `column_slice`, `row_flip`, `broadcast_row`; evidence: the card-run tally walk 74)
- **TG.RUN.006** `silicon` transpose: an f16 read whose innermost axis moved, the new innermost extent a multiple of 16 and the other side either a multiple of 16 or read 16-padded inside its buffer: mover GT4, a 4 x 4 lane transpose in each 16-lane chunk (`xlane` 5 then 10 under lane masks), mover GT4, a mover copy (padding rows dropped); exact; identity moves skipped. (code: run.py:598-711; kernels/transpose.py:1-94; inventory A-034, A-035; evidence: test_tinygrad.py `transpose`, `heads`, `channels_last`, `channels_first_6`; evidence: the card-run tally transpose 38)
- **TG.RUN.007** `RTL` flip: an f16 read walking its innermost axis backwards, rows of whole words, the source's row-major bytes valid: the mover walks words last to first and a core reverses each word's lanes (`xlane 15`); exact. (code: run.py:809-867; kernels/transpose.py:97-120; inventory A-036; evidence: test_tinygrad.py `column_flip`)
- **TG.RUN.008** `RTL` gather: any other single read into an f16 output, by `forms.relayout`: one kernel of `kernels.relayout`'s forms (whole-word walks, runs, splats, transposes; L2.REL.006-011), else the lane relayout (taps of one source word at one lane rotation, classes of words with the same taps, fp32 index lists gathered and scattered by the mover, `xrot` + `where` under lane masks on a core); exact. A dense output from a word is written whole; a window or offset output keeps what its words held between its elements. (code: run.py:714-769; software/application/kohakutpu/application/kernels/relayout.py; software/application/kohakutpu/application/kernels/lanes.py; doc: tinygrad.md:104; evidence: test_tinygrad.py `narrow_transpose`, `odd_permute`, `narrow_flip`, `stride_slice`; application/tests/kernels/test_relayout.py)
- **TG.RUN.009** `RTL` boxes: a `where` on index tables (pad, cat, stack): the kept ranges cut where any table changes (at most 64 boxes), each box run with its tables constant -- a mover fill of one value where the box's output is whole words, else the value moved in from a temporary; a move; or a rows kernel into a window; no read leaves its buffer. (code: run.py:897-1014, :1073-1144; evidence: test_tinygrad.py `pad`, `pad_value`, `cat_rows`, `cat_columns`, `cat_then_math`, `stack`)
- **TG.RUN.025** `unproven` A `where` on index tables whose gate moves with a reduced range, whose cut is not boxes, or whose box is off whole words falls through to un-gated reads (TG.RUN.010). (code: run.py:897-1014; evidence: no passing card test is known to fall through)
- **TG.RUN.010** `unproven` un-gated: each padded read is read from a zero-padded copy of its source over its coordinates, the gate kept as a select; a gate never letting through reads a constant 0; a gate over a range the read does not read is refused. (code: run.py:1017-1070)
- **TG.RUN.011** `RTL` narrow: a plan of more than `vc.descriptors - 1` [7] reads materialises first the reduction-free subexpression with the most reads (2..7) into an f16 temporary over the ranges its reads walk, read back as one. (code: run.py:425-504; inventory A-041; evidence: test_tinygrad.py `test_wide_kernels_split_at_eight_views`)
- **TG.RUN.026** `unproven` A plan of more than 7 reads with no reduction-free subexpression of 2..7 reads is refused. (code: run.py:425-504; evidence: refusal, no card or RTL run)
- **TG.RUN.012** `RTL` materialise: reductions over different range sets run an innermost one first into an f16 temporary over the ranges outside it, read back by the rest; recursive. A product leaf is laid out so the clusters take it ([batch, M, N], up to 6 ranges' orders tried). (code: run.py:289-385; evidence: test_tinygrad.py `channel_sum`, `bn_var`, `cross_entropy`)
- **TG.RUN.013** `RTL` flat: no reduction, a dense output, every read at the output's own index (offset a multiple of 16): one pass of 128-value rows over the f16 forms. The output is the f16 bytes of an f16 buffer, else its f16 form. (code: run.py:1854-1894, :168-181; evidence: test_tinygrad.py `add`, `affine`, `relu`, `exp`, `gelu`, `f32_input`)
- **TG.RUN.027** `unproven` flat: a one-value read binds its word and reads its lane (`unpack lane=`); a part of a buffer takes the flat path only when its rows are its own (n a multiple of 128, offset on a word). (code: run.py:1854-1894; evidence: no passing card test is known to make a one-value read (`docs/spec/stack/dsl/graph.md` conflict 9) or a flat write of part of a buffer)
- **TG.RUN.014** `RTL` rows: one reduction or none over a view -- `along` (rows the kept ranges, columns the reduced), `down` (rows the reduced: a halving tree of rows kernels, `runtime/tree.py`) or `rows` at a split of the output's ranges -- the view laying out the fewest reads, then whole 32-column rows, then the order listed. A single live range longer than the stack's widest block (256 columns) is folded into rows of 256, 128, 64 or 32 first. (code: run.py:1430-1507, :1814-1851; software/application/kohakutpu/application/runtime/tree.py:45-121; evidence: test_tinygrad.py `sum_rows`, `sum_cols`, `max_cols`, `sum_cols_120`)
- **TG.RUN.015** `RTL` rows width: the kernel runs W' = ceil32(W) columns; with W' != W along the rows a column mask table guards each reduction, padding lanes holding the reduction's identity (sum 0, max -65504, prod 1). (code: run.py:1427, :1438, :1454-1465; inventory A-039; evidence: test_tinygrad.py `sum_02`, `max_13`)
- **TG.RUN.016** `RTL` rows binding: a read the kernel takes as it is binds as it is -- rows of whole words at least W' apart within their pitch, a row from a word, a value a row from a word (16 a word), one value; any other read is laid out once over every row and every column range it reads, rows W' apart (a table on the host, a buffer by the bare-read paths, spread to W' by `repitch`). (code: run.py:1519-1588; evidence: test_tinygrad.py `row_broadcast`, `batch_table`; offline binding witnesses: `software/rust/crates/ktpu-plan/tests/run.rs`)
- **TG.RUN.017** `RTL` rows placing: a reduction along the rows writes its R f16 values (16 a word) into the output where those words are the statistic's own (it starts on a word and ends on one or at the buffer's end), else into a temporary moved in; any other result goes into the output where its rows are whole words and W' = W, else its padded-rows form `("rows", W, W')` when it is a whole float buffer, else a temporary moved in (any window, any offset; a non-f16 output through its f16 form). (code: run.py:1591-1698; evidence: test_tinygrad.py `sum_rows`, `cumsum_rows`, `layernorm`)
- **TG.RUN.018** `RTL` A reduction whose view lays out a read and whose reduced ranges interleave with the kept ones runs as two, the inner ranges first; two or more reductions down the rows run one after another. (code: run.py:388-422, :1439-1444; evidence: test_tinygrad.py `channel_sum`, `channel_sum_64`, `bn_mean`)
- **TG.RUN.019** `RTL` matmul: an output not dense as `[batch.., M, N]` is computed into such an f16 temporary and moved in; an operand not `[batch.., rows, K]` row-major is laid out so first (a B no batch reads shared); N is padded to Np = ceil32(N); the epilogue's trip quantum is 4 rows when it reads no statistic; the tiling is ktpu-kernels' `matmul::plan` under the contraction knobs the environment resolves (`matmul::Knobs::resolve`, `KTPU_MM_*`), each product's `matmul.plan` and `matmul.mm_kernel` calls recording the knobs it was planned under (a call recording none replays under `matmul::unrecorded`); A and B are MXFP7 packings made once; epilogue operands are laid out to Np (the mover, else `forms.relayout`, a table on the host), an operand held as padded rows at least Np wide (whole words) read as those rows; the clusters' product with the epilogue on the cores, the product through DRAM or, with `ring_depth`, through `@stage` slots as many waves deep as the staging room holds (`matmul::ring_resolve`); the prepared product (operands made inside the kernel) only for a call whose kernel knobs all resolve off (`_rs.mm_resolved`). (code: run.py:1903-2140; evidence: test_tinygrad.py `linear_relu`, `k_major_weight`, `transposed_left`, `batched_n48`, `n84_dense_operand`; padded rows read as they are: test_padded_reads.py)
- **TG.RUN.020** `RTL` A product's output whose rows of N are not whole words (or not f16) and that is a whole float buffer stays in its padded-rows form `("rows", N, Np)`. (code: run.py:2197-2266; doc: tinygrad.md:114-117; evidence: `n84_dense_operand` passes; LeNet's products of N 120, 84, 10 took it on the card (API.FORM.004))
- **TG.RUN.028** `unproven` matmul: batches not one row-major stack are refused; the epilogue's trip quantum is 16 rows when it reads a statistic (`STAT_ROWS`). (code: run.py:1999-2006, :1903-2140; evidence: refusal; the quantum of 16 is added since af7c1bb and no passing card test is known to read a statistic in an epilogue)
- **TG.RUN.029** `unproven` A padded product that does not stay in its padded-rows form goes to an `[bt, mp, Np]` temporary and its `[M, N]` window is moved into the output. (code: run.py:2197-2266; evidence: `n10_out` takes it and misses the 2e-2 tolerance; no passing case does)
- **TG.RUN.021** `unproven` Kept ranges only tables read (a strided window's phase) run once a value of those ranges, each into its slab of an f16 temporary (slabs whole words), then moved into the output; folded tables a reduction reads are uploaded as f16 buffers first. (code: run.py:1719-1797)
- **TG.RUN.022** `RTL` copy: a buffer's current form (row-major bytes word to word, the f16 form, or the padded-rows form) copied whole by the mover; a copy off a word or of part of a form runs as the bare read it is. (code: run.py:191-224; evidence: test_tinygrad.py `test_assign_then_read_in_one_realize`; evidence: the `af7c1bb` version ran on the card, the card-run tally copy 36)
- **TG.RUN.023** `unproven` A part of a buffer written while its row-major bytes are not current makes them current first from its f16 form (an f16 buffer); for any other element type it is refused ("part of a TYPE buffer written while its bytes are not current"). (code: run.py:870-884; evidence: no record shows the LeNet run or a passing card test writing part of a buffer not row-major current; refusal)
- **TG.RUN.024** `unproven` Writing part of an f32 buffer keeps the rest: the buffer's f16 form is made current first, the kernel writes into it. (code: run.py:168-181, :1674-1698; evidence: offline plan witnesses in `software/rust/crates/ktpu-plan/tests/run.rs`, not card-value evidence)

## 6. Float on the card

- **TG.FLT.001** `silicon` Every tensor on the card is float (owner scope rule): a model is placed with its floats cast to f16 (`nn.place`), a loss reads its labels as one-hot float values, and integer data never reaches a kernel as integers. (code: software/application/kohakutpu/application/ktpugrad/nn.py:25-31; software/application/examples/tinygrad/mnist_mlp.py:83-87; doc: tinygrad.md:126-127; owner scope rule: every tensor on the card is float, integers only for the sysnode and SIMT; evidence: the LeNet card run)
- **TG.FLT.002** `silicon` A hidden state is f16 or, as a product's operand, MXFP7. (code: run.py:1674-1698; runtime/forms.py:62-71, :174-230; doc: tinygrad.md:61-63; evidence: the tally's f16 buffers and the LeNet products' `mx7a` / `mx7b` packings (quant 25 kernels))
- **TG.FLT.003** `RTL` A bool tensor is 0.0 / 1.0 f16 lanes: comparisons give 0 / 1, `and` is a product. (code: lower.py:100, :353-354; kernels/expr.py:207-223; evidence: test_tinygrad.py `bools`, `where`)
- **TG.FLT.004** `RTL` A float buffer tinygrad declares f32 is held on the card as f16 (its f16 form). (code: run.py:168-181; runtime/forms.py:77-92; evidence: test_tinygrad.py `f32_input`; every LeNet tensor is half)
- **TG.FLT.005** `unproven` On bools `or` is a maximum, `xor` `|a - b|`, `not` `1 - a`. (code: kernels/expr.py:224-229; evidence: no card test uses them)

## 7. Buffer lifetime

- **TG.LIFE.001** `silicon` While installed, `realize` runs a schedule through the seam's `run_linear`: a KTPU buffer the schedule names, that no live Tensor's graph holds, is deallocated right after the last kernel that reads it (when it is allocated and has no allocated views). (code: seam.py:117-171; doc: tinygrad.md:59; evidence: the LeNet run's schedules, `--no-jit`)
- **TG.LIFE.002** `unproven` Without KTPU buffers, or under a JIT, tinygrad's own `run_linear` runs. (code: seam.py:117-171; evidence: the LeNet run had no JIT; no card test runs one)

## 8. TinyJit

- **TG.JIT.001** `unproven` A TinyJit batch on KTPU is a `KTPUGraph`: each call copies the batch's inputs into slots of its own (fixed addresses) from their host bytes, with the f16 forms of non-f16 inputs the last call made; an input without host bytes (made on the card), at an offset, or whose host bytes are not the whole buffer makes the call run through the planner unrecorded. (code: device.py:130-177, :220-226)
- **TG.JIT.002** `unproven` A call with filled slots records the card's log (packages, bindings, host writes and reads) with every allocation in private arenas; two consecutive recorded calls with equal entry state (each storage's valid forms, host bytes held, element type, form places; each node's resident cores; the private arenas' spans), equal log and equal exit state, and no host read in the log, make that log the batch. (code: device.py:206-268; runtime/device.py:212-230)
- **TG.JIT.003** `unproven` A later call whose entry state equals the batch's replays the log (every package already in its node's heap, submitted back to back, the host waiting once) and restores the storages' records and resident-core snapshots as the recorded call left them; it returns the replayed cycles over `CLOCK_HZ`. A call with any other entry state records again; `misses` lists where consecutive records first differed; `counts` tallies planned, recorded and replayed calls. (code: device.py:229-268, :271-291)
- **TG.JIT.004** `unproven` `mnist_mlp.py` runs the step under TinyJit unless `--no-jit`; Adam16's bias corrections `b1^t`, `b2^t` live on the card and advance in the step's graph so a replay does not freeze them. (code: software/application/examples/tinygrad/mnist_mlp.py:94, :133-135, :163; nn.py:63-66, :86-91)

## 9. Your own kernel and training

- **TG.BRIDGE.001** `RTL` `ktpugrad.bridge(kernel)(*tensors, **consts)` realises every input on KTPU in one schedule (each contiguous, moved to KTPU if elsewhere), specialises the kernel for f16 / f32 specs of their shapes, hands each over in its port's form (API.FORM.012), allocates each output as a new `Tensor.empty` on KTPU, runs once (kind "bridge") and marks the outputs written; a one-output kernel returns its Tensor. (code: software/application/kohakutpu/application/ktpugrad/bridge.py:25-108; doc: tinygrad.md:208-217; evidence: test_tinygrad.py:269-272)
- **TG.BRIDGE.002** `unproven` A bridged input of another dtype is `ValueError`; an output not row-major f16 / f32 is `ValueError`; a count mismatch is `ValueError`; a kernel of several outputs is called through `.outputs(...)`, which returns every output. (code: bridge.py:28-33, :64-75, :88-93; evidence: refusals; no card test bridges a several-output kernel)
- **TG.NN.001** `silicon` `nn.place(module, device="KTPU", dtype=half)` replaces every tensor of the module's state dict with its copy on the device, floats cast to `dtype`. (code: nn.py:25-31; doc: tinygrad.md:176-177; evidence: the LeNet run's model placement)
- **TG.NN.002** `silicon` `Adam16(params, lr=1e-3, b1=0.9, b2=0.95, eps=1e-8, weight_decay=0, loss_scale=1024, compensate=True)` keeps m, rms = sqrt(v) and (with `compensate`) a Kahan error buffer, each f16 like its weight; `scale(loss)` multiplies the loss by `loss_scale`; `schedule_step()` under `TRAINING` returns the tensors to realise: `w -= lr * (m * m_scale / (rms * r_scale + eps * loss_scale) + wd * w)` with the rounding error kept and added to the next update. (code: nn.py:34-128; doc: tinygrad.md:172-206; inventory A-047; evidence: the LeNet run's optimizer (mnist_mlp.py:89-91), 2 steps matching the CPU (TG.TOL.004))
- **TG.NN.003** `unproven` `schedule_step()` outside `TRAINING` is `RuntimeError`; a parameter without a gradient is `RuntimeError`. (code: nn.py:34-128; evidence: error paths, no card or RTL run)

## 10. Devices and environment

Every device kind and `VerilatorCard` requires a board named by `board=` or
`KOHAKUTPU_BOARD`, resolved through the machine schema. Without one it raises
`ValueError` naming RUL.011 before opening a card or model.

- **TG.ENV.001** `silicon` `KOHAKUTPU_DEVICE=card` picks the card itself as the runtime device. (code: software/application/kohakutpu/application/runtime/device.py:1-16, :31, :43, :81-92; evidence: the LeNet run used `card`)
- **TG.ENV.002** `RTL` A `sim` device opens the model at `KOHAKUTPU_SIM_BUILD`, else `build/v9g/vlt_card_v9_<nodes>n_v2`; its board is the required `board=` argument or `KOHAKUTPU_BOARD`. (code: runtime/device.py:50-60, :108-124; runtime/card.py:465-486; software/application/tests/conftest.py:11-17; evidence: test_tinygrad.py's `dev` fixture, the runtime's default model)
- **TG.ENV.003** `silicon` A `card` device opens board `KOHAKUTPU_BOARD` over `KOHAKUTPU_TRANSPORT=xdma` on a Linux host, when every node used is at the board's idle profile. (code: runtime/device.py:93-107; runtime/card.py:499-557; evidence: LeNet on `multimesh_v9t6` node 0 over XDMA)
- **TG.ENV.008** `RTL` `KOHAKUTPU_DEVICE` unset (`sim`) is the Verilated card. (code: runtime/device.py:31, :43, :81-92; evidence: test_tinygrad.py's `dev` fixture (conftest.py:11-17) opens it)
- **TG.ENV.009** `unproven` `KOHAKUTPU_DEVICE=offline` compiles, checks and encodes every run and executes nothing; any other value is refused; constructor arguments override the variables. (code: runtime/device.py:1-16, :81-92; evidence: no card run or card test uses them; refusal)
- **TG.ENV.010** `unproven` A `card` device requires a named board and its transport defaults to `jtag`; `XDMA_KO` names the driver module for link-reset recovery; it opens every node the board has unless a node count is given; a node not at the board's idle profile is `ClockMismatch`. (code: runtime/device.py:93-107; runtime/card.py:499-557; evidence: the LeNet run named its board and transport; no record of a link reset or of the node count it opened; refusal)
- **TG.ENV.011** `unproven` A missing `sim` build raises `FileNotFoundError` (the test fixtures then skip). (code: runtime/device.py:108-124; conftest.py:13-16; evidence: error path; a skip is not a pass)
- **TG.ENV.004** `unproven` An `offline` device opens the required board named by `board=` or `KOHAKUTPU_BOARD`, with the named machine's `card.dram.bytes` of paged host memory standing for DRAM; runs return 0 cycles. (code: runtime/device.py; runtime/offline.py)
- **TG.ENV.005** `unproven` `KOHAKUTPU_SIM_NODES` sets the node count of any device kind (default 1; a `card` the board's meshes). (code: runtime/device.py:33-34, :94-96; inventory A-077; evidence: the LeNet run's record (v9t6 node 0, 2 steps of 64, loss 2.3320 / 2.2305) names node 0, not the variable or the count opened)
- **TG.ENV.006** `unproven` `KTPU_DUMP` names a directory each compiled kernel's L2 and L1 text is written to; `KTPU_COMPILE_CACHE` names the on-disk compile cache (empty turns it off). `KOHAKUTPU_BOOT_FLAGS`, `KOHAKUTPU_RESIDENT`, `KOHAKUTPU_KEEP_FAILED` are the card runtime's (`debug/firmware.md`, L0 pages). (code: software/compiler/kohakutpu/stack/kernel.py; software/rust/crates/ktpu/src/lib.rs; runtime/card.py:69-73)
- **TG.ENV.007** `unproven` `DEV=KTPU` (tinygrad's own variable) selects the device in a script that imports nothing of KohakuTPU once the autoload hook is installed (TG.REG.004). (code: tinygrad_hook.py:1-6; doc: tinygrad.md:29-31)

## 11. Tolerances the tests hold

- **TG.TOL.001** `RTL` Data movement cases (`MOVEMENT` but `transpose_add`, `cat_then_math`) are bit-exact against numpy. (code: software/application/tests/ktpugrad/test_tinygrad.py:255-266; doc: tinygrad.md:125-126; evidence: `test_program_on_ktpu` over the 18 exact `MOVEMENT` cases, all among the 76 of 80 passing)
- **TG.TOL.002** `RTL` Every other case holds `max |got - want| / max |want| < 2e-2` against float64 numpy; four matmul cases (`k10` 0.0239, `n10` 0.0216, `n10_out`, `n84_epilogue` 0.0221) do not. The tolerance clause belongs to `numerics/formats.md`. (code: test_tinygrad.py:259-266; software/application/tests/conftest.py:20-28; evidence: `test_program_on_ktpu`, 76 of 80 passing on the current tree, the four misses MXFP7 precision)
- **TG.TOL.003** `RTL` An assign read back in the same realize gives exactly the assigned value, and the dependent update within rtol 1e-3, atol 2e-3. (code: test_tinygrad.py:275-284; evidence: `test_assign_then_read_in_one_realize`)
- **TG.TOL.004** `silicon` LeNet's step on the card matches f32 on the CPU: loss 2.3320 / 2.2305 vs 2.3324 / 2.2289 over 2 steps of 64, accuracy 0.5312 vs 0.5469 on 64 images. (code: software/application/examples/tinygrad/mnist_mlp.py; evidence: the 2026-10-21 LeNet card run, `mnist_mlp.py --model lenet --no-jit` on `multimesh_v9t6` node 0)

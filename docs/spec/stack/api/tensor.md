# API: the `kp` tensor API, buffer forms and storage

`kohakutpu.application.api` (`kp`) is the machine's own tensor library: a
lazy graph planned by the API itself. Realisation can execute multiple generated
kernels (API.FUSE.003). Its buffers, forms and allocation are the runtime's
(`application/runtime/`), shared with the tinygrad device (`tinygrad.md`).
Clause format, ids and evidence tags: `../README.md`.

Evidence on this page:

- `silicon`: retained only for the scoped card-exercised behaviour whose
  historical implementation is identified in the clause evidence.
- `RTL`: requires a named existing RTL or Verilated test of the stated behaviour.
- `unproven`: no such witness established; host-only tests do not upgrade a tag.
  The tensor API clauses are not evidence of a tensor-API card run.

Machine facts are machine-schema parameters with the v9t6 value in brackets:
`die.word_bytes` [32], `vc.lanes` [16 f16 a word], `vc.count` [2],
`mg.count` [2]. A product column block is `vc.vlmax / mg.lanes` [32]:
one vector register across the cluster's GT4 row band. The stack uses a
widest block of 256 columns,
and a statistic word of `vc.lanes` values.

## 1. Tensors

- **API.TEN.001** `unproven` `kp.tensor(a, dtype=np.float16)` uploads a contiguous array. For f16 it rounds through `fp16.write`: finite overflow saturates to ±65504, genuine infinities remain infinities, and subnormals are retained; for f32 it casts to that type. Other element types raise `Unsupported` with API.REF.011. `zeros`, `ones`, `full` and `arange` first construct numpy f16 arrays and pass them to `tensor`. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:400-409; software/kohakutpu/application/kohakutpu/application/api/__init__.py:30-43; software/kohakutpu/language/kohakutpu/language/numerics/fp16.py:8-16)
- **API.TEN.002** `unproven` A tensor holds a realised buffer, a lazy expression over realised reads and at most one product on a rows view, or a transpose view. realize() evaluates its lazy expression through the selected runtime path, which may launch multiple kernels; numpy() realises and reads the current form. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:63-84, :118-128, :168-182, :614-639; software/kohakutpu/application/kohakutpu/application/runtime/rows.py:264-323)
- **API.TEN.003** `unproven` Realising a lazy built-in tensor operation sets the result storage and tensor type to f16. Uploaded tensors and custom-kernel outputs may be f32. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:634-636, :400-409; software/kohakutpu/application/kohakutpu/application/api/custom.py:55-79)
- **API.TEN.004** `unproven` `numpy()` of a statistic reads its f16 values from the current form (API.FORM.009) as `shape`; of a row tensor, its current form compacted to `size * itemsize` bytes; of a transposed view, the base's array with the last two axes swapped. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:173-182)
- **API.TEN.005** `unproven` `reshape(*shape)` realises and returns a tensor over the same buffer (numpy's reshape rules, `-1` allowed) keeping the statistic flag; `flatten()` is `reshape(size)`. A reshape of a transposed view is refused ("a reshape of a transposed view: only matmul reads one"). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:184-199)
- **API.TEN.006** `unproven` `.T` of a tensor of rank at least two realises its base and returns a last-two-axes-swapped view without moving bytes. Computational operands accept it only as matmul's right operand; `numpy()` also reads it by swapping the base array's last two axes. `.T` of the view returns its base; rank below two is refused with API.REF.009. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:173-176, :201-214, :412-417, :514-536)
- **API.TEN.007** `unproven` `bool(t)` is refused ("read it with .numpy() first"). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:273-276)
- **API.TEN.008** `unproven` kp.device() returns the process runtime device, constructing it on first request. kp.runs() returns a copy of that device's run-history list; an ordinary submitted kernel enters that list after successful collection, not merely upon submission. (code: software/kohakutpu/application/kohakutpu/application/api/__init__.py:70-77; software/kohakutpu/application/kohakutpu/application/runtime/device/__init__.py:344-349; software/kohakutpu/application/kohakutpu/application/runtime/device/submission.py:400-429)

## 2. Operations

- **API.OP.001** `unproven` Elementwise operators build expressions for addition, subtraction, multiplication, division (including reflected forms), powers, negation, absolute value, comparisons, selection, extrema, exponentials, logarithms, roots, reciprocal, sine, cosine, truncation and derived activations. Numeric square expands to multiplication; <= and >= negate opposite strict comparisons. Cosine shifts sine by pi/2. GELU computes x * sigmoid(2z), where z = sqrt(2/pi) * (x + 0.044715*x*x*x). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:216-340, :453-481)
- **API.OP.002** `unproven` Operand shapes broadcast as numpy's; shapes that do not broadcast are refused ("they do not broadcast"). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:453-461)
- **API.OP.003** `unproven` Reductions `sum`, `max`, `min` (`-max(-x)`), `prod`, `mean` (sum times 1/n), `var` (population: mean of squared deviations), `std` (`sqrt(var)`) take `axis` (the last only) and `keepdim`; the result is a row statistic of shape `shape[:-1]` (+`(1,)` with `keepdim`). `axis=None` reduces the whole tensor through a `[1, size]` view (shape `()` or all ones with `keepdim`). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:343-368, :488-511)
- **API.OP.004** `unproven` `softmax(axis=-1)`, `log_softmax(axis=-1)` (last axis only), `layernorm(weight, bias, eps=1e-5)`, `rmsnorm(weight, eps=1e-6)` are built of the ops above over the last axis. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:370-397)
- **API.OP.005** `unproven` `matmul(a, b)` / `a @ b` takes `b` as the `.T` view of an [N, K] (or batched [.., N, K]) tensor; the result is `a.shape[:-1] + (N,)`; `kp.linear(x, w, b=None)` is `x @ w.T (+ b)`. A batched B's batch shape equals A's. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:514-542)
- **API.OP.006** `unproven` Product planning rounds N to Np=ceil(N/block)*block, block=vc.vlmax/mg.lanes [32], and runs at Np. For whole floating outputs with N != Np, a narrow result (N f16 values not whole words, or non-f16 logical output) uses padded rows; otherwise the padded result materialises through the output-window path. Logical dimensions retain N. (code: software/kohakutpu/application/kohakutpu/application/ktpugrad/run/product.py:186-205, :229-270, :352-365)
- **API.OP.007** `unproven` Product computation uses MXFP7 operands and vector-core epilogue arithmetic. A may be bound as dense f16 rows and quantised inside the product kernel when that path is admitted, rather than arriving as a separately cached MXFP7 form. (code: software/kohakutpu/application/kohakutpu/application/ktpugrad/run/product.py:274-305; software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/matmul.rs:1195-1200, :1254)
- **API.OP.008** `unproven` The shared product runner can attach demanded output packings to the product kernel and publish them with its producer site. The kp frontend subsequently calls `wrote` again on the returned form, clearing other valid forms and the producer site; kp therefore does not retain those published packing hints and valid forms for its consumer. (code: software/kohakutpu/application/kohakutpu/application/ktpugrad/run/product.py:340-357; software/kohakutpu/application/kohakutpu/application/api/tensor.py:634-636; software/kohakutpu/application/kohakutpu/application/runtime/memory/storage.py:235-246)
- **API.OP.009** `unproven` Whole f16 copies updating held values can attach consumer packings; host scheduling invalidates previous forms and marks attached packings valid. Demands are learned for single-batch offset-zero whole row-major updated-buffer reads and grouped by first demanded [N,K] shape. Form a admits only a descriptor-fitting prefix; remaining demands stay for consumers. Rust requires whole bands, positive groups, packed width K and K divisible by each chunk, chooses a fitting divisor, computes stored-f16 members, packs checked and zero-packs extra rows. Form b uses checked quant after the writer with composed relayout where admitted. Auto prices copy-surrogate packages and rejects a selected form costlier than separate writer/quant launches. Publication is scheduling metadata, not successful-completion observation. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:166-169, :722-760, :839-855; software/kohakutpu/application/kohakutpu/application/ktpugrad/launch/emit.py:135-187, :190-231, :234-282; software/kohakutpu/application/kohakutpu/application/ktpugrad/run/__init__.py:225-248; software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/fused.rs:288-337, :416-472, :479-525)

## 3. Fusion and kernels

- **API.FUSE.001** `unproven` kp.set_fusion(on) stores bool(on) and returns the previous setting. With fusion disabled, consuming a lazy operand realises it instead of inlining its expression; this does not guarantee one kernel per public operation. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:35-40, :420-450)
- **API.FUSE.002** `unproven` With fusion on, a lazy operand is inlined only when its rows view equals the consumer's, it has no reduction over a width not divisible by 32, adds no second distinct product, puts no product beside a reduction, and a width above the software maximum block width (256 columns) does not put a reduction in an elementwise consumer or combine multiple reductions. Otherwise it is realised and read as a `Ref`. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:420-450)
- **API.FUSE.003** `unproven` Realisation selects a product first; otherwise rows whose width is neither 1 nor divisible by 32 use `_planned_rows`; other statistics use `_statistic`, and other results use `_wide`. These paths do not guarantee one generated launch: wide reductions can materialise intermediate statistics. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:614-639, :651-713; software/kohakutpu/application/kohakutpu/application/runtime/rows.py:218-221, :264-323, :368-386)
- **API.FUSE.004** `unproven` For an elementwise operation whose tensor operands are all statistics, the consumer adopts the rows view of the first lazy operand whose leading row extents match its initial view and whose last extent is not one. Inlining that operand still requires the fusion predicates of API.FUSE.002; adopting its view does not guarantee fusion. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:420-450, :462-485)

## 4. Reads (operand kinds)

- **API.READ.001** `unproven` The direct rows operand classifier returns scalar for a one-element tensor; otherwise it pads the tensor's rows shape with leading ones and accepts full for an equal view, col for one shared row, or row for one value per matching row. Other shapes raise Unsupported(API.REF.013). Partial-column planned rows instead construct dense broadcast accesses through _access. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:546-565, :642-648, :716-725, :738-746)
- **API.READ.002** `unproven` Mixing statistics and non-statistics in an elementwise operation refuses every statistic with more than one element whose shape does not end in 1, with API.REF.003. In ordinary rows binding, a statistic classified as full or col is also refused; statistic-space binding first converts non-scalar inputs to row operands. Product epilogue binding refuses statistic extras classified as full or col. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:462-469, :568-584, :797-800)
- **API.READ.003** `unproven` Statistics of statistics run over R values with W 32, each input value a row (16 a word). (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:571-573, :696-699)

## 5. Row layouts

- **API.ROW.001** `unproven` A rows kernel computes over [R, W] rows with W divisible by `mg.kblock` [32]. Its output port holds f16 values. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:337-352, :1192-1225; evidence: No named hardware coverage of this generator established.)
- **API.ROW.008** `unproven` A rows plan refuses W not divisible by `mg.kblock` [32], naming API.ROW.008 and requiring whole GT4 column blocks. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:347-351)
- **API.ROW.002** `unproven` Rows plans use bands of `mg.lanes` [4] rows. Default column selection searches descending multiples of `mg.kblock` [32] dividing W and fitting the row quantum, starting at W when no wider than the maximum block, otherwise at the first W divisor in the maximum-block halving sequence. L1 accounting reserves 16 words, double-buffers loop inputs and output and separately counts column prologue storage. Trips normally take at most four bands; statistic input/output sets the quantum to `vc.lanes` [16], otherwise `mg.lanes` [4]. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:282-329, :337-395, :1170-1176; evidence: No current named hardware coverage established.)
- **API.ROW.011** `unproven` A multi-block reduction, including nested reductions, uses a whole-row band when descriptor strides are in range, quantum times W is no greater than four maximum-width bands and lowering buffer accounting fits L1. Loop inputs are double-buffered, column inputs occupy a whole row and output may reuse an equally sized full/tile input pair. The plan then uses W columns and one quantum per trip; otherwise multi-block paths apply. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:120-123, :1086-1138, :1170-1176; software/kohakutpu/application/kohakutpu/application/runtime/rows.py:194-221)
- **API.ROW.003** `unproven` When whole-row-band admission fails, non-statistic or multiple-reduction expressions materialise inner statistics first. A remaining single statistic reduction uses block partials pitched ceil(R/vc.lanes)*vc.lanes [vc.lanes=16], pairs opposite halves, copies an odd middle block and evaluates surrounding expression. single_package_ast defaults enabled absent separate-launch mutant; KTPU_SINGLE_PACKAGE_AST overrides Python selection with exact value 1. Enabled uses wide_fold_kernel with f16 partial/fold scratch; disabled emits separate rows/copy launches. (code: software/kohakutpu/application/kohakutpu/application/runtime/rows.py:26-32, :194-221, :240-322; software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/reductions.rs:29-42, :271-289, :312-369; evidence: No current named RTL witness of complete path established.)
- **API.ROW.004** `unproven` The final incomplete row quantum uses scratch: full-row and tile inputs copy into zeroed bands; statistic inputs copy a whole word; column and scalar inputs remain unchanged. The expression runs on that band and copies back real destination rows, except statistics write whole words. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:398-428, :1237-1243, :1250-1382; evidence: No current named hardware witness established.)
- **API.ROW.009** `unproven` When a multi-block statistic reduction leaves operands outside that reduction, those operands must be row or scalar operands, otherwise RowsError is raised. For a multi-block expression requiring other reductions, the runtime materialises an innermost reduction first and recursively evaluates the remaining expression. (code: software/kohakutpu/application/kohakutpu/application/runtime/rows.py:218-221, :247-252, :312-316, :368-386)
- **API.ROW.005** `unproven` For a non-product rows view whose last extent is neither one nor divisible by 32, kp builds one vector plan over the logical axes. Each reduction gets its own column range; statistic outputs omit the final axis. execute runs the plan. Refused, RowsError, FormError and ValueError raised within execution free the output storage and become Unsupported with API.REF.007. (code: software/kohakutpu/application/kohakutpu/application/api/tensor.py:627-628, :716-785)
- **API.ROW.006** `unproven` Flat kernels use rows of `vc.vlmax` [128] values. Trip length starts at 16 rows and halves until double-buffered inputs, scalars and output fit `vc.l1_words` [512] less 16 words. Remaining rows run in groups divisible by four, two, then one. Non-whole-row N stages non-scalar inputs by word-rounded extents into zeroed scratch covering the computation and copies only the word-rounded output extent back. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:1493-1534, :1563-1588, :1627-1656; evidence: No current named hardware witness established.)
- **API.ROW.010** `unproven` A scalar flat operand declares vc.lanes elements of its input dtype, loads that extent and unpacks the specified lane; every computed element uses the resulting scalar. This extent is one memory word for f16, not necessarily for other input dtypes. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:1548-1577, :1612-1625)
- **API.ROW.007** `unproven` Balanced trips, the default, use `p=max(1,min(n,cores))` and core c receives `[ceil(c*n/p),ceil((c+1)*n/p))`; an empty stage has one zero-trip instance. Hchunk uses `h=ceil(n/p)` and `ceil(n/h)` cores when p exceeds one, with a shorter final chunk. (code: software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:185-279)

## 6. Forms

- **API.FORM.001** `silicon` A storage has primary row-major bytes and side forms. `wrote(key)` makes key the only valid form and drops retained host bytes unless `keep_host=True`; `made(key)` adds a valid form without invalidating others. (code: software/kohakutpu/application/kohakutpu/application/runtime/memory/storage.py:48-59, :235-252; evidence: The validity and host-byte rules match af7c1bb:software/application/kohakutpu/application/runtime/storage.py:29-38, :60-68 in the LeNet host path.)
- **API.FORM.002** `unproven` Missing forms use the available conversion path. An f16 form may be converted from retained host bytes and uploaded, materialised from a padded or word-walk form on the device, or cast from f32 bytes on the device; unavailable conversions raise `FormError`. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:223-269; evidence: af7c1bb:software/application/kohakutpu/application/runtime/forms.py:94-96 uses numpy f16 casting for retained host bytes; the current host conversion saturates finite overflow.)
- **API.FORM.003** `silicon` A row-major f16 read of an f16 buffer whose primary bytes are current uses those bytes directly plus subview byte offset. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:216-220, :233-235; evidence: af7c1bb:software/application/kohakutpu/application/runtime/forms.py:69-75 has the same direct read; LeNet f16 tensors and 8131 f16 unpacks witness it.)
- **API.FORM.004** `silicon` A padded-rows form (rows,n,np) holds n logical f16 values at pitch np f16 elements, occupying whole memory words. Rows planning rounds width to a multiple of 32 columns; product planning rounds N by vc.vlmax/mg.lanes [32]. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:37-39; software/kohakutpu/application/kohakutpu/application/ktpugrad/run/shape.py:73-75; software/kohakutpu/application/kohakutpu/application/ktpugrad/run/product.py:186-205; evidence: Pitches match af7c1bb:software/application/kohakutpu/application/runtime/forms.py:29-35 and af7c1bb:software/application/kohakutpu/application/ktpugrad/run.py:1528-1530, :2064-2068; LeNet N120/84/10 runs at Np128/96/32.)
- **API.FORM.005** `unproven` Compaction converts padded f16 rows with `repitch`: a mover walk for whole-word width and pitches, otherwise `relayout`, which tries specialised forms before lane relayout. A two-byte-element destination uses its primary allocation; other element widths use its f16 side form. Compaction hints the producer site flat. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:294-306, :317-358; evidence: No named RTL witness established for the complete current path.)
- **API.FORM.006** `unproven` An MXFP7 form key contains side, source operand, rows, columns, padded dimensions, lane grouping, K grouping and batches. Existing valid keyed packings are reused. Packing can use composed or prepared inputs or explicitly materialised whole-word rows, with zero padding and the chosen quant recipe; it is not restricted to mover quantization. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:780-838, :856-917; evidence: The full current packing paths have not been established in af7c1bb.)
- **API.FORM.007** `unproven` Packing reads compatible current padded rows directly. Known-zero padding may supply columns through the next word boundary. Otherwise a non-word column count, pitch or offset creates a zero-padded whole-word relayout, composed into packing where admitted, prepared within packing where admitted, or explicitly materialised before quantisation. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:856-897, :920-935)
- **API.FORM.008** `unproven` table converts f16 constants through fp16.write, makes them contiguous and caches storage by SHA-1 of converted bytes, shape and dtype. A miss allocates at least 32 bytes, uploads and marks the physical allocation constant. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:972-995; evidence: af7c1bb:software/application/kohakutpu/application/runtime/forms.py:341-350 casts directly to numpy f16, hashes bytes and shape, and does not register constants.)
- **API.FORM.009** `unproven` Read-back resolves a deferred form, then selects current primary bytes, the current f16 form converted to the requested dtype, padded rows with padding stripped, or a word-walk form gathered on the host, in that order. A subview applies its logical element offset to the selected form; a non-flat offset not aligned to an element is refused. No readable current form raises `FormError`. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:998-1037; evidence: af7c1bb:software/application/kohakutpu/application/runtime/forms.py:353-371 reads primary bytes for nonzero offsets and has no deferred or word-walk read-back.)
- **API.FORM.013** `unproven` A requested form without a supported conversion raises `FormError`. Retained host bytes can be converted to f16 on the host and uploaded as a side form; form creation is not restricted to device execution. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:254-267, :969)
- **API.FORM.014** `unproven` An f32 buffer with retained host bytes and no current f16, padded-row or word-walk form obtains f16 by applying `fp16.write` to those bytes and uploading the result. Finite overflow saturates, infinities are retained, and subnormals are not flushed. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:245-269; software/kohakutpu/language/kohakutpu/language/numerics/fp16.py:8-16; evidence: af7c1bb:software/application/kohakutpu/application/runtime/forms.py:94-96 uses numpy casting without finite-overflow saturation; no current named RTL witness established.)
- **API.FORM.015** `unproven` After current f16, padded-row and word-walk forms have been considered, an f32 buffer without retained host bytes obtains its f16 form through a device cast if its primary bytes are current. If this fallback has neither retained host bytes nor current f32 primary bytes, it raises FormError. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:245-267)
- **API.FORM.016** `unproven` table(dev,arr,dtype) accepts another numpy element type and includes converted bytes, shape and dtype in its cache digest. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:972-978; evidence: odd_permute alone is not an established current named RTL test of this helper.)
- **API.FORM.017** `unproven` After resolving deferred content, read-back takes current primary bytes first. Otherwise it requires an element-aligned subview offset and selects current f16 before padded rows, reading the f16 range and converting to requested numpy dtype. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:998-1024; evidence: TG.DEV.010 is not a named RTL test; af7c1bb:software/application/kohakutpu/application/runtime/forms.py:353-371 reads primary bytes for every nonzero subview offset.)
- **API.FORM.019** `unproven` Read-back of a buffer with no current form is `FormError`. (code: software/kohakutpu/application/kohakutpu/application/runtime/forms.py:1037)
- **API.FORM.010** `unproven` Row-statistic output holds consecutive f16 values padded to vc.lanes [16]; allocation is ceil(R/vc.lanes)*die.word_bytes [32] bytes. Rust rows planning selects statistic-sized row quantum when an operand/output is a statistic, not necessarily exactly sixteen rows per trip. Block partials add a leading block dimension. Full-row storage broadcasts unpacked statistics to mg.kblock [32] columns before packing. (code: software/kohakutpu/application/kohakutpu/application/runtime/rows.py:429-432; software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/vector.rs:1159-1187, :1020-1041; software/kohakutpu/compiler/crates/ktpu-kernels/src/gen/mod.rs:43-46, :69-71, :91-100; evidence: No current named RTL witness of complete generator path established.)
- **API.FORM.011** `unproven` Non-ring matmul allocates f16 tile scratch with tile=(tm/mg.lanes,tn/mg.lanes), mg.lanes [4], feeding it as a tile epilogue operand. A resolved ring path delegates to the ring scheduler. ### Prepared operands and current-form reads

A deferred operand (`forms.Pending`) holds relayout steps, not readable primary
bytes. With `forms.PREPARED` on, a rows consumer emits those
steps inside its own kernel. Quant-side preparation (`forms.PREPARED_QUANT`)
folds a pending packing only where the cost profile admits its recipe
(`runtime.costs`); with no profile it never does. Both defaults have one
source, `ktpu_kernels::gen::prepared::defaults()` (`_rs.PREPARED_DEFAULTS`;
`KTPU_PREPARED`, `KTPU_PREPARED_QUANT` override them per process), read by
`forms` and by the Rust planner (`ktpu_plan::run::Knobs::forms`), which takes
the same prepared, made and profile-gated paths. `forms.COMPOSED`, of the same
source, reads a pending operand on its consumer's loads and packs where that
is taken (`docs/spec/stack/l2/prepared-consumers.md`). Unrepresentable steps fall
back to explicit relayout launches. A repeated rows operand is prepared once; each reader retains
its own offset. The optional single-package reduction path materializes pending
operands before entering its emitter.

Every reader selects a valid storage form. In particular, `_laid_read` obtains
the current dense f16 form after its bare-read producer before repitching;
a producer may have written padded rows according to its consumers' hints.
Read-back of a subview uses its logical element offset in the current F16,
padded-rows, or word-walk view form, not an invalid primary allocation.

Fusion acceptance uses CPU f32 references: maximum absolute error divided by
maximum absolute reference value (floor 1e-9), below 0.03 for the tested MXFP7
products and 0.002 for f16 reductions. Nonfinite results fail. Reduction order
may differ; stale reads and incorrect aliases are not numerical tolerance.

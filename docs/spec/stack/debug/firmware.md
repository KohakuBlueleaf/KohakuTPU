# DBG: the debug firmware interface

What sysnode firmware reports and how the host reads it. The clauses describe
current production and debug implementations; hardware evidence is scoped per
clause. Source inspection and behavioural tests are not hardware execution.
Clause format, ids and evidence tags follow `docs/spec/stack/README.md`.

Paths are repo-relative. `fw/` is `software/kohakuaccel/firmware/`, `drv/` is
`software/kohakuaccel/driver/`, `rt/` is `software/kohakutpu/application/kohakutpu/application/runtime/`.
`LOG` is the v9t6 card run `lenet_n1_nojit.log` (sysnode 0, 2026-10-21, no JIT):
`C:\Users\apoll\AppData\Local\Temp\claude\C--Users-apoll-Desktop-vivado-JTAG-DMA-test\c3bc27a6-e85c-44db-a0a8-9a59aa433062\scratchpad\silicon\lenet_n1_nojit.log`.
The external `CARD1` debug-run attribution is not used to certify current
complete contracts where the named vector and execution evidence cannot be
located. Its remote log paths are not accessed during this audit.

The locally available LOG records 2035 runs and a timeout report with unit
counters and phase timing. It does not contain PKGF de stat/ctr snapshots and
does not itself identify the image/date; it is not evidence of the complete
snapshot contract.

Parameters named here: `node.imem_bytes` [32768], `node.spad_bytes` [32768],
`node.console_fifo_bytes` [256], `fw.max_units` [16], `fw.max_pkg_units` [32],
`fw.max_buffers` [64], `mover.fault_bits` [4].

## 1. What exists

### 1.1 The completion report

- **DBG.RPT.001** `unproven` A RUN returning from the interpreter attempts one terminal 32-byte completion; SIGNAL steps may post additional progress completions. Word 0 is tag; word 1 holds status in bits 15:0, detail in 31:16 and step in 63:32; word 2 counts sysnode cycles through result-cycle sampling, including failure reporting and quiesce but excluding subsequent PKGT and service reporting; word 3 is eng.sent on success or the failure value. eng.sent includes firmware-accounted engine-enqueued sends and fetches, not a hardware issue counter. Publication orders run record, completion and CQ tail; a full CQ waits without timeout. (code: software/kohakuaccel/firmware/queue/service.c:113-138, :163-168, :340-350; software/kohakuaccel/firmware/package/interp.c:755-793, :1779-1782, :1902-1942, :1961-1970)
- **DBG.RPT.002** `unproven` An engine watch observing no issue-count change longer than its bound, without an earlier failing check, reports TIMEOUT (0x30), detail 11 (ENGINE), and STAT as value. Completion faults, mover faults and queue overflow are checked first. (code: software/kohakuaccel/firmware/package/interp.c:632-651; software/kohakuaccel/firmware/include/ka/package/status.h:23, :44; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:661-681 reports detail 2, AWAIT, for this timeout.)
- **DBG.RPT.003** `unproven` The enum defines 23 status codes including OK, PROGRESS and reserved MBOX_OVERFLOW. UNIT_FAULT (0x20) carries package unit index or 0xffff for unmatched coordinate and raw completion. MOVER_FAULT (0x22) carries fault field and MVSTAT. Rejected mover registers produce NO_REACH (0x23) with register and proposed value. Nonzero ASSERT_ZERO produces CONTRACT (0x24) with step count and register contents. Engine queue overflow produces BAD_STEP (0x14), detail 0xde and STAT. (code: software/kohakuaccel/firmware/include/ka/package/status.h:6-29; software/kohakuaccel/firmware/dispatch/engine.c:132-162; software/kohakuaccel/firmware/package/interp.c:504-506, :572-574, :637-642, :1622-1626)
- **DBG.RPT.004** `unproven` `ka_engine_fail` records status, detail and value only while no status is recorded. Quiesce clears status while draining, then restores the original status, detail and value; the saved hardware snapshot is not replaced. The debug failure callback can run again during that drain. (code: software/kohakuaccel/firmware/dispatch/engine.c:17-32, :48-61, :383-399)
- **DBG.RPT.005** `unproven` Failures with held dispatch-engine ownership, outstanding sends, fresh mover work, or unit/mover fault status enter terminal quarantine. Dispatch-engine end also quarantines on engine status failure. Quarantine disables dispatch, reports the saved engine snapshot and publishes fatal state before exiting; it bypasses ordinary per-unit printing, UNIT/FAIL records and quiesce. Other failures use the ordinary report/quiesce path. (code: software/kohakuaccel/firmware/package/interp.c:1077-1102, :1902-1928; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:1565-1581 prints failure counters and quiesces before returning a result.)
- **DBG.RPT.006** `unproven` With TIMING, the interpreter attempts to print PKGT head, copy, bind, steps, barrier, local, total, first, last, sent and idle fields before returning. Phase counters end at result-cycle sampling before printing. Barrier includes failure reporting and quiesce. First and last are recorded timestamps relative to bind; in dispatch-engine mode timestamps surround send-producing steps, not hardware issues. Sent is eng.sent, including firmware-accounted engine-enqueued sends and fetches. Idle spans the previous result timestamp to this start, including intervening reporting and queue work, and is zero before a previous result exists. (code: software/kohakuaccel/firmware/package/interp.c:755-793, :1781-1782, :1856-1863, :1902-1942, :1961-1969)
- **DBG.RPT.007** `unproven` A quarantined RUN disables dispatch, reports the engine snapshot, publishes fatal state and exits from the interpreter. It does not return to the queue service for ordinary terminal CQ publication. (code: software/kohakuaccel/firmware/package/interp.c:1077-1082, :1902-1905; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:1565-1581 prints failure counters and quiesces before returning a result.)
- **DBG.RPT.008** `unproven` Run reports are emitted before terminal completion: the interpreter reports, the service prints any failure line, then flushes before push_cq. This orders attempted output, not guaranteed delivery: a full stdout ring drops remaining sink-call bytes after one boot timeout. (code: software/kohakuaccel/firmware/queue/service.c:59-88, :275-286, :340-350; software/kohakuaccel/firmware/package/interp.c:1902-1924, :1961-1965; evidence: af7c1bb:software/firmware/kohakuaccel/queue/service.c:238-249 posts completion before its failure line.)
- **DBG.RPT.012** `unproven` For a failed completion with a record, the host reads stdout through the recorded produced-byte boundary using read_stdout_bytes_to. It slices accumulated bytes and advances console_at by bytes before NodeError decodes with UTF-8 replacement. Without a record it reads current stdout. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1076-1082, :1273-1281, :207-211; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **DBG.RPT.009** `unproven` Firmware-path SIGNAL calls the queue callback with step index, count and 64-bit argument. The callback flushes stdout and posts PROGRESS (0x01) using absolute cycles and count truncated to 16 detail bits. Execution resumes after publication, which can block indefinitely on full CQ. Host appends progress completions to NodeQueue.progress. (code: software/kohakuaccel/firmware/package/interp.c:1627-1631; software/kohakuaccel/firmware/queue/service.c:113-137, :163-168; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:997-999)
- **DBG.RPT.010** `unproven` Production STEPS tracing prints PKGS first, last and cycle after each attempted step or dispatch group. Cycles are relative to bind minus time emitting earlier trace entries. Debug firmware instead emits binary step records when tracing is enabled; that path does not print PKGS. No fixed per-line cost follows from this implementation. (code: software/kohakuaccel/firmware/package/interp.c:1839-1843, :1845-1877)
- **DBG.RPT.011** `unproven` Ordinary failure result finalization reports the last attempted interpreter step. Quarantined failures exit before that finalization and do not produce its step result. (code: software/kohakuaccel/firmware/package/interp.c:1077-1102, :1805-1811, :1902-1928; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:1565-1581 prints failure counters and quiesces before returning a result.)

### 1.2 Fault printers per unit class

- **DBG.FLT.001** `unproven` Production firmware invokes a package unit's describe callback, when present, for a fault-classified completion before recording failure. Debug firmware omits the callback and retains the raw completion for host decoding. (code: software/kohakuaccel/firmware/dispatch/engine.c:130-163)
- **DBG.FLT.002** `unproven` Production MG (0x4D47) decoding prints [MG] fault, signal <code> arg <hex>. Production VC (0x5643) prints [VC] fault code <n> (<name>), signal <code>, using arg[7:0]: 1 F_DTYPE, 2 F_VSRC, 3 F_CHAIN, 4 F_OPCODE, 5 F_LEN, 6 F_LOOP, 7 F_VL, 8 F_REDVL, 9 F_CUDATA, otherwise ?. Debug builds set both describe callbacks null and do not invoke these printers. (code: software/kohakutpu/firmware/units/matmul.c:6-23; software/kohakutpu/firmware/units/vector.c:6-30; software/kohakuaccel/firmware/dispatch/engine.c:155-162)
- **DBG.FLT.003** `unproven` Dispatcher includes MG/VC classes but no SR class. SR uses generic classification: FAULT produces UNIT_FAULT with unit index and raw signal, without class-specific print. Host SR CU_DBG decode reads low 32 bits as cumulative compute cycles. (code: software/kohakutpu/firmware/build.py:61-70; software/kohakuaccel/firmware/unit/registry.c:8-35; software/kohakuaccel/firmware/dispatch/engine.c:144-163; software/kohakutpu/driver/kohakutpu/driver/units/__init__.py:47-54, :63-65)
- **DBG.FLT.004** `unproven` Each mv_wait iteration checks mover fault and fails MOVER_FAULT with fault code and raw status. de_watch checks after draining completions unless already failed. moves_all_done skips status when no fresh move is recorded; cached configuration credit avoids room wait. Host codes 0..10 name none, index length, range, AXI, mode, element width, alignment, bound axis on XFORM, transform slot, configuration overflow and invalid fp32 index. (code: software/kohakuaccel/firmware/package/interp.c:499-522, :532-553, :632-640; software/kohakuaccel/driver/kohakuaccel/driver/device/mover.py:73-87)

### 1.3 Timeouts

- **DBG.TMO.001** `silicon` A RUN whose word 5 is zero selects the boot block's timeout as the package engine wait bound in sysnode cycles; this is not a whole-run deadline. (code: software/kohakuaccel/firmware/queue/service.c:326-336; software/kohakuaccel/firmware/package/interp.c:1795; evidence: LOG:84,89-90; timeout selection matches af7c1bb:software/firmware/kohakuaccel/queue/service.c:233 and af7c1bb:software/firmware/kohakuaccel/package/interp.c:1490.)
- **DBG.TMO.007** `unproven` Nonzero RUN word 5 replaces boot timeout for the package engine. It does not replace stdout sink boot timeout or bound CQ publication. (code: software/kohakuaccel/firmware/queue/service.c:65-73, :116-118, :326-336; software/kohakuaccel/firmware/package/interp.c:1795)
- **DBG.TMO.002** `unproven` A `TIMEOUT`'s detail names the wait: 1 credit, 2 await, 3 barrier, 4 mover, 5 bell, 6 mailbox offer, 7 slot, 8 RX, 9 ack, 10 ring, 11 engine (dispatch-engine mode, no issue progress for one bound, DBG.RPT.002). (code: software/kohakuaccel/firmware/include/ka/package/status.h:32-45; software/kohakuaccel/firmware/dispatch/engine.c:263, :291, :320-321, :335, :360-361, :380; software/kohakuaccel/firmware/package/interp.c:518, :650, :1123, :1160, :1191, :1429, :1477, :1495)
- **DBG.TMO.003** `silicon` The dispatch-engine progress watch restarts its interval when the issue count changes; after fault checks, unchanged issue count for more than the wait bound triggers a timeout. This bounds lack of progress, not the elapsed duration of the ENGINE step. (code: software/kohakuaccel/firmware/package/interp.c:632-651; evidence: LOG:89 records 10741399 step cycles under an approximately 2000000-cycle bound; af7c1bb:software/firmware/kohakuaccel/package/interp.c:661-681 implements the same progress policy.)
- **DBG.TMO.008** `unproven` Mover waits reset their timeout origin on completed-move count changes; engine watches reset it on issue-count changes. wait_until and fetch-credit waits measure from their start. These rules do not bound every wait: CQ publication can wait indefinitely for space. (code: software/kohakuaccel/firmware/package/interp.c:499-522, :632-651; software/kohakuaccel/firmware/dispatch/engine.c:216-238, :315-323; software/kohakuaccel/firmware/queue/service.c:116-118)
- **DBG.TMO.004** `unproven` BootArgs.timeout is required keyword-only with no default; omission raises TypeError. It supplies firmware wait bound in sysnode cycles. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/boot/args.py:54-69; evidence: af7c1bb:software/driver/kohakuaccel/driver/node/boot/args.py:34-37 defaults to 2000000 cycles.)
- **DBG.TMO.009** `unproven` Mover/engine waits measure rdcycle sysnode cycles without profile conversion. Runtime supplies bound(seconds,hz/1e6), with truthy sys_hz or board idle MHz times one million and seconds from firmware_wait_seconds(self.timeout,wait_seconds). bound rejects nonpositive arguments and returns int(seconds*sys_mhz*1e6). (code: software/kohakuaccel/firmware/include/ka/hal/cpu.h:7-12; software/kohakuaccel/firmware/package/interp.c:499-518, :644-651; software/kohakutpu/application/kohakutpu/application/runtime/card/__init__.py:261-266, :300-305; software/kohakuaccel/driver/kohakuaccel/driver/node/boot/args.py:35-40; evidence: af7c1bb:software/application/kohakutpu/application/runtime/card.py:219-225 retains boot default unless sys_hz, then uses full host timeout times sys_hz.)
- **DBG.TMO.010** `unproven` A dispatch-engine failure at de_end enters terminal quarantine. Quarantine disables dispatch, reports the engine snapshot, publishes fatal state and exits without reaching completion-cycle finalization or ordinary quiesce. (code: software/kohakuaccel/firmware/package/interp.c:1077-1102, :1880-1928; evidence: af7c1bb:software/firmware/kohakuaccel/package/interp.c:1565-1588 finalizes completion timing after ordinary reporting and quiesce.)
- **DBG.TMO.005** `unproven` A full CQ holds the queue service with no bound (it yields until the host advances the CQ head). (code: software/kohakuaccel/firmware/queue/service.c:116-118)
- **DBG.TMO.006** `unproven` Each successful queue status poll checks FATAL before processing completions, marks the queue quarantined, reads stdout, and raises BootRefused for a boot-argument exit code or FirmwareFatal otherwise. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:940-947; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)

### 1.4 stdout, stdin and the console tap

- **DBG.OUT.001** `unproven` read_stdout drains available ring bytes, decodes the accumulated bytes with UTF-8 replacement and final=False, removes only consumed bytes, and advances console_at by that byte count. An incomplete UTF-8 suffix remains buffered for a subsequent read. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1253-1260; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **DBG.OUT.002** `unproven` When stdout is full, the sink waits up to one boot timeout for room. If it remains full, it drops the remaining bytes of that invocation, adds their count to SO_WR + 8, and publishes the successfully produced count at SO_WR. The queue stdout reader reads the produced count and does not inspect the lost-byte count. (code: software/kohakuaccel/firmware/queue/service.c:59-88; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1226-1260, :1269-1281)
- **DBG.OUT.003** `unproven` Service publishes READY before printing its banner of sysnode mesh, queue address/depths, units, signature, class names and main/banner cycles. On READY host reads currently available stdout and returns without waiting for complete banner. (code: software/kohakuaccel/firmware/queue/service.c:220-231, :304-309; software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:555-558, :571-583; evidence: af7c1bb:software/firmware/kohakuaccel/queue/service.c:184-195, :213-214 has same ordering; no recorded banner witness established.)
- **DBG.OUT.004** `RTL` Reading CONS returns the current byte in bits 7:0 and a nonempty flag in bit 8 without advancing the FIFO. Writing CONS advances its read pointer by one byte when nonempty. (code: src/kohakuaccel/sysnode/cpu/rv64_load_win.v:99-115; evidence: sim/verilator/harness/rv64_win_main.cpp:62-70, :192-220 drains console and checks text.)
- **DBG.OUT.008** `unproven` Before a stdout sink exists, ka_putc writes each byte to KA_R_CONSOLE. The load window uses a `node.console_fifo_bytes` [256] byte array and wrapping pointers without a full check: writes advance unconditionally. NodeBoot.console delegates to the driver, which reads the nonempty flag and byte then writes CONS once per consumed byte. (code: software/kohakuaccel/firmware/lib/stdio/stdio.c:21-26; src/kohakuaccel/sysnode/cpu/rv64_load_win.v:88-115; software/kohakuaccel/driver/kohakuaccel/driver/device/rv64load.py:203-211; software/kohakuaccel/driver/kohakuaccel/driver/node/boot/loader.py:98-100)
- **DBG.OUT.005** `unproven` ka_debug writes directly to the console tap. Fatal trap writes a short message through ka_debug, prints cause, epc and tval through ordinary stdio, calls the fatal hook and exits. Stdio uses the stdout sink when installed and console tap otherwise; detailed trap text need not go to a ring. (code: software/kohakuaccel/firmware/lib/stdio/stdio.c:21-38; software/kohakuaccel/firmware/hal/cpu/trap.c:20-26; software/kohakuaccel/firmware/queue/service.c:47-54)
- **DBG.OUT.006** `unproven` Before stdout sink installation, boot magic/version/unit-count and queue magic/version/geometry refusals print through console tap. Invalid region extents, duplicate uses and overlaps refuse silently. Queue-region absence, base mismatch, undersized header, unaligned base or insufficient ring/record capacity also refuse without diagnostic; KA_SPEC_MEMORY_MUTANT omits those queue-region guards. (code: software/kohakuaccel/firmware/lib/stdio/stdio.c:21-25; software/kohakuaccel/firmware/boot/args.c:10-45, :47-55; software/kohakuaccel/firmware/queue/service.c:170-202, :291-297)
- **DBG.OUT.007** `unproven` Before modifying the stdin ring, stdin UTF-8-encodes the text, reads the firmware consumed count, computes unsigned outstanding bytes, and raises ValueError if the input exceeds free ring capacity. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1286-1290; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)

### 1.5 Exit words and the fatal state

- **DBG.EXIT.001** `RTL` ka_exit stores the exit word to R_EXIT; a returning main reaches crt0 storing its return value to EXIT_ADDR. The rv64_win_2p2 harness polls status bits 3/2 until either is set or cycle limit expires, then checks exit word. (code: software/kohakuaccel/firmware/hal/cpu/trap.c:13-18; software/kohakuaccel/firmware/arch/rv64/crt0.S:50-54; software/kohakutpu/firmware/build.py:44-45; evidence: sim/verilator/harness/rv64_win_main.cpp:191-220 implements polling and exit-word check.)
- **DBG.EXIT.005** `unproven` `NodeBoot.status` decodes `HR_STATUS` and reads the exit word and halt PC once the core has stopped. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/boot/loader.py:89-96)
- **DBG.EXIT.002** `unproven` Fatal state publication uses the established queue address when available. Otherwise it requires valid boot magic and version, successful region validation, a nonzero queue region matching the boot queue address, queue-line alignment, and enough extent for the firmware state line; failure of any fallback check suppresses publication. (code: software/kohakuaccel/firmware/queue/service.c:25-45; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **DBG.EXIT.003** `unproven` Fatal fallback state publication requires a validated boot queue region whose address matches the boot queue, is queue-line aligned and covers the firmware state line. A nonzero aligned address alone does not authorize a write. (code: software/kohakuaccel/firmware/queue/service.c:25-45; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)
- **DBG.EXIT.004** `unproven` STOP prints completed entries, task-stack bytes, switches and idle passes, flushes and posts OK. It advances submission head, flushes again, publishes STOPPED with fatal zero and returns 0x5701000000000000 | (value & 0xffffffff). The queue task records the return; dispatcher exits with it after scheduler return. Printed entry count excludes STOP. (code: software/kohakuaccel/firmware/queue/service.c:358-383; software/kohakuaccel/firmware/include/ka/hal/cpu.h:38; software/kohakuaccel/firmware/apps/dispatcher/main.c:27-33, :58-60; software/kohakuaccel/firmware/hal/cpu/trap.c:13-18)

### 1.7 Firmware images and build

- **DBG.BLD.001** `unproven` Default production image is build/fw/kohakutpu_node.elf; requested debug loading without explicit image selects build/fw/kohakutpu_debug.elf; otherwise supplied image is loaded. Production source selection includes framework architecture/library/HAL plus boot, OS, queue, package, dispatch, unit, dispatcher and KohakuTPU units. (code: software/kohakutpu/firmware/build.py:29-46, :58-167, :329-345)

### 1.8 The host side

- **DBG.HOST.001** `unproven` With checking enabled, a failed terminal completion raises NodeError. A recorded stdout boundary selects raw bytes through that boundary; otherwise the host reads current stdout. NodeError retains console_bytes and decodes those bytes with UTF-8 replacement for console text. (code: software/kohakuaccel/driver/kohakuaccel/driver/node/queue/client.py:1076-1082, :1273-1281, :207-211; evidence: implementation inspection only; no card or named RTL witness established for this complete contract.)

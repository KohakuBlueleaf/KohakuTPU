# L1 on KohakuTPU: unit ops, vector order, kernels

**Status: frozen.** A change to the types, invariants or lowering below is an
owner-reviewed spec change; kernels and measurements grow.

The framework's L1 -- per-unit streams, sync points, lowering to L0 -- is
[docs/spec/l1-program.md](../../../spec/l1-program.md). This page is what
KohakuTPU puts in it: the cluster and vector-core op types, the invariants they
refuse, the vector-core order pass, the vector core's lowering hook, and the
hand-written kernels. L1 decides nothing about placement, layout or tiling
(those are L2's); it touches L0 (ISA encoders, `kohakuaccel.package`) and
nothing else. Code: `compiler/kohakutpu/ir/l1/`.

## 1. Contents

| unit | L1 types (`ir/l1/...`) | one word each |
|---|---|---|
| matmul cluster | `cluster.Fill`, `Gemm`, `Drain` | yes |
| vector core, sent | `vector.Image` (IMEM words), `Desc` / `Dims` (descriptor base / walk), `Run` | one flit per word |
| vector core, in an image | `Alu`, `Vld`, `Vst`, `Vshuf`, `Vfill`, `Vdrain`, `Bar`, `Seti`, `Setvl`, `Setmode`, `Loop`, `Halt` | `Seti` is two |
| mover | `mover.Quantise`, `mover.Copy` through `Program.move` (`kohakuaccel.package.mover`) | register writes |

`kohakutpu.ir.l1.Program` is the framework's `Program` with the vector core's
lowering hook (§5). A `Gemm` without `emit` carries no `addr` (it is 0): one
GEMM, one value. Every type's text is [text.md](text.md) §1.

## 2. When a word completes

The framework's semantics hold ([l1-program.md](../../../spec/l1-program.md)
§2). A cluster FILL completes when its last entry has landed, a GEMM when its
sweep STARTS, a DRAIN when its last sub-tile has LEFT; a vector core's IMEM and
descriptor words on arrival, a RUN when it HALTs (HALT waits for the run's
fills and drains).

## 3. Invariants L1 enforces

Refused when the op is built or encoded, never truncated:

- `Gemm(emit=True)` must not open its tile: ``acc or nk > 2``
  (`CuIsa.can_emit`; no load-and-emit accumulator op, the fused DRAIN would
  wait forever).
- A `Gemm`'s `nk` is 1 or a multiple of the pumped K-step 2
  (`CuIsa.legal_nk`; MEASURED on card: nk 3 and 5 corrupt sub-tile (0, 0) of
  every tile on every cluster, nk 1, 2, 4 exact; the unit model does not
  reproduce it). Tilers and kernels pick legal K-chunks only.
- A FILL counts at most 255 entries; an L1 bank holds 256 a side.
- An image fits IMEM's 512 words from its base; a descriptor walks at most four
  dims; every register, descriptor and field fits its encoding.

## 4. Vector instruction order (`ir/l1/vsched.py`, L1 -> L1)

The vector core issues in program order (`vec_core.v`), so the order of an image
is a cost the kernel chooses:

- ONE load/store engine runs VLD, VST, VFILL and VDRAIN walks one at a time.
  ALU ops issue beside a walk; the next walk instruction, and anything neither
  ALU nor walk, waits for the engine.
- A VLD shares the register write port with ALU beats, 1:1 while both run.
- An ALU op's first beat waits until every register NAMED in va/vb/vc/vd has no
  write in flight, selectors notwithstanding: kernels point unused fields at
  `vd`.
- VBAR waits for every fill in flight, so the next region's VFILL goes after it.

`vsched.Core` models this with the measured constants (ALU 11.6 independent / 26
dependent, VLD 14.4, VST 13.4, VLD+ALU 22.4 a pair, VSHUF 27, VFILL 1 a word,
VDRAIN 1.3 a word); `vsched.schedule` list-schedules a body against it and
places each VFILL/VDRAIN nothing waits on at the position the model times
fastest. Dependences: registers and predicates (RAW/WAR/WAW), L1 words through
the descriptor walks (`L1Map`), VBAR against fills and loads; VSETI, VSETVL,
VSETMODE, VLOOP and VHALT are fixed. `compiler/tests/l1/test_vsched.py` checks
every reorder against a symbolic execution written from `vec_alu.v`.

## 5. The vector core's lowering (`Program.lowerings["VC"]`)

A vector core's interval passes through `imem.rewrite` against that core's
`imem.Resident`, kept by the caller across packages: an image the core holds
and a descriptor field already at its value are not sent. Every word is a
completion the node retires; a burst of image words backs up the westbound NoC
and stalled the other core's fills 23k cycles (MAG_PORT_TRACE). Everything else
is the framework's lowering ([l1-program.md](../../../spec/l1-program.md) §3).

## 6. Kernel patterns (`ir/l1/kernels/`)

| kernel | pattern |
|---|---|
| matmul | tile-major MXFP7 operands, one FILL run per (tile, K-chunk); `plan` deals tiles round robin (the clusters read the same A rows together) or in staggered column bands (cluster c's first row tile c/4 short, so drains fall apart; two FILL runs where a row tile crosses a packed tile); L1 bank alternates per K-chunk ACROSS tiles; the tile's fused DRAIN goes LATE (after the next tile's non-emitting work) because it holds the sequencer until its last sub-tile leaves |
| linear+bias | one more ACCUMULATING GEMM per tile over a constant ones A-block (resident in both banks after the chunk entries) and a bias B-block |
| conv2d 3x3 | BAND-LANE layout: an entry's 4 lanes are the same (y, x) of 4 horizontal bands with halos, so every tap is a whole-entry shift; positions over the padded width make a tap a constant offset; A filled once per tap row, the dx taps read it at A offset `dx*cb` |
| stream (vector) | two L1 regions, two parity images: RUN k waits for region r's fill, drains region 1-r (RUN k-1's result) and refills it with RUN k+1's input beside its compute, an epilogue RUN drains the last region; RUN 0's drain writes stale words where a later drain of the same core overwrites them. Bodies ordered by `vsched` |
| silu | slices op-major in groups (loads, each op, stores), groups rotating over register sets so `vsched` can overlap one group's loads and stores with another's ALU work |
| softmax | rows across chunks (VL 128 = 8 rows, one per chunk); tree folds, 4-step VSHUF butterfly, `VFMA(x, log2e, -m*log2e)` before `VEXP2`, reciprocal once a step |
| binary (add, sub, mul) | two input streams (`stream` `inputs=2`, 128 words a slot), result over input 0 |
| layer norm | rows across chunks; sum and sum of squares by tree + butterfly; gamma/beta one resident block read through a STRIDE-0 walk (one VLD puts word j in all 8 chunks) |
| matmul -> silu | `matmul.cluster_ops` with a `mark` after each drained tile; the node waits each mark one round behind the sends and streams silu over that tile in memory, in place, on the cores in turn. An in-place stream needs a `sink` for RUN 0's stale drain |
| flash attention (one query block) | per 64-key block: S on a cluster (q resident in A bank 0); online softmax on a core in SUB-TILE layout (band b in chunk b; lane-group reduce by rotate 1, 2 and a predicated broadcast); P to the quantiser's order by the predicated 4x4 granule transpose; mover quantise; P @ v on a cluster; O = O*corr + PV on the core |

## 7. Measured (card_v9_1n, 4 clusters + 2 vector cores, warm)

Graded against the reference on what the hardware computes on (MXFP7-quantised
operands for the clusters): every case 0 elements over 4e-3 of scale, max
<= 1.3e-3 (`scripts/py/l1/check.py`).

| kernel | shape | cycles | efficiency |
|---|---|---|---|
| matmul | 1024^3, tile 64x64x2, round robin | 312.5k | 83.9% MAC |
| matmul | 1024x512x1024, staggered | 177.2k | 74.0% MAC (round robin 72.7%) |
| matmul | 512^3 | 59.5k | 55% MAC (fill-bound: 1 MB at ~30 B/cycle) |
| linear+bias | 1024x512x1024 | 201k | +11.5% over matmul at K=512 |
| conv2d 3x3 | 64x64, 128->128, tile 44x32 | 183.7k | 80.3% MAC |
| conv2d 3x3 | 32x32, 320->320, tile 68x40, chunk 2 | 274.4k | 84.0% MAC |
| silu | 64k elements | 25.8k | 0.397 lanes (a RUN 2.55-2.72k: 0.47-0.50) |
| softmax | 256x256 | 42.5k | |
| add | 262144 elements | 89.3k | 17.6 B/cycle moved; a RUN 1.36k against ~1.1k of walks |
| layer norm | 256x320 / 256x128 | 53.2k / 26.7k | a RUN within 5% of the vsched model; 320 wide fits 8 rows a RUN |
| matmul -> silu | 1024^3 / 1024x512x1024, 64x64x2 | 515.8k / 432.8k | sequential ~682k / ~547k; core-bound (silu over 1M ~370k alone) |
| flash attention | 32 queries, a 64-key block | ~10-11.7k a block | softmax RUN 4.06k (80 VSHUF ~2.2k), update 1.27k, quantise + P@v + syncs ~5.5k |

Attention is graded to 2e-2 of scale: VEXP2 is within 0.35% of exp2, which
can put a P element across an MXFP7 rounding step (card: P 0.0088043 against
numpy's 0.0087738 at a half step of 0.0088), moving O by a step times |v|.

matmul 1024^3 by parts (k_matmul.py `--parts`): sweeps alone 98%; with fills
93.4% round robin / 84.4% staggered; with drains 85.7% / 92.4%. Round robin
shares A reads across clusters, staggering spreads the drains; both land at
~84% together.

Tiling: tiles split evenly over the clusters (46x80 at 32x32 320->320 makes 6
tiles for 4 clusters, 64.3%); within that, cycles ~ max(compute per cluster,
fill bytes / ~30 B/cycle) ranked every measured conv tiling correctly.

Primitive rates (`scripts/py/l1/primitives.py`, `cluster_prims.py`): a sweep
runs at 100% of 1,024 MAC/cycle per cluster; four clusters' fills share ~30
B/cycle from distinct addresses (81 B/cycle when all read the same); a drain
18.8 B/cycle from one cluster, 21.7 from four together; vector rates in §4.

## 8. Running

- Offline: `ir.l1.model.L1Model` lowers a Program and runs it on the unit
  models (`compiler/tests/l1/`).
- Card model: `scripts/py/l1/card.py` (`L1Card`) with the `k_*.py` runners and
  the primitive probes (`primitives.py`, `cluster_prims.py`,
  `dispatch_prims.py`); vector-core state counters with a `VC_STATE_PROF`
  model. Firmware flag `KA_BOOT_F_STEPS` prints each step's end; its prints
  shift every later time, so dispatch is timed without it.

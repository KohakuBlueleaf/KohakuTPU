# L2 on KohakuTPU: layouts, work items, lowerers

**Status: frozen.** A change to the layouts, item kinds or lowering contract
below is an owner-reviewed spec change; schedule builders and measurements grow.

The framework's L2 -- buffers, views, items, derived dependences, packages, the
L2 -> L1 compiler -- is [docs/spec/l2-schedule.md](../../../spec/l2-schedule.md).
This page is what KohakuTPU puts in it. Code: `compiler/kohakutpu/ir/l2/`.

## 1. Layouts (`layouts.py`)

A layout is a tag on a buffer: its byte size, and the host's pack/unpack.

| layout | bytes | what |
|---|---|---|
| `MxA(rows, k, gm, nk)` | rows*k | MXFP7 A operand, tile-major: (row tile, K-chunk, group, block) |
| `MxB(rows, k, gn, nk)` | rows*k | MXFP7 B operand, the same order with B's slot map |
| `Tiles(rows, cols, gm, gn)` | rows*cols*2 | drained sub-tiles, tile-major: tile (i, j) of gm x gn sub-tiles at ``(i*tn + j)*gm*gn*32``, a sub-tile's 4x4 row-major in one word; the host packs a tile-shaped input the same way |
| `TileCols(cols, gn, count)` | (cols/4gn)*count*gn*32 | `count` column vectors as a drained tile's columns: per column tile, each vector's `gn` words, word `sc` holding its 4 columns in all 4 rows |
| `ConvTiles(h, w, cout, gm, gn)` | | a 3x3 conv's `(h, w, cout)` as `conv_tile` drains it: `Tiles` of the band-lane positions |
| `OnesA(gm)` | gm*128 | the A side of the bias K-block (`matmul.ones_block`): every row ``(1, 2^-6, 0, ...)`` |
| `BiasB(n, gn)` | n/4*128 | the B side of the bias K-block (`matmul.bias_block`): each channel's bias as ``hi, lo`` against the quantised ones row, past fp16 ([l3.md](l3.md) §4) |
| `Flat(n)` | n*2 | fp16 elements in order |
| `Rows(rows, cols)` | rows*cols*2 | fp16 row-major |
| `BandLane(h, w, c, gm, cbc)` | | conv input, `ir/l1/kernels/conv2d.pack_input` |
| `ConvB(cout, cin, gn, cbc)` | | conv weights, `conv2d.pack_weights` |

## 2. Work items (`items` built by `ops.py`)

| kind | unit | reads -> writes | params |
|---|---|---|---|
| `gemm_tile` | MG | A rows panel, B cols panel (+ ones, bias) -> one C tile | gm, gn, nk, chunks, `late` |
| `conv_tile` | MG | input chunk rows, weight panel -> one C tile | tile geometry, cbc, `late` |
| `gemm` | MG | one K-chunk of A and B -> C (no emit) | gm, gn, nk; operands may stay RESIDENT |
| `vec_stream` | VC | input views -> output view | body (silu, binary op, softmax, layernorm, or a generated vector program `("vp", ...)`, [l3.md](l3.md) §5), words, runs, sink, `install` (the share of one image install a generated program's images were chosen with) |
| `vec_run` | VC | views -> views, the core's local storage | one RUN of a named image (attention's init, softmax, update, final) |
| `vec_prog` | VC | views -> views, the core's local storage | one RUN of a generated run program `("vr", ...)` ([l3.md](l3.md) §5): its input filled from `in_at`, its tile drained to `out_at` |
| `quantise` | mover | fp16 entries -> MXFP7 entries | src, dst, entries |
| `copy` | mover | bytes -> bytes | src, dst, nbytes |

A `gemm_tile`'s `late` holds its fused DRAIN until the next tile's
non-emitting work (it holds the sequencer until its last sub-tile has left):
round robin tiles measured 83.9% with it; a tile a vector core consumes
measured better without (515.8k against 531.0k fused 1024^3).

## 3. Lowerers (`lowerers.py`)

- **Cluster.** One allocator per L1 side: each bank's content (the operand
  bytes it holds) and the bank the latest GEMM read. An operand already held is
  not filled again (q across key blocks; a conv input row across its three dx
  taps); a new one goes to the bank the latest GEMM on that side did NOT read,
  so a fill never lands under a running sweep. A held fused DRAIN completes its
  item in the chunk that carries it. Cost: sweep cycles ``gm*gn*nk/2`` a GEMM.
- **Vector core.** One chunk a `vec_stream` (the `stream` pipeline), `vec_run`
  or `vec_prog`; images and descriptors go through the L1 program's residency
  hook, and a run program's images and shared descriptors are sent once while
  the core holds them. A stream's images are two parity images, or -- when two
  do not fit instruction memory -- `shared`: one compute image addressing its
  region through `AD_L1`'s base, which the node sets before each RUN, and two
  images that only wait, drain and fill. Cost (`stream_cost`): the `vsched`
  model of the images times the RUNs, plus `DISPATCH` (260 cycles, MEASURED)
  a RUN dispatch, two a RUN when shared, plus the item's `install` share of
  the images' install, `stream.INSTALL` (51 cycles, MEASURED) an
  instruction-memory word. A generated program's register configuration and
  the RUN size are both chosen on this cost, so a short stream on cores that
  do not hold its images takes the smaller images: softmax 32x128 runs two
  64-word RUNs (238 image words) rather than one 128-word RUN (438), 30.0k
  node cycles against 50.4k not resident, 5.87k against 5.94k resident.
- **Mover.** `quantise` is the L1 mover op `Quantise` (`mover.convert`), `copy`
  is `Copy` (`mover.copy`).

The text of these layouts and kinds: [text.md](text.md) §2.

## 4. Gate

Schedules built by `ops.py` for every L1 reference kernel, compiled, run on
card_v9_1n: cycles within a few percent of the hand-written L1
([l1.md](l1.md) §7), 0 bad elements.

## 5. Measured (`scripts/py/l2/parity.py`, card_v9_1n, warm)

Same inputs; both graded against the quantised reference, every case 0 bad
elements and bit-identical outputs.

| kernel | hand L1 | compiled L2 | ratio |
|---|---|---|---|
| matmul 1024^3, 64x64x2 | 312,503 | 312,912 | 1.001 |
| matmul 1024x512x1024 | 180,945 | 180,277 | 0.996 |
| linear+bias 1024x512x1024 | 198,852 | 199,016 | 1.001 |
| conv 64x64 128->128, 44x32 chunk 4 | 183,744 | 182,976 | 0.996 |
| conv 32x32 320->320, 68x40 chunk 2 | 274,065 | 272,901 | 0.996 |
| silu 65536 | 25,599 | 25,573 | 0.999 |
| add 262144 | 89,251 | 89,219 | 1.000 |
| softmax 256x256 | 42,261 | 42,267 | 1.000 |
| layer norm 256x320 | 53,243 | 53,221 | 1.000 |
| matmul -> silu 1024^3 | 513,962 | 494,681 | 0.962 |
| flash attention, 32 queries x 4 key blocks | 50,076 | 47,469 | 0.948 |

The two below 1 are the node order (lower.py): every producer's next work is
sent before the node blocks and the waits follow the producers' finish order,
where the hand-written programs blocked earlier.

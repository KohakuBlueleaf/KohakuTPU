# L3 on KohakuTPU: ops, dtypes, reference kernels

The framework's L3 -- programs, functions, map, scan, carries, the verifier and
the reference interpreter -- is [docs/spec/l3-program.md](../../../spec/l3-program.md).
This page is what KohakuTPU puts in it. Code: `compiler/kohakutpu/ir/l3/`.

## 1. Ops (`ops.py`)

Each op is one hardware feature. `VEC` operands are what the vector cores load
and store (f16, f32, bool, i32) and literals.

| op | unit | operands -> result |
|---|---|---|
| `mmt a, b` | cluster GEMM | mx7 `[M, K]`, mx7 `[N, K]` -> `[M, N]`, `a @ b^T`; K whole 32-blocks |
| `conv3x3 x, w` | cluster GEMM, the band-lane walk | mx7 `[H, W, C]`, mx7 taps-major `[O, 3, 3, C]` -> `[H, W, O]`, same padding |
| `quantise x` | node mover | f16 -> mx7, last axis whole 32-blocks |
| `transpose x` | vector core (a descriptor walk) | `VEC` `[..., A, B]` -> `[..., B, A]` |
| `add sub mul max min` | vector-core ALU (`VADD`, ...) | `VEC`, broadcast |
| `neg abs exp2 log2 inv rsqrt copy` | vector-core ALU (`VNEG`, `VEXP2`, `VINV`, `VRSQRT`, `VMOV`, ...) | `VEC`, broadcast |
| `fma a, b, c` | `VFMA` | `a * b + c` |
| `select p, a, b` | `VSEL` | `p ? a : b` |
| `cmp.lt cmp.gt cmp.eq` | `VCMPLT`, ... | -> bool |
| `reduce.sum reduce.max reduce.min x axis=k` | `VRED` tree | drops axis `k` (default last) |
| `fill c` | `VSETI` + `VMOV` | a constant -> the statement's shape |
| `gather x, idx` | descriptor walk | rows of `x` at `idx` |
| `scatter x, idx, src` | descriptor walk | `x` with rows `idx` replaced by `src` |

## 2. Dtypes

`f16`, `f32`, `i32`, `bool` (the framework's), and `mx7`: MXFP7 as `mx_quant.v`
quantises it (`kohakutpu.hw.mxfp7.value_fp16`), 32-element blocks along the
last axis. The clusters read mx7 only, and an mx7 value is quantised once: by
the host's packing (an `mx7` parameter) or by `quantise`. MXFP7 quantised a
second time is not itself (MEASURED: `value_fp16` is not idempotent), so
nothing re-quantises an mx7 value.

## 3. Reference kernels (`kernels/*.l3`)

| file | programs | graded against (`compiler/tests/text/test_l3.py`) |
|---|---|---|
| `attention.l3` | `attention`: flash attention, online softmax in base 2, P quantised by the mover | the L1 kernel's numpy reference, within 2e-3 |
| `linear.l3` | `linear` (+bias), `linear_silu` (`inline silu`), `silu_call` (`call silu`) | the quantised product plus bias exactly; silu in float64 |
| `rows.l3` | `softmax`, `layernorm` | float64 |
| `conv.l3` | `conv` then add | the quantised 3x3 sum |

## 4. Numerics (`kohakutpu/ir/numerics.py`, `python -m kohakutpu.ir numerics -o DIR`)

Every case's result from three SOURCES -- `interp` (the L3 interpreter),
`model` (the hand-written L2 schedule compiled to L1, run on the unit models)
and `rtl` (the same packages on the Verilated card_v9_1n through the driver's
node queue, `scripts/py/numerics_rtl.py --build <vlt_card dir>`, which runs
with the card simulation stack) -- against two host references in float32:
`fp32` (no quantisation) and `mx`
(MXFP7 operands as `mx_quant.v` makes them, attention's P quantised). The
`mx-ref` row is the mx reference against fp32: the quantisation's own error.
Figures: max and mean absolute error, `max_rel` (max error / max |ref|),
`rel_l2` (error norm / ref norm), `rel_p99` (element-wise, elements >= 1% of the
peak). Gate (`compiler/tests/numerics/`): each source's `rel_l2` against `mx`
below 6e-4 (an fp16 store), 6e-3 for attention, 5e-3 for the model's
linear+bias; against `fp32` no further than the quantisation.

Measured (seed 0, `build/numerics/rtl/numerics.json`; RTL: the
`build/v9pt/vlt_card_v9_1n` model), `rel_l2`, and the elements where the RTL
and the unit model differ:

| case | mx-ref vs fp32 | interp vs mx | model vs mx | rtl vs mx | rtl != model | why above an fp16 store |
|---|---|---|---|---|---|---|
| matmul 128^3 | 1.64e-2 | 2.08e-4 | 2.08e-4 | 2.11e-4 | 945/16384 | |
| linear+bias 128^3 | 1.32e-2 | 2.78e-4 | 3.90e-3 | 3.90e-3 | 1126/16384 | the cluster's bias path (ones x bias GEMM) quantises the bias to MXFP7 |
| matmul->silu 256x128x256 | 1.67e-2 | 3.21e-4 | 3.22e-4 | 3.24e-4 | 3166/65536 | |
| silu 16384 | 0 | 2.08e-4 | 2.09e-4 | 2.09e-4 | 19/16384 | |
| softmax 32x128 | 0 | 1.93e-4 | 2.65e-4 | 2.65e-4 | 15/4096 | |
| layernorm 32x128 | 0 | 2.02e-4 | 2.02e-4 | 2.02e-4 | 14/4096 | |
| attention 32q x 128k | 2.77e-2 | 4.28e-3 | 4.34e-3 | 4.39e-3 | 120/2048 | S and P stored in fp16 before P is quantised (the reference keeps them fp32) |
| attention 32q x 256k | 2.92e-2 | 4.01e-3 | 4.06e-3 | 4.03e-3 | 207/2048 | the same |
| conv3x3 16x16 64->32 | 1.61e-2 | 2.08e-4 | 2.08e-4 | 2.12e-4 | 754/8192 | |

The interpreter and the compiled program agree to the fp16 store on every case
but linear+bias, whose L3 program adds the bias on the vector core exactly.

**The unit models are not bit-exact against the RTL; every difference is one
fp16 ulp and none moves an error figure.** Two causes:

- **The cluster's accumulator.** The RTL accumulates in S1E7M14 (`ACC_MW = 14`
  in `mx_cluster_node_pump.v`), and the pumped front end merges each pair of
  K-block partials with a truncating alignment shift before normalising (RNE)
  and adding into the tile (RNE). The unit model (`model.py` `sweep_q`)
  accumulates every block exactly into S1E7M16. An emulation of the RTL's
  steps at M14 reproduces the card's matmul 128^3 output with 0 differing
  elements (at M16: 947).
- **The vector lane's seeded ops** (`exp2`, `log2`, `inv`, `rsqrt`): the RTL
  evaluates them from range reduction and a coefficient table (`vec_alu.v`),
  the unit model exactly before rounding to E8M15. Not yet reproduced bit for
  bit.

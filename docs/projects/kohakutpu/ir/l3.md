# L3 on KohakuTPU: ops, dtypes, reference kernels, the L3 -> L2 compiler

The framework's L3 -- programs, functions, map, scan, carries, the verifier,
the reference interpreter and the instantiation at concrete shapes -- is
[docs/spec/l3-program.md](../../../spec/l3-program.md). This page is what
KohakuTPU puts in it and how it compiles to L2
([l2.md](l2.md)). Code: `compiler/kohakutpu/ir/l3/`.

## 1. Ops (`ops.py`)

Each op is one hardware feature. `VEC` operands are what the vector cores load
and store (f16, f32, bool, i32) and literals.

| op | unit | operands -> result |
|---|---|---|
| `mmt a, b` | cluster GEMM | mx7 `[M, K]`, mx7 `[N, K]` -> `[M, N]`, `a @ b^T`; K whole 32-blocks |
| `conv3x3 x, w` | cluster GEMM, the band-lane walk | mx7 `[H, W, C]`, mx7 taps-major `[O, 3, 3, C]` -> `[H, W, O]`, same padding |
| `quantise x` | node mover | f16 -> mx7, last axis whole 32-blocks |
| `transpose x` | vector core (a descriptor walk) | `VEC` `[..., A, B]` -> `[..., B, A]` |
| `add sub mul max min` | vector-core ALU (`VADD`, ...) | `VEC`, broadcast |
| `neg abs exp2 log2 inv rsqrt copy` | vector-core ALU (`VNEG`, `VEXP2`, `VINV`, `VRSQRT`, `VMOV`, ...) | `VEC`, broadcast |
| `fma a, b, c` | `VFMA` | `a * b + c` |
| `select p, a, b` | `VSEL` | `p ? a : b` |
| `cmp.lt cmp.gt cmp.eq` | `VCMPLT`, ... | -> bool |
| `reduce.sum reduce.max reduce.min x axis=k` | `VRED` tree | drops axis `k` (default last) |
| `fill c` | `VSETI` + `VMOV` | a constant -> the statement's shape |
| `gather x, idx` | descriptor walk | rows of `x` at `idx` |
| `scatter x, idx, src` | descriptor walk | `x` with rows `idx` replaced by `src` |

## 2. Dtypes

`f16`, `f32`, `i32`, `bool` (the framework's), and `mx7`: MXFP7 as `mx_quant.v`
quantises it (`kohakutpu.hw.mxfp7.value_fp16`), 32-element blocks along the
last axis. The clusters read mx7 only, and an mx7 value is quantised once: by
the host's packing (an `mx7` parameter) or by `quantise`. MXFP7 quantised a
second time is not itself (MEASURED: `value_fp16` is not idempotent), so
nothing re-quantises an mx7 value.

## 4. Numerics (`kohakutpu/ir/numerics.py`, `python -m kohakutpu.ir numerics -o DIR`)

Every case's result from these SOURCES -- `interp` (the L3 interpreter),
`model` (the hand-written L2 schedule compiled to L1, run on the unit models),
`l3` (the L3 program compiled by §5, on the unit models; `l3:core-bias` the
same with `bias="core"`) and, on a card, `rtl` and `l3-rtl` (the same packages
on the Verilated card_v9_1n through the driver's node queue,
`scripts/py/numerics_rtl.py --build <vlt_card dir>`, which runs with the card
simulation stack) -- against two host references in float32: `fp32` (no
quantisation) and `mx` (MXFP7 operands as `mx_quant.v` makes them,
attention's P quantised). The `mx-ref` row is the mx reference against fp32:
the quantisation's own error. Figures: max and mean absolute error, `max_rel`
(max error / max |ref|), `rel_l2` (error norm / ref norm), `rel_p99`
(element-wise, elements >= 1% of the peak), and on a card each package's node
cycles. Gate (`compiler/tests/numerics/`): each source's `rel_l2` against `mx`
below 6e-4 (an fp16 store), 6e-3 for attention; against `fp32` no further than
the quantisation.

Measured (seed 0, `build/l3final7/numerics/numerics.json`; RTL: the
`build/v9pt/vlt_card_v9_1n` model), `rel_l2` against `mx`, and the elements
where the card and the unit models differ:

Attention is above an fp16 store because S and P are stored in fp16 before P
is quantised, where the reference keeps them fp32. linear+bias is below the
interpreter: the clusters add the bias in the accumulator, before the one fp16
rounding, where the program rounds the product to fp16 first. The bias rides
the bias K-block in two columns, ``hi*A0 + lo*A1`` with ``A = (1.00195,
0.01758)`` the ones row as `mx_quant.v` quantises it (`matmul.bias_block`): one
column carries the bias at MXFP7's int7 (rel_l2 4.7e-3 of the bias; the ones
quantise to 1.00195), two carry it to 8.3e-5 at any bias scale from 0.05 to
300, past fp16, in the same single sweep.

**The unit models are bit-exact against the RTL on every case.** The cluster
model accumulates as `mx_cluster_node_pump.v` does (S1E7M14, the pair merge's
truncating alignment). The vector lane (`model.py` `lane`) is `vec_alu.v`'s
datapath on 24-bit words, not exact arithmetic rounded once:

- **The seeds** (`exp2`, `log2`, `inv`, `rsqrt`) are the RTL's range reduction
  (exp2: x to s8.17, round half up), the coefficient ROM (`SEED_TABLE`,
  regenerated from `scripts/py/vec_tables.py`'s fit and checked against
  `vec_tables.v`), the two 16-bit-slice Horner stages and the identity pins.
  They are faithful, not correctly rounded: 4.4k-8.2k of ~150k swept words per
  seed differ from exact-then-round.
- **The FMA** aligns the addend with one right shift and keeps a sticky over a
  16-bit mask, so a zero addend (every MUL) sets sticky and a product tie
  rounds up; a product below half the addend's ulp is dropped.
- **Moves** ride as `winner * 1.0 + 0`, so a -0 operand comes out +0.
- **Loads** round FP32 to E8M15 as `vec_cvt_f32_to_e8` does; **VRED** runs the
  `vec_lanes.v` tree (adjacent pairs, the left one as `a`) and sixteen rotating
  partials, each node one lane op.
- **exp2 of |x| in [128, 256)** is not a special (only E > 134 is) and its
  s8.17 word wraps: exp2(200) = 2^-56, exp2(-200) = 2^56, exp2(128) = 0.

`compiler/tests/numerics/lane_rtl.py` streams 1,083,240 instructions (every
opcode; every mantissa of four octaves per seed; the FMA's alignment range
with sparse mantissas for ties; the specials grid) through `vec_alu.v` under
Verilator and diffs every word: 0 differ (`build/lane_rtl/report.json`).
`test_lane_seeds.py` holds 6,093 of those RTL words as `lane_golden.npz`.

## 5. The L3 -> L2 compiler (`lower.py`)

`lower.compile(module, program, shapes, target)` instantiates the program at
the inputs' shapes (the framework's `instance.instantiate`: dims bound,
`inline` and `call` expanded, dead values dropped), lowers it to an L2
`Schedule` over buffers `target` allocates, and returns a `Compiled`: the
schedule, each input's packing, each output's read-back, and `origin` (each
item's L3 values). `Compiled.run(target, arrays)` packs, runs the packages and
unpacks. Text: `python -m kohakutpu.ir lower x.l3 -p PROG --shape x=AxB ...`.

A map body, or the top level, is one GROUP; a group stores one value.

| group | lowers to |
|---|---|
| vector ops only | one vector program (`vgen`) over the whole tensors, split across the cores in whole rows or words: ``rows`` mode when it reduces along rows or reads a column vector, ``flat`` otherwise |
| one `mmt` (or `conv3x3`), then vector ops over its tile | `gemm_tile` / `conv_tile` items; a column vector added straight to the tile, its only reader, rides the clusters' bias K-block (`bias="cluster"`); the rest is each tile's epilogue in place on a core, ``flat`` mode over the drained sub-tiles, column vectors as `TileCols`, other tile-shaped inputs packed as the tile (`Tiles`, `ConvTiles`) |
| carries, then a `scan` | per map point, on one cluster and one core: the scan body's phases in order -- each `mmt` a `gemm`, each `quantise` a mover item, each run of vector ops a `vec_prog` RUN (`vrun`) over the core's L1, the carries and the values crossing phases kept there -- then the ops after the scan into the stored tile |

Knobs: `contract` (on: ``mul`` read once by ``add`` -> one ``fma``; ``(a - p) * q``
with `p`, `q` per row or scalar -> ``fma(a, q, -(p*q))``), `bias` (``"cluster"``,
or ``"core"``: the column vector in the vector epilogue), `conv_tile` (a
`conv3x3`'s ``(gm, gn)``; L3 names none), `installs` (vector images installed
an execution: 1, the default, when the cores run other programs' images
between executions; 0 when they hold this program's -- it weighs the images'
install against their RUNs, §5.1).

### 5.1 Vector programs (`kernels/vgen.py`)

A spec ``("vp", mode, geom, inputs, cols, nodes, out)`` is an L2 parameter
(`vec_stream`'s `body`). Each node is SCALAR (folded, an S register), PER-ROW
(a reduction or an op of per-row values: one register a step) or WIDE. A wide
node runs in pass ``max(its wide args' passes, its per-row args' ready
passes)``; a reduction is ready the pass after its argument's. A wide value read
a pass later goes through L1 as fp16, over a slot whose value is dead by then
or a scratch slot. Reductions fold columns into partial accumulators, a tree,
then the VSHUF butterfly. Registers come from a first-freed-last pool, an op
writes over an operand it reads last, and a flat tile's column-vector words
stay in registers for the RUN when they fit.

The configurations are steps at once, partials a reduction and held column
vectors, and in flat mode slices one or four at a time (a group's loads first,
one input's words after another). The one kept is the cheapest over the item's
RUNs: `vsched`'s cycles a RUN times the RUNs, plus the item's share of the
images' install (`installs` over the streams a core runs with one install; a
core's epilogue tiles share it). Of configurations the model times alike the
first listed is kept: four slices at a time is the hand binary kernel's order,
which the card runs 9% faster than one at a time where the model sees 0.2%
(add 262144: 93.9k against 102.6k). The images are two parity images or --
when they pass instruction memory -- `shared` ([l2.md](l2.md) §3). The RUN
size is the one `lowerers.stream_cost` puts lowest, the same cost with the
dispatches. The share is the item's `install` parameter, so the L2 -> L1
lowering rebuilds the same images.

### 5.2 Run programs (`kernels/vrun.py`)

A spec ``("vr", gm, state, runs)``: `gm` bands of four rows, VL ``16*gm``,
one register a sub-tile column of every band (lane ``4i+k`` row `i`, column
`k`); a per-row value is a register whose lanes ``4i..4i+3`` hold row `i`'s.
`state` names the L1 words the RUNs share: tiles (``"W"``), per-row values
(``"P"``), the fill slot, the drain slot and the two index words. A row
reduction folds the columns into two partials, then each lane group of four
(rotate 1, 2) and broadcasts lane `4i` with three predicated rotates; a value
the mover quantises next is drained in the quantiser's order by the 4x4
granule transpose. Per-row state writes land at the RUN's end; a carry read
after the phase that updates it is refused.

### 5.3 What it refuses (`LowerError`, by what it found)

A group that reads another group's output; two stores in a group; a reduction
over part of a row or over a cluster tile; three streamed inputs, or two and a
column vector (nine descriptors); an output or a streamed input not fp16; a
cluster operand that is not a host-packed mx7 parameter outside a scan; a
`conv3x3` inside a map; a scan whose vector phase reads two cluster results, or
whose carry is read after its update's phase.
